## 快速开始

### 在新机器安装

准备 Git、Windows PowerShell 5.1、Python 3.11 或以上、Node.js 22 或以上。验证版本见 [.python-version](<../../.python-version>) 与 [.nvmrc](<../../.nvmrc>)。

```powershell
git clone https://github.com/SanN2Z/APPSO-workflow.git
Set-Location APPSO-workflow
powershell -NoProfile -ExecutionPolicy Bypass -File tools/bootstrap.ps1 -FullTest
powershell -NoProfile -ExecutionPolicy Bypass -File tools/workflow.ps1 verify
```

初始化在 clone 内恢复锁定依赖、Wenyan、Codex／Claude 工具及配置模板。真实账号与浏览器登录态在本机接入；Image2 需要当前 Agent 提供生图能力，被测产品 CLI 按其官方支持情况接入。

```powershell
# 查看功能是否已经随仓库提供
powershell -NoProfile -ExecutionPolicy Bypass -File tools/workflow.ps1 capabilities doctor --bundle-only

# 查看本机账号、浏览器及其他执行条件
powershell -NoProfile -ExecutionPolicy Bypass -File tools/workflow.ps1 capabilities doctor
```

当前登记 9 个能力包，覆盖内容工具、公众号、X、公司飞书、公司浏览器、Image2、APPSO 视觉配置、外部模型接入与写作技能资产。具体安装与本机输入见[能力说明](<../../tools/README-capabilities.md>)。

### 开始一项任务

可以直接描述：

> 根据这个 brief 和手册，为 APPSO 做一篇带实际制作体验的商单。先对齐必展功能与对标质量，设计几个有区别的案例；可以用目标产品官方 CLI，网页操作保留全局截图。完成后交图文、实际视频和主编阅读包。

一项内容任务通常经过六步：

1. **明确交付。** 确认平台、账号、稿型、读者、brief 与当前交付物。
2. **取得材料。** 查一手资料和原图；体验稿实际操作，保存输入、过程与结果。
3. **形成内容。** 围绕一个读者问题，把事实、判断、功能与案例接起来。
4. **完成视觉。** 官方材料保持原貌，编辑图执行品牌规范，实测结果保留真实归属。
5. **审阅交付。** 核对事实、声画、图注、权利与当前载体的实际效果。
6. **吸收反馈。** 局部修改落到成品，长期适用的要求进入所属流程。

## 视频与 CLI

适合多案例商单、图生视频、运镜与表演测试、转绘，以及由多个镜头组成的长片。主展示片段通常围绕 15–20 秒设计；整片时长由故事与产品能力决定。

| 任务 | 执行方式 |
|---|---|
| 关键图、同规格视频、重复参数、批量镜头 | 官方 CLI／API 可覆盖时优先调用 |
| 剧本协作、画布、资产、分镜、3D 站位、转绘入口 | 在目标产品 Web 中实际操作并留图 |
| Web 导出参考，再由 CLI 生成 | 保存实际输入与引用关系，说明各阶段的真实路径 |
| 没有可用 CLI 或接口不支持该功能 | 使用已登录浏览器完成 |

CLI 是执行方式，工作台流程是测试对象。通用生成接口的成片不能被写成一个尚未实际完成的专用功能产物。

```text
brief 与功能要求
→ 案例、角色设定与分镜
→ 确认官方 CLI、账号、规格和计费
→ 先完成一条可采用的样片
→ 分镜提交，保存任务 ID
→ 查询状态，下载原始结果，检查完整性
→ 核对人物、动作、运镜、对白、声音与口型
→ Web 整集合成或剪辑衔接为完整作品
→ 选取完整展示片段，保留原片与导出版本
→ HTML 审阅和 ZIP 交接
```

每条任务记录模型、提示词、参考图／视频、时长、比例、分辨率、扣分与文件位置。等待或下载超时，先查询已有任务，避免重复提交；已成功的片段继续复用。

**长片按故事拆镜。** 先固定演员、服装、道具和场景，再检查相邻镜头的连续性。保留原始素材，导出不无故降低分辨率、帧率或音质；白模与短预演按其实际用途展示。

**过程图在操作时保存。** 入口与设置、关键制作状态、结果预览都应有对应画面。工作台先给完整导航、资产栏、分镜区和预览区，局部图补小字；写到哪一步，图就放在对应段落。

执行细节见[视频产品体验制作 SOP](<../../APPSO-数字资产/03-SOP/AIGC 视频产品体验制作 SOP.md>)。目标 CLI 的具体参数以该产品当前官方文档和 `--help` 为准；仓库不假设不同厂商使用同一套参数。

## 出图

| 用途 | 制作方式 | 保存什么 |
|---|---|---|
| 封面、编辑创意 | Image2，参考图与 APPSO 笨拙涂鸦规范 | 参考图、计划、成图、图注 |
| 架构、流程、关系解释 | Image2，完整设计规范与登记 Logo 一起进入调用 | 节点关系、规范引用、输入与成图 |
| 成本、价格与数值比较 | 标准绘图工具，使用可复算数据 | 数据、单位、取材日期、渲染脚本 |
| 官方图、原帖、界面 | 保存真实原图或截图 | 出处、上下文、权利与裁切记录 |
| 被测模型关键图、视频抽帧 | 使用目标产品的实际输出 | 模型、生成记录、输入、原文件与导出关系 |

先写生成计划，执行预检，再调用内置生图工具，最后看实际成图。预检通过说明输入合同成立，不能代替看图。

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools/workflow.ps1 image-preflight <内容包> --task <图片任务> --stage final --include-prompt --write-receipt
```

使用 [APPSO 生图计划模板](<../../APPSO-数字资产/04-模板/APPSO 生图计划模板.json>)，执行说明见 [Image2 工作流](<../../共享/运营/SOP/Image2 生图工作流.md>)。本页封面和架构图均按该流程制作。

前两项根据一份 JSON 清单生成离线页面，并复制实际素材。图像示例可直接运行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools/workflow.ps1 media-review docs/appso-workflow/examples/image-review.json --output output/image-review --zip
```

视频使用[视频清单](<../../docs/appso-workflow/examples/video-review.json>)，填写实际成片、封面和过程截图后运行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools/workflow.ps1 media-review <视频审阅清单.json> --output output/video-review --zip
```

输出包含 `index.html`、`assets/` 和 ZIP，完整解压后离线查看与播放。生成器保留视频原文件，不转码；模型、规格与成本取自本次清单。字段说明见 [HTML 模板用法](<../../APPSO-数字资产/04-模板/HTML/README.md>)。

文章 Markdown 的图文预览继续复用 Wenyan：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools/workflow.ps1 wechat preview <内容包> --open
```

## 交付与复盘

**主编审阅：** 图文、实际视频、关键图与过程图库一起交。清洁阅读版保留正文和作品，内部制作记录与编辑意见另列；GIF、视频封面和完整视频分别管理。

**飞书协作：** 使用本机已连接并获授权的工具，写入后读回标题、正文和图片。公司同步可用 `company status` 查看下一步；用户已经指定 HTML 或 ZIP 时按该载体交付。

**公众号交接：** 按当前任务选择人工编辑或公司浏览器扩展；密封草稿用于已验证的账号与主题组合。扩展版本以[当前入口](<../../tools/company/ifanr-feishu-wechat-layout/README.md>)为准，保存后重开核对真实样式。

**反馈沉淀：** 单篇需求留在内容包，品牌偏好进入 APPSO 配置，制作方法进入专项。改一张图只复查相关素材和载体，不重新生成整组视频。

发布、覆盖草稿、群发与外部账号写入按本次具体授权执行。状态以 `draft.md` 为准，HTML 审阅和 Git 提交不代表内容已发布。

| 层 | 主要入口 |

| 人与助手 | [工作流使用入口](<../../共享/运营/SOP/工作流使用入口.md>)、[self-media-ops](<../../.agents/skills/self-media-ops/SKILL.md>) |
| 共用生产与审稿 | [内容工作流](<../../共享/运营/SOP/内容工作流.md>) |
| APPSO 栏目与视觉 | [APPSO 内容流程](<../../APPSO-数字资产/03-SOP/APPSO 内容生产 SOP.md>)、[数字资产目录](<../../APPSO-数字资产/README.md>) |
| 素材与内容包 | [内容包规范](<../../.agents/skills/self-media-ops/references/content-package.md>)、[模板](<../../共享/模板/微信公众号内容包/>) |
| 执行工具与本机输入 | [能力说明](<../../tools/README-capabilities.md>)、[工具注册](<../../tools/workflow-toolchain.json>) |

按需扩展包括 X 改写与趋势工具、明确指定时的 [Gemini 主笔试跑](<../../共享/运营/SOP/Gemini 主笔试跑.md>)、外部模型客户端、PDF／图片辅助工具和历史语料分析。科研保留[独立入口](<../../RESEARCH_WORKFLOW.md>)，日常 APPSO 写作不启动科研流水线。

```text
APPSO-数字资产/       品牌、栏目、专项 SOP 与可复用模板
.agents/skills/      助手分流、审校、反馈与素材合同

```

内容包按阶段增加 brief、来源、素材清单、审稿和交付记录，正文与状态以 `draft.md` 为真源。原始成片和登记来源保留，预览与导出可以重建。

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools/workflow.ps1 validate <内容包>
powershell -NoProfile -ExecutionPolicy Bypass -File tools/workflow.ps1 test
powershell -NoProfile -ExecutionPolicy Bypass -File tools/repository_preflight.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File tools/workflow.ps1 export-workflow
```

规则只更新所属真源，入口保留链接。工具与依赖变更按可迁移合同验证，账号与登录资料通过本机配置接入。项目内容与公司资产按原有保密和权利规则使用；第三方代码保留各自许可，`tools/aris/upstream/` 的 MIT 许可不改变公司资产的使用边界。
