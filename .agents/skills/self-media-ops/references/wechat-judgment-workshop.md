# WeChat 写前共创门

规则 ID：`PROJECT-WECHAT-JUDGMENT-001`

状态：`trial`

触发与豁免只引用核心流程中的 [`PROJECT-WECHAT-JUDGMENT-001`](../../../../共享/运营/SOP/内容工作流.md#project-wechat-judgment-001公众号写前共创门试运行项目配置)，本文件不另立口径。L3 必须进入本门；L2 只有出现会改变中心判断或故事路线的真实选择，或用户明确要求共创时才进入。进入本门后，Codex 主动提交核心判断、故事主线、四格叙事链、最强对手、表达任务，以及在这些关系成立后写出的标题和暂定小标题；存在真实竞争路线时，按 `CORE-ROUTE-001` 提交最多 3 张成文前路线卡。用户确认前，不启动完整正文。

它负责把文章真正回答的问题和故事路径锁定下来，不负责用目录、路线数量或叙事术语证明选题值得写。若 `CORE-VALUE-001` 未通过，先停在 `research`，不得继续用本工具把材料组织成长文。

## 进入条件

按 `PROJECT-WECHAT-JUDGMENT-001` 进入；必要广搜已完成，初步事实可用，`CORE-VALUE-001` 已通过。

## 第一步：主动提交写前共创包

Codex 必须先基于已有材料提出推荐方案，不能把空白问题丢给用户。默认共创包包含：

- 读者真正要解决的一个问题；
- 一条普通读者可以复述的核心判断；
- 一句话故事主线和读者依次会追问的问题；
- 一张 `CORE-CHAIN-001` 四格叙事链表；
- 本文最强的反例或对手，以及在第几拍正面接它；
- 开场中的可见动作与尚未解决的压力；
- 结尾落到什么具体公众收益、理解或行动；
- 每节必要的事实锚点与待核项；
- 计划使用的高显著性转折、判断、隐喻或结尾各自承担什么具体表达任务；
- 2—3 个标题，其中明确标出推荐项；
- 在故事节拍成立后写出的 3—5 个暂定小标题；
- 明确不写哪些背景、宏大主题、技术细节和防御性边界。

存在真实的高影响分歧时，按 `CORE-ROUTE-001` 把推荐方案与最多 2 个替代框架做成路线卡，并说明每个选择会改变什么、放弃什么。用户选择、修改或全部退回；AI 不投票。没有真实分歧时只给一个推荐框架，不为显得完整强凑方案。标题和目录必须服务同一个判断，不能只是话题标签。

## 第二步：围绕真实分歧完成必要决策

决策点按「产生了什么决定」计数，不按聊天消息数量计数。用户可以一次确认整套推荐方案，也可以只修改其中一个关键点；不要为了凑轮次制造来回。下面 5 类决定按实际需要记录，不要求每次逐项来回：

1. 找共同处境：谁在什么时刻遇到了什么变化。
2. 从真实路线中选出或修改主判断。
3. 核对它靠什么成立，哪里可能说过头。
4. 决定案例和写作模式：`personal` 或 `company`。
5. 锁定开场发动机、叙事发动机、支撑关系和结尾落点。

讨论用来决定文章思想，不用来反复润色同一句话。只有出现真实分歧时才继续追问。

## 第三步：锁定开场发动机与叙事发动机

思想相同，不等于写法相同。提纲之前还要决定：读者为什么在首屏继续看，以及后面的材料为什么必须按这个顺序出现。

开场卡及最终正文必须通过核心流程的 `PROJECT-WECHAT-OPENING-001`。选定的开场卡、首屏未解决压力与 `time_first_exception` 要复制到 `brief.md` 和 `research/co-writing-log.md`；本文件不重复该规则的触发、豁免和回归口径。

不要先写一版新闻导语，再在同一句上反复换词。分析型长稿先做 2–3 张开场卡，每张只写 1–2 句，并使用不同发动机。每张卡同时标出：第一个可见动作或事实、尚未解决的压力、暂缓交代的背景，以及它怎样把读者送进主问题。选择其中一张，其余记录放弃原因；若证据只允许一种可靠开法，说明为什么，不强凑数量。

### 开场发动机

分析型长稿只选一个主要开场发动机：

1. **具体场景或动作**：一个人、产品或机构正在做一件可见的事。
2. **矛盾或异常事实**：两个本应一致的结果发生冲突。
3. **反直觉结果**：先给出与常识相反、且有证据支持的结果。
4. **人物进入难题**：一个值得关注的人为什么走进这个问题。
5. **直接判断或决策**：先给读者一个会改变选择的明确判断。

钩子是有事实支撑的「未解决压力」，不是热点词、情绪词或口语密度。公司、日期、融资额、人物履历和发布信息本身只是事实卡；只有它们制造了矛盾、代价、悬念或选择时，才构成钩子。

分析型长稿的首屏必须同时做到：

- 有一个具名人物、产品、机构或对象正在行动，或正在遭遇变化；
- 出现一个读者能复述的冲突、反常结果或问题；
- 读者能说出「我为什么要继续看」；
- 背景只保留理解当前冲突所需的最少信息。

若前三段可以直接改成一则新闻摘要，或交换顺序后几乎没有损失，开场未通过。纯事实快讯可以先报事件；问答和人物访谈可以先让人物或回答进入现场，不强制套用上述五种长稿开场。

### 叙事发动机

全文只选一个主要叙事发动机，其他结构只能为它服务：

- **谜团揭示**：异常 → 线索 → 解释 → 边界或后果；
- **人物追求**：人物想做什么 → 遇到障碍 → 尝试 → 结果与代价；
- **问题升级**：表面症状 → 深层机制 → 失败方式 → 应对 → 尚未解决的问题；
- **实验验证**：预期 → 测试 → 意外结果 → 原因 → 新判断；
- **对照决策**：几条路径 → 同一判断尺度 → 证据 → 选择。

根据来源、发布日期、公司或论文主题排目录，不算叙事发动机。「五种能力」「四项原则」等清单可以保留在研究笔记里；除非文章承诺的就是一份可执行清单或真实的平行比较，否则不能直接拿来当正文骨架。

写一张最短的叙事链表，不追求固定节数：

| 本节新增的事实或动作 | 它让局面发生了什么变化 | 它留下了什么未解决的问题 | 下一节为什么必须回答这个问题 |
|---|---|---|---|
|  |  |  |  |

四格全部必填。第 ④ 格写不出来，说明相邻两节是并列关系：合并、重排，或明确改用平行比较。平行比较必须在链表头部声明唯一共享尺度，即同一问题、同一量纲或同一决策用途；每节都在这把尺子上给出结论。

小标题在节拍成立后再写。标题应说明本节发生了什么变化或作出了什么判断，不能只写「背景」「技术」「影响」「第一关」或论文名。遮住小标题和序号后，段落关系仍然必须成立。

### 表达定调

写前不预制「金句」，只约定关键位置必须完成的表达任务。对计划中的高显著性转折、抽象判断、隐喻和结尾，记录：它要把哪项事实、冲突、决定或后果说清；它具体指向什么；不用修辞时最直接的说法是什么；删除后读者会失去什么。若答案只是「加强张力」「显得有观点」或「这里需要一句能记住的话」，不把它冻结进共写记录。

此处只记录表达任务，不执行 canonical draft 阶段的 `PROJECT-WECHAT-PRAGMATIC-001` 完整诊断，也不提前写死句子。古语、名言、热梗和比喻不是默认禁用或必用项；只有它建立了后文继续使用的问题模型，并立即落到具体动作或证据时，才有保留理由。

## 第四步：锁定全文思想与故事路径

`research/judgment-workshop.md` 只有同时记录以下内容，才能从 `discussing` 改为 `locked`：

- 一个具体的共同处境；
- 2—3 个标题及最终标题方向；
- 一个普通读者可以复述的主判断；
- 2–4 个支撑判断；
- 每个判断对应的事实或待核项；
- 已经放弃的写作方向；
- 读者看完后应该重新理解什么；
- `personal` 或 `company` 模式；
- 一个主要开场发动机及首屏压力；
- 2–3 张不同发动机的开场卡、最终选择和放弃原因，或只保留一种开法的证据理由；
- 一个主要叙事发动机及一句话故事主线；
- 一张每节四格完整、能说明段落依赖的叙事链表；
- 一条读者追问链；
- 最强对手、证据，以及在第几拍正面接它；
- 重点修辞的具体表达任务、指向和直接说法，或「本稿不预设高显著性修辞」；
- 拟定小标题、各节任务及前后逻辑依赖；
- 必要事实锚点与明确不写的方向；
- L3 用户选定的路线卡，或 L2 `not_required`；
- 已确认的声音锚点及其信息关系，不复制表面词句；
- 实际发生的决策摘要；
- 用户明确确认和日期。

锁定后才允许把小节／段落契约写入 `research/co-writing-log.md` 并开始正文。后续若主判断、共同处境、选定路线或写作模式发生实质变化，重新打开共创记录并再次确认。

## 个人稿与公司稿

### `personal`

可以使用真实、相关且允许公开的第一人称经历。个人案例负责让共同处境变得具体，不能单独证明所有人都会如此。

### `company`

个人经历可以帮助发现问题，但不直接充当公司正文的公开证据。正文默认改用可核实的新闻、研究、产品变化、数据或真实人物案例承接；找不到支撑时，降低结论力度或暂时不用。不得把个人经历改写成虚假的「很多人都这样」。

公司稿默认不用作者的「我」；「我们」只有在确实代表媒体、编辑部或已获授权的集体观察时使用。

## 通过条件

- 用户已确认标题方向、唯一主判断、故事主线、追问链和逻辑推进；
- 用户能够复述唯一主判断；
- 2–4 个支撑判断都服务同一主判断；
- 普通人的共同处境从开头参与结构，不是结尾临时补上一段；
- 首屏不是公司、日期、投资、人物履历和背景的新闻摘要堆叠；
- 开场卡改变的是叙事入口，不是同一句话的同义改写；
- 全文沿一个主要叙事发动机推进，每一节都让局面发生变化；
- 叙事链表每节四格完整；线性稿逐节回答上一问并逼出下一问，平行稿声明并使用唯一共享尺度；
- 最强对手非空并已安排正面回应，或稿件已明确降级；
- 重点修辞有具体表达任务和指向，而不是把「制造文章感」写成任务；
- 隐去小标题后，读者仍能说明为什么这一节必须接在上一节之后；真实平行比较则能说出统一尺度；
- 事实、作者观察和待核项没有混写；
- 公司稿没有把个人经历偷换成普遍事实；
- `research/co-writing-log.md` 引用这份共创记录、选定路线与确认日期；
- 讨论记录已锁定，用户确认可追溯。

## 失败信号

- 没有讨论或用户确认就出现完整正文；
- 只问用户「想怎么写」，没有主动提交推荐方案；
- 保留多个并列中心，靠流畅文字掩盖分歧；
- 让 AI 评审投票代替用户选择路线，或把多条路线自动拼成一篇；
- 记录只改句子，没有产生决定；
- 用「普通人」作空泛称呼，却说不出具体处境；
- 把热点事实当作钩子，却没有冲突、代价、悬念或选择；
- 只给新闻导语换语气词，没有尝试另一种开场发动机；
- 用来源顺序、五项能力或论文主题直接充当正文目录；
- 先起一套整齐小标题，再把研究材料逐格填进去；
- 用「这里需要张力／金句／升华」代替具体表达任务；
- 计划中的抽象判断删去后没有任何事实、关系、决定或后果损失；
- 同时使用多个叙事发动机，开头、主体和结尾各讲一套故事；
- 证据还没找到，结论已经写满；
- 用禁写边界清单删光反方材料，使文章从设计阶段就没有对手；
- 公司稿偷渡第一人称经验或虚构共识。
