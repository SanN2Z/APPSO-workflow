# 微信公众号平台指令

本文件继承项目根 `AGENTS.md`，并补充公众号专属规则。

- 正文默认交付 Markdown，图片使用内容包内的相对路径。
- 正式稿件位于独立内容包；想法阶段只需 `draft.md`，来源、审校、终校、素材和发布记录随状态逐步增加。进入 `ready` 前必须补齐对应硬门记录。
- 标题负责承诺，开头尽快兑现；不要为了点击率把推断写成事实。
- 长文要有故事线和证据链。小标题服务阅读节奏，不要每两段就做一次总结。
- 语气自然、有人味；避免套话、机械排比、重复解释和密集的“首先/其次/最后”。
- 厂商跑分、独立评测和作者判断必须分开；图表注明数据来源和比较口径。
- 读者可见的公众号正文不保留 Markdown 或 HTML 表格；需要行列对照时，表格只留在 `research/` 作为底稿，发布正文改做 `infographic`。只有用户在当前稿件中明确要求保留表格时例外。
- 社交平台截图要保留必要上下文，处理隐私信息，并在图注说明来源。
- 有公开讨论面的产品或热点稿，视觉调研默认同时保留两类候选：一类有可见热度、能证明真实摩擦；一类未必最高热度，但角度新鲜、具体，能引发讨论。按平台分别记录来源 URL、取证时间、页面可见互动量、上下文、隐私与权利状态，不把跨平台原始互动数混排成统一榜单。若话题没有公开讨论面，或访问、隐私、权利条件不允许，须在研究笔记说明例外。
- 每篇稿件都要识别真正值得记忆和传播的判断；适合图像化时优先用一张与论点直接相连的 `clumsy_doodle`，不为凑数量添加装饰图。
- 官方产品图必须保留出处；发布前人工确认版权与转载边界。
- 不直接登录公众号后台，不代替用户群发。只有用户明确要求时才准备发布操作。
