## Fable Max 5x 额度控制

「Max 5x」是订阅档位，不是模型的 max 推理档。本次不默认启用最高 Effort、子 Agent 或长规划。

- 两边都先选择 CLI 中明确可用的 medium 档；若一边没有该档，记录实际设置，称「指定配置下的产品体验」，不声称计算量相同。运行前记录 CLI 版本、模型完整 ID、Effort、工具、账户额度页面和时间。
- Fable 仅跑 C02，一份 6 件商品的数据、一个本地静态页面，不提供大仓库，不搜索、不安装依赖、不启用多 Agent。首轮 8 分钟到点即停。
- 本轮 Fable 的人为停止阈值：相对起点，5 小时已用额度增加 10 个百分点，或全模型周已用额度增加 2 个百分点，或 Fable 专用周已用额度增加 3 个百分点，任一先到即结束。各百分比的分母不同，不能相加。上述数字是保守的实验预算，不是官方保证。
- 每题前后截图；约每 60 秒查看一次可见用量。一次调用也可能跨过阈值，Prompt 不能保证硬限额。用量不可见或延迟明显时，不触发第二轮；首轮仍按 8 分钟上限人工中断。
- 单题采用上表的外部计时器；时间到由操作者中断当前 CLI，并确认没有仍在运行的子进程或模型任务。写进 Prompt 的分钟数和工具次数只是软约束。
- 不为本轮开付费用量、不购买 Credits、不自动续跑。触达限制记录为「预算内未完成」，不能写成模型完全不会。
- Fable 默认 1 个新会话、1 条完整任务消息。首轮已完成且三个用量增量均低于对应阈值的一半时，才可发送 C02 的固定修改要求；两边都发相同要求。额度不够就双方只比较首轮，不能拿 Astra 修改版对 Fable 首版。
- 即使执行可选修改，Fable 也最多 1 个会话、2 条任务消息。消息数不等于后端模型调用数。其余所有案例不调用 Fable。

官方帮助页确认：Max 中 Fable 属于套餐内使用，消耗普通周额度且有 Fable 使用上限，不能把 API 单价或缓存折扣换算成订阅百分比。来源见 S03。

## 隔离与公平

每题从 `cases/Cxx/input/` 单独复制到干净实验目录，再分别复制给 Astra 和 Fable。不要从运营仓库根目录启动被测 CLI，避免读取本仓库 Skills、历史文章和裁判答案。`prompts.md` 的首轮文本手动粘贴，固定追问到第二轮才发。`judge/`、来源调研与另一个模型产物全部留在实验目录外。

两边关闭个人记忆／自定义规则／额外插件，或记录无法关闭的差异。全程单 Agent；只有 C05 允许联网检索，其余题只读给定文件、写当前目录、执行本地代码。浏览器仅访问本地页面。两边使用相同预装浏览器及基础运行时，预检 Python、Node、截图工具能用，预检不调用被测模型。

如果能力配置有差异，保留两个层次：同输入同预算的成果对照，以及实际 CLI 配套工具带来的体验差异。不可把 Codex 与 Claude Code 的工具差异写成纯模型差异。固定追问在首轮完成后发送；这测「修改后保持约束」，不冒充运行中异步转向测试。

只运行一次也可以做体验稿，但每题必须标注 n=1。先冻结题目、评分规则、修改语句和额度阈值，再开跑；不看过一边结果后给另一边加强 Prompt。首轮失败也保留，不只截图成功作品。不能用输出 Token 少直接推导成本更低；如果看不到缓存、推理和工具用量，就只记可观察项。

## 统一前置提示词

每个新会话先附下面这段，再附该题首轮任务。具体工具开关仍由操作者配置。

```text
这是一次有固定边界的单人工作任务。只读取当前目录，产物只写当前目录。
只由你一个 Agent 完成，不创建或调用子 Agent，不进入长时间自主循环，不调用其他模型。
不要安装依赖或读取上级目录、个人历史、其他项目。除任务明确允许外，不联网。
直接完成可交付结果，计划至多 5 行。不需要向我解释内部推理。
如果当前环境缺关键能力，保留已有成果，说明具体缺项；不要假装测试、截图或功能已经完成。
交付后停止。最终回执最多 150 字，列文件、实际验证和未完成项。
```

## 评分与呈现

视觉横评先匿名 A／B 盲看，再揭示模型。写作只评价 Astra 首轮与修改后的完成度。至少由作者本人做独立判断；有第二位读者则分开记录，不必为了评分再消耗 Fable。每题按 `judge/rubric.md` 的 4 项各记 0／1／2：缺失或错误／部分达成／达成。不能以颜色、行数、长度或动画数量直接打高分。

功能门、事实门独立记录。漂亮但按钮失效不算可交付；文笔好但捏造采访也不算合格。主文不合成一个跨题总分，不用 3 个样本选「世界最强模型」。记录首轮交付、固定追问后交付、人工救援、时间、额度和阻塞原因。

网页统一桌面 1440 × 1000、手机 390 × 844、缩放 100%、同一滚动位置；保留首屏和一个关键交互，不能给一边挑最佳截图。写作使用同字体同字号排版，避免把页面美化混入文笔对比。截图中的用户名、用量账号信息先处理隐私；原始证据留研究目录。

建议文章图序：C02 两张作品首屏开场 → C01 同段文字对照 → C03 一次真实修复 → C06／C04 完整交付 → 一张官方图交代定位 → ARC Prize 框架差异图给结论加边界。官方图不替代自己的实测证据。
