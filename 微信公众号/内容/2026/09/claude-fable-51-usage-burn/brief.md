# Brief

## 任务与稿型

- 选题：Fable 5.1 上线首夜的真实用户体验，重点调查快速用量消耗、Agent 扩张和预算可控性。
- 平台：微信公众号。
- 稿型：首日实测 / 社区现场 / 产品判断。
- 生产档位：L2，直接写 canonical draft；不并行修改正文。
- 目标读者：Claude Code、Max / Pro 订阅用户，以及考虑把 Fable 5.1 设为默认模型的开发者。
- 一句话承诺：读者看完能分清作者本人的可疑额度跳变、正常但昂贵的 Agent 蜂群，以及 Fable 5.1 真正值得调用的任务。

## 锁定的作者时间线

- 测试开始时，当前 5 小时用量为 17%。
- 作者只发出一条 Prompt，仍处于 Plan Mode，正式实现未开始。
- 大约 10 分钟内，用量先从 17% 跳到 90% 多；此时尚未出现可见子 Agent 调用。
- 随后模型调起一个可见子 Agent，用量才从 90% 多瞬间到 100%。
- 因此，不能用后续子 Agent 解释掉前一段大幅跳变；正文将其称为「bug 级体验」，不把技术根因写死。

- 标题方向：`Fable 5.1 还没开工，5 小时额度先没了`。
- 开场冲突：工人还没进场，油表先掉进红区。

- 结尾判断：暂不设为默认主力；高难度、验收明确的任务可选择性调用。

## 写作边界

- 事实边界、证据强弱和替代解释完整保留在 `sources.md` 与 `research/fact-sheet.md`，不逐段泄漏到公开正文。

- 不写 Anthropic 已确认计量 bug；也不把所有社区帖子概括成统一故障率。
