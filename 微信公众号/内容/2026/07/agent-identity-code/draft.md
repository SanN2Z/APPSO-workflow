# AI Agent 开始拿钱包了，中国先给它办「身份证」

> 当 Agent 能跨应用叫车、寄快递，甚至收钱和转账，问题就不再只是「它聪不聪明」。我们还得知道：它到底是谁，谁允许它行动，出了问题该找谁。

这周，Agent 像是集体过了一次成人礼。

7 月 20 日，美国金融科技公司 Natural 宣布完成 3000 万美元 A 轮融资，同时称面向 Agent 的钱包、付款、请款、转账等 6 项产品已经上线。它不是银行，账户服务由合作银行提供；但产品方向很直白：有人已经在搭 Agent 移动资金所需的管道。

同一天，《经济日报》在 WAIC 观察中写到另一幕：阶跃的终端 Agent 负责理解和调度，支付宝「阿宝」接过任务，调用出行、本地生活和支付服务。以后帮你办事的未必是一个无所不能的 AI，而可能是一串互相交接任务的 Agent。

一边有人给 Agent 做钱包，一边有人让 Agent 跨应用跑腿。到了这一步，「对面到底是谁」就不能再靠一句自我介绍。

中国给出的第一套答案，是一组智能体互联标准。

## 不是一张证，而是一套「社会规则」

2026 年 5 月 22 日，国家市场监管总局批准发布了《人工智能 智能体互联》系列文件。6 月的官方发布会把它概括为 7 个部分：

1. 总体架构：整套互联体系的地图；
2. 身份码：给每个 Agent 一个可识别的编号；
3. 身份管理：围绕身份完成注册、核验和管理；
4. 智能体描述：说明「我能做什么」；
5. 智能体发现：让其他 Agent 找得到合适的协作者；
6. 智能体交互：约定双方怎样通信；
7. 智能体工具调用：约定怎样使用外部工具。

![国家市场监管总局公告附件中的智能体互联系列文件清单](assets/samr-seven-standards-official.png)

*国家市场监管总局公告附件中的 7 项智能体互联文件。图源：国家市场监管总局*

这里还有一个很容易被标题带跑的数字细节。市场监管总局那份公告写的是「批准发布 8 项国家标准化指导性技术文件」，但附件第 1 项是乐器有害物质测试，后面 7 项才是 Agent 系列。也就是说，公告里有 8 项文件，智能体互联本身是 7 件套。

更重要的是，它们的编号是 `GB/Z`，当前属于「国家标准化指导性技术文件」，不是要求所有 Agent 立刻持证上岗的强制标准。市场监管总局说，后续将适时推进身份码相关标准向强制性国家标准转化；那是下一步，不是已经发生的事实。

所以，把它叫作 Agent「身份证」很好懂，但别把这个比喻理解得太满。

身份码更像证件上的号码，解决的是机器之间如何稳定地指向同一个 Agent；身份管理才继续处理注册、核验等问题。能力描述像简历，发现机制像通讯录，交互与工具调用则像不同机构之间的办事规则。

只有把这些拼起来，一个 Agent 才可能在离开自家应用后，仍然让另一套系统知道它是谁、会什么、该怎样和它协作。

## Agent 一旦开始「转交任务」，身份就不再是装饰

支付宝在 4 月提交给 W3C 会议的技术演示里，已经把 Agent 注册、发现、认证、证书签发和安全通信画进了同一套架构。7 月，它又与阶跃展示跨端协作：终端 Agent 理解用户要什么，再把具体服务交给支付宝 Agent 执行。

![支付宝在 W3C 会议材料中展示的 Agent Hub Access 架构](assets/alipay-aha-w3c-official.png)

*支付宝在 W3C 会议材料中展示的 Agent Hub Access 架构，包含注册、发现、认证和证书签发。图源：W3C 会议材料 / 支付宝*

这和过去「打开支付宝，自己点打车」有本质区别。

过去，用户知道自己进了哪个 App，也能看到每一步。现在，入口可能是手机助手、车机或眼镜。它把意图交给第二个 Agent，第二个 Agent 再调用地图、支付和商家服务。每多转一手，责任链就长一截：原始指令有没有被改写？对方真是它声称的服务方吗？拿到的是查信息权限，还是下单和扣款权限？

身份码不能独自回答所有问题，但它提供了一个共同索引。没有稳定身份，授权、日志、撤销和追责都很容易变成一笔糊涂账。

官方 6 月口径称，已有 50 多家企业开展标准试点应用。7 月 22 日，IT 之家又报道，北京一场专题会启动新一轮试点，美团、滴滴、联想等 18 家单位首批签约并发放身份码。由于这场活动的主办方原始新闻页尚未检索到，18 家与现场发码细节在本文中只作为媒体报道的试点信号，不当作已经全国互通的证明。

## 有身份证，不等于不会干坏事

如果说跨 Agent 协作让身份变得必要，支付则把问题推到了更现实的位置。

Natural 的官方介绍显示，它已上线 Agent 钱包、付款、请款、转账等产品，并把「身份与可观测性」列入支付基础设施。它同时明确说明，自己不是银行。3000 万美元融资只能证明资本愿意下注，不能证明 Agent 已经大规模掌管真实资金。

![Natural 官方公告展示的 Agent 支付产品](assets/natural-agent-payments-official.png)

*Natural 于 7 月 20 日公布融资与 Agent 支付产品。图源：Natural*

但这个方向已经足够说明问题：一旦 Agent 能碰钱，「它是谁」只是第一问。

一个身份真实的 Agent，仍可能理解错指令、被提示注入、调用错误工具，或者在权限边界外继续行动。它也可能确实来自某家公司，却没有得到用户对这笔交易的授权。

身份证解决冒名，解决不了持证者被劫持；能追到责任主体，也不等于损失会自动撤销。

国家信息中心 5 月组织的研究任务组，已经把「身份凭证与行为归责」放在一起讨论，提出要让 Agent 与其所有者的法定身份建立关联，并让 AI 行为可追溯。这个动作恰好说明：身份码只是治理的起点，真正棘手的是身份后面的授权和责任。

统一身份还会带来另一面。跨平台识别越方便，数据被关联的范围也可能越大。谁能查询身份？哪些行为被记录？日志保存多久？用户能不能要求注销和删除？如果这些问题没有同步设计，「可追责」也可能滑向「过度追踪」。

## 下次让 Agent 替你办事，先问 5 句话

普通用户不必先读完 7 份标准。真正把高权限任务交给 Agent 前，先看产品能否回答这 5 个问题：

1. 它是谁？跨系统后，身份还能被对方验证吗？
2. 谁授权？是你本人、公司管理员，还是某个上游 Agent？
3. 能做多少？有没有金额、工具、数据范围和有效期限制？
4. 怎么叫停？授权能否立即撤销，正在执行的任务能否中断？
5. 出错找谁？能否看到从原始意图、任务转交到工具调用的完整记录？

身份码主要把第一个问题标准化，并为后面 4 个问题提供挂钩的位置。它不是一枚「可信 AI」奖章，也不会自动替用户补上权限控制。

Agent 真正的成年礼，不是说话更像人，而是它开始进入别人的服务、账户和责任范围。

钱包正在被造出来，跨应用的办事链也已经出现。给 Agent 一个稳定身份，几乎是必经之路。

只是身份证发下去之后，行业还欠我们更重要的答案：谁替它签字，谁能随时收回钥匙，以及它闯祸时，账单到底寄给谁。
