# Frontend Arena：三模型同题前端对比

建立日期：2026-07-25
用途：本内容包的实测证据源。产出结果进入 `sources.md` 的「作者体验」类目，不作为模型能力的主证据。

## 一句话说明

**同一段 prompt，GPT-5.6 Sol / Claude Opus 5 / Claude Sonnet 5 各写 3 次，九份产物并排比。**

这题的价值在于失败模式是视觉化的。球穿墙飞出去、球陷在壁里发抖、拖滑块直接炸开，读者不用看一行代码就知道谁做对了。

## 三个模型，两条轴

| 模型 | 定价（每百万 token） | 位置 |
|---|---|---|
| GPT-5.6 Sol | $5 / $30 | OpenAI 旗舰，2026-07-09 GA |
| Claude Opus 5 | $5 / $25 | Anthropic 旗舰，2026-07-24 发布 |
| Claude Sonnet 5 | $3 / $15（8 月 31 日前促销 $2 / $10） | Anthropic 中档 |

**跨厂轴：Opus 5 ↔ GPT-5.6 Sol。** 两家旗舰输入同价，输出 Opus 5 便宜六分之一。价格站在同一起跑线上，这是最干净的正面对比。代价是 thinking level 和 reasoning effort 分属两套体系，只能对到「相近」，这个漏洞无法消除，写稿必须交代。

**档位轴：Opus 5 ↔ Sonnet 5。** 同厂同代，共用一套档位体系，可以设成完全相同。回答的是「日常活儿用便宜那个行不行」。

```powershell
Get-FileHash */PROMPT.md -Algorithm SHA256 | Select-Object Hash, Path
```

不一致就说明三边不是同一道题，结果作废。

## 怎么跑

每个模型 3 次，共 9 次。每次：

| 项目 | 要求 | 为什么 |
|---|---|---|
| 会话 | 全新会话 | 同会话连跑，后一次会参考前一次的实现 |
| 输入 | 对应目录 `PROMPT.md` 的全文，逐字粘贴 | 顺手加一句「注意物理正确」就毁了这次对比 |
| 联网 | 关闭 | 开了可能检索到现成实现 |
| 代码执行 | 关闭 | 这题测的是一次成型，不是调试能力 |
| 思考档位 | Opus 5 与 Sonnet 5 设成**完全相同**的 thinking level；GPT-5.6 Sol 的 reasoning effort 取最接近的一档，并把两边的实际取值都记进 `记录.md` | 同厂能严格对齐，跨厂只能相近 |
| 轮次 | 只取第一次输出，不追问、不让它改 | 一旦允许迭代，测的就是另一件事 |

模型输出的代码原样存成对应 `run-N/index.html`，不要顺手格式化或修 bug。元数据和判分填 `run-N/记录.md`。

输出被截断、需要说「继续」才写完的，**照样保留**，并在记录里注明。一次能不能写完本身就是差异的一部分。

## 判分

每份 `记录.md` 里有完整检查表，满分 30 分：硬门 → 物理正确性 15 分 → 完成度 15 分。

**切向传动那一项（4 分）是这道题的胜负手。** 它要求模型意识到：碰撞点的墙面速度等于角速度叉乘该点到中心的向量，得把这个速度并进相对速度再算冲量。漏掉它画面照样动、照样有球在弹，得盯着看才发现球从来没被壁带着转。这一项同时考「做对」和「有没有偷懒」。

九份跑完，填这张汇总表：

| | GPT-5.6 Sol | Opus 5 | Sonnet 5 |
|---|---|---|---|
| 硬门通过（3 次中几次） | | | |
| 切向传动做对（3 次中几次） | | | |
| 穿墙 / 卡墙（3 次中几次出现） | | | |
| 改边数或反转导致炸开 | | | |
| 交互三项齐全 | | | |
| 一次成型（未截断） | | | |
| 平均分 / 最高 / 最低 | | | |
| 平均输出 token | | | |
| 平均成本（美元） | | | |
| 每美元得分 | | | |

### 成本这一列要认真算

三个模型的 tokenizer 互不相同，**Sonnet 5 同样文本比上代多算约 30% token**。这道题输出量大，一份完整单文件 HTML 通常几百行，tokenizer 差异会被放大。所以 token 用量必须取接口返回值，不能按字数估算，更不能拿价目表倒推。

```text
每美元得分 = 平均分 ÷ 平均单次成本（美元）
```

预期会出现的一种结果：Sonnet 5 绝对分最低，但每美元得分最高。这不矛盾，也不该被藏起来——它恰好是读者选型时最需要的那个数。

### 区分度标注（诚实性硬门）

**如果三个模型的分差小于同一模型三次运行的波动范围，这次测试的结论就是「这道题上分不出来」。** 这个结论照写，它本身有信息量——说明官方 benchmark 上的差距未必出现在你手上的活儿里。

同样地，某个检查项如果三个模型全做对或全做错，这一项对本次测试无区分度，在汇总表里标灰，不计入分差解释。

## 素材

固定参数录制：**边数 6、角速度 80%、球数 40**。九份产物都用这一组，否则截图没法并排比。

- 每份存静态截图 + 15 秒录屏
- 出现失败的，单独截那一帧。**球穿墙飞出去的瞬间就是最好的配图**
- 最值钱的一张图是 **3 × 3 九宫格**：横轴三个模型，纵轴三次运行，同一时刻同一参数。稳定性差异一眼可见，比任何分数表都直观

素材落盘后按项目规范登记进内容包的 `asset-manifest.yml`，标明由本项目自行运行生成，权利自有。

## 三个容易翻车的点

**顺手补一句提示。** 看到模型漏了切向传动，忍不住说一句「注意墙是转的」——这一句让这次运行作废。有话等九次跑完再说。

**只留最好的一次。** 三次里挑最像样的代表模型水平，等于把方差藏起来。九份全留，方差本身是结论的一部分。

**参数不统一就截图。** 每次手动拖到「差不多」的角速度，截出来的图没有可比性。滑块拖到底再回退固定格数，或者直接在记录里写清读数。

## 限制（写稿必须交代）

- 样本 3 次，只能说明这一天这个档位下的表现，不能推广成模型排名。
- 题目为本项目自拟，不是标准 benchmark，没有第三方复现，判分标准也是自定的。
- **跨厂的思考档位无法严格对齐。** GPT-5.6 Sol 的 reasoning effort 与 Claude 的 thinking level 分属两套体系，只能取相近档。这是本测试最大的方法缺陷，不能靠措辞绕过去。
- 同一档位下三个模型消耗的思考 token 并不一样，这一点在成本列里体现，但无法消除。
- 判分含主观项（视觉观感、代码可读性），已单列，不与物理分混算。
- 这道题只考「一次成型写一个物理动画」。它不能代表编程能力全貌，更不能代表模型的整体能力。
