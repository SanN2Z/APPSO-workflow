# 论证地图

## 主张

Agent 安全正在从“模型会不会听一句坏话”变成“外部资料能不能借模型之手动用真实权限”。GPT‑Red 把一个会持续适应防守的攻击者接进训练，解决的是安全评测和攻击样本更新速度跟不上 Agent 能力的问题。

## 因果链

1. Agent 为了办事，需要读取网页、邮件、文件和工具返回。
2. 这些外部内容由第三方控制，可能夹带恶意指令。
3. Agent 同时拥有浏览、发信、下单、改代码或调用内部工具的权限。
4. 一旦模型把第三方文字错当成用户意图，文本错误就会变成真实动作。
5. 固定 benchmark 只能覆盖已知攻击；防守在旧题上接近满分后，攻击者仍会针对新模型和新工具组合适应。
6. GPT‑Red 通过攻防共同训练持续生产新攻击，再把成功样本送回生产模型训练。
7. 因而 Agent 安全评测需要同时检验自适应攻击、完整系统和权限边界，不能只报静态模型分数。

## 最强证据

- 受控售货机测试从模拟迁移到实际运行 Agent，说明攻击不只在提示框里改变一段文字，而能触发定价、采购和取消订单工具。
- 84% 场景覆盖显示自动化搜索在该内部复刻设置中能广泛找到攻击，但预算不透明，不能包装成人类能力淘汰赛。
- 部分旧间接注入 benchmark 已超过 97%，同时新攻击仍可打穿另一套真实系统，说明 benchmark 饱和与系统安全不是同一件事。

## 反方与回应

### “模型都 99% 安全了，剩下只是极端案例”

内部 benchmark 只描述其题目分布。Agent 一旦获得高风险权限，少量失败也可能产生真实动作；更重要的是攻击者会改变题目。

### “让 Agent 一律拒绝外部指令不就行了”

Agent 的工作正是读取并使用外部资料。防守模型的奖励同时要求抵抗攻击和完成原任务，说明可用性与安全必须一起测。

### “84% 已证明 AI 红队比人类强”

公开页面没有给出等时间、等查询、等 token 的详细协议。现有证据只能支持 GPT‑Red 在这套内部 mirror 上覆盖更多场景。

### “训练一个攻击模型就解决了提示词注入”

GPT‑Red 主要强化模型层。最小权限、关键动作确认、隔离、监控、撤销和审计仍属于系统层；OpenAI 自己也强调分层防守。

## 可迁移判断

以后看 Agent 的安全宣称，优先检查：攻击集合是否会适应防守；测试对象是否包含真实工具和权限；高风险动作是否有模型之外的硬关口。
