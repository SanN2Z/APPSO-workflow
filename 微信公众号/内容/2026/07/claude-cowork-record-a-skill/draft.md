# Claude 新增 `Record a skill`：你做一遍，它自动生成 Skill

> 有些活，自己做只要 3 分钟，教给 AI 却要半小时。Claude 的新办法是：别写说明书了，你做一遍，我在旁边学。

每周发稿前，我都要干一件闭着眼都能完成的活：整理配图。

官方截图挑出来放一边，AI 生成图放另一边；文件名重新编号，最后补一份素材清单。手比脑子快，几分钟收工。

有天我想偷懒，把这活交给 AI，麻烦立刻来了。我得解释先看什么、为什么这么分、遇到重名怎么办、哪类文件绝对不能动——一件靠手感完成的小事，硬生生要写成一份谁也不想看的员工手册。

规则写到第三条，我放弃了。自己动手还快点。

昨晚（北京时间 7 月 21 日），Claude 发布了一个专门解决这类麻烦的功能。

Cowork 新增了一个按钮，叫 `Record a skill`：开始录制后，你照常干活，边做边把思路说出声；结束后，Claude 会把这次示范整理成一个以后可以反复调用的 Skill。

![Claude 官方宣布 Cowork 新增 Record a skill](assets/claude-record-a-skill-official-post.png)

*Claude 官方发布 `Record a skill`。图源：@claudeai*

以前是你给 AI 写 SOP；现在，它坐在旁边看你干一遍。

网友 Bruce Martin 留言：「做给 AI 看，比解释 47 遍强多了。」

![网友认为演示一遍比反复解释更有效](assets/bruce-show-dont-tell-reaction-user.png)

## 怎么用：找到按钮，然后边做边说

入口在 Claude 桌面应用的 Cowork 里。点输入框旁边的「+」，就能看到 `Record a skill`。官方标注支持 Pro、Max 和 Team 套餐。

![Claude Record a skill 官方产品示意图](assets/claude-record-a-skill-official-ui.jpg)

*Claude 官方产品示意图展示了入口、录制提示，以及 Skill 的保存结果。图源：Claude 官方 X 账号*

按下 `Start recording` 后，照常操作，同时把「为什么这么做」说出声。停止录制后，Claude 会分析这次示范，存成一个 Skill。官方示意图里的例子只录了 23.4 秒，产出一个叫 `/file-expenses` 的 Skill。

如果没有看到按钮，先把应用更新到最新版并重启；仍然没有，可能是功能还没推送到账号。Reddit 上就有 Pro 用户一开始没有按钮，后来才看到入口。

这里的 Skill 是一份 Claude 能反复调用的工作说明：什么时候用、按什么步骤做、遇到例外怎么处理。以前这份说明要你亲手写，现在 Claude 想从你的示范里提炼出规则。

如果 Claude 能从示范里提炼规则，下次它就能重做整段流程：录一遍月报流程，以后它自己导数据、清洗、做表、备好邮件草稿；录一遍发布流程，它记住图片尺寸、标签顺序和封面安全区；录一遍报销流程，连「超过 1000 元要注明项目名称」这种从没写进手册的规矩都一起带走。

这些场景目前都只是设想，没有完整实测。它们都包含没写进手册、只有操作者知道的判断。

## Codex 上个月已经上线，实测并不总是省事

OpenAI 在 6 月 18 日就上线了同类功能 `Record & Replay`。你在电脑上完整做一遍，Codex 观察操作，再把流程整理成 Skill。下次新开对话，只要说明换了哪个文件、报表要哪段时间，它就按同一套规则继续做。

APPSO 报道这个功能时，一条读者评论写道：「我的『好兄弟』正在『蒸馏』我」。

对没有现成 API 的流程，这类产品给了另一种做法：AI 观察你怎么点按钮、切窗口、填表单，再把这些步骤整理成 Skill。

OpenAI 列出的任务包括报销、订停车位、创建一条配置正确的 issue、发视频和拉周期性报表。这些任务要么步骤固定而繁琐，要么依赖只有操作者知道的规则。目前，该功能只能在 macOS 上使用，首发不覆盖欧洲经济区、英国和瑞士；使用前还要开启 Computer Use，让 Codex 能查看屏幕并操作鼠标和键盘。

一个月后，Anthropic 在 Cowork 中推出了相似功能。有网友把两家的差别总结成段子：「Codex 记住你点了哪里，Claude 听你解释为什么点。」

![网友比较 Codex 与 Claude 的录屏生成 Skill 功能](assets/priorshift-codex-claude-compare-user.png)

*网友对两种产品思路的概括。图源：@priorshift；仅作评论引用*

这句对比并不准确。OpenAI 的官方说明写着，Codex 会观察你的操作和窗口内容，录制前还会先让你补充任务背景；生成的 Skill 会写明何时使用、需要哪些输入、按哪些步骤执行，以及如何验证结果。Claude 这边则专门强调，录制中的语音也会被一并记录。因此，「只记点击位置」漏掉了 Codex 使用的任务背景和验收方法。

程序员鱼皮上个月用 Codex 测了一个真实需求：从网易云音乐下载指定风格的 FLAC 音乐。他先说清要求，再演示搜索、下载和检查格式；Codex 随后生成了一个可编辑的 Skill，并在新对话里复现了整套流程。

他的评价并不高：跑得慢，偶尔点错；一两句话能说清的任务，直接打字更省事。他认为，这类功能更适合「说不清，但做得出」的流程，比如在不熟悉的公司 OA 系统里办事、按个人偏好整理报表，或者跨好几个应用完成一串操作。

语音解释能否减少 Claude 复现错误动作的情况，仍需完整实测。

## 录制时，多讲理由，少报鼠标位置

第一次练手，别碰公司后台、真实报销单和客户资料。新建一个独立文件夹，扔几张虚构配图进去，就够了。规则也不用复杂：以 `official-` 开头的文件放进官方素材文件夹，以 `ai-` 开头的文件放进 AI 素材文件夹；跳过文本文件，重新编号，最后生成一份清单；不许删原件，遇到重名或陌生前缀要停下来问。

如果只播报鼠标动作，旁白会像这样：

> 「我现在把这张图拖过来，改个名字，再弄下一张。」

这种讲法只告诉了 Claude 你做了什么。更有用的讲法是：

> 「文件名以 `official-` 开头的是官方素材。文件名、数量和路径下次都会变，请学分类规则，别记住今天这批文件。目标位置有同名文件时不要覆盖，先停下来报告。」

前一句教动作，后一句才教方法。

录之前，先用这 5 个问题检查旁白：

1. 最后要交付什么？
2. 为什么这样判断？
3. 哪些内容下次会变？
4. 遇到例外怎么办？
5. 做到什么才算结束？

官方提示显示，屏幕画面、鼠标点击、键盘输入和语音都会被记录并发送给 Claude。录制前要关掉聊天通知、密码管理器和无关窗口，更别一边教它整理图片、一边顺手登录网银。

## 生成 Skill 后，换一批材料再跑

Claude 生成 Skill 后，用刚才那批图再跑一遍，只能检查它能否用同一批材料完成同一任务。

要判断这套规则能否用在新材料上，至少要做三轮测试。

第一轮，换样本。把文件名、数量和顺序全换掉，看分类规则是否仍然有效。

第二轮，加异常。塞进一个陌生前缀的文件和一个重名文件，看它会停下来询问，还是直接猜测。

第三轮，测触发和重复执行。不提 Skill 的名字，只描述任务，看它能不能找到正确的方法；再连跑两次，检查它会不会重复编号或覆盖文件。

一项 Skill 能处理新材料、遇到例外会停、不点名也能被触发，才说明它可以复用。只在原样本上成功，说明它可能记住了示范，却没有学会规则。

## 截至 7 月 22 日，尚未找到完整复跑实测

Android Authority 作者的 Pro 账号已经出现按钮，Reddit 上也有 Pro 用户后来才看到入口。我查了 X、Reddit、YouTube 和几家独立媒体，但没有找到一份从录制、生成 Skill 到换新材料复跑的完整记录；前面三轮测试也没有现成结果可参考。

运行速度同样要等实测。网友 Rohit Sabu 此前吐槽，Claude 操作电脑像长辈用电脑；更让他不满的是，占用的还是用户自己的电脑。

![网友吐槽 Claude 操作电脑的速度](assets/rohitsabu-computer-use-critique-user.png)

*这是对 Claude 电脑操作体验的评论，不是对 `Record a skill` 再次运行效果的实测。图源：@rohitsabu_；仅作评论引用*

是否真能省时间，要看生成 Skill 和再次运行分别需要多久、会消耗多少额度，以及是否需要人全程盯着。如果自动化时仍得有人守在旁边，省下的可能只有几次点击。

`Record a skill` 的价值，取决于 Claude 能不能从示范里提炼出那些很难写进说明书的判断：为什么这张图要多看一眼，什么文件一看就不对劲，什么时候能自己处理，什么时候必须叫人。

等这个功能出现在我的账号里，我会拿前面那套「配图归档」任务复跑；录制耗时、异常处理和陌生文件上的结果，才是判断这份 Skill 能否复用的依据。
