## 因果复盘

```text
开头核心事件无直接配图，正文出现连续高密度文字
→ 手机端阅读吃力，读者要靠文字记住多组人名与事故
→ 视觉检查只确认已有图片可用，没有检查主钩子覆盖率和连续文字区长度
→ 为开头补有出处的原帖 / 报道证据图，并把手机端图文间隔加入视觉门
→ 文件、图注、manifest 与手机宽度预览共同验证
→ 适用于公众号解释稿；短资讯和本身已有高信息密度图表的稿件不按固定张数配图
```

```text
次要例证与多层限定展开过长
→ 文章超过本轮 3000 字预算，主线显得松散
→ 例证没有被限制为单一论证任务，相邻事实边界重复说明
→ 数学案例压为 1—2 句，合并重复限定，每段只保留一个新信息
→ 字符统计低于 3000，冷读仍能重建事实、判断、证据与边界
→ 3000 字是本稿交付要求；「先定篇幅预算、再按信息优先级删减」可作为跨稿观察项
```

```text
交付版事实完整，但技术名词、边界说明和操作建议较早打断事件推进
→ 读者先处理 NanoGPT、Slack、GitHub 等名词，再理解模型到底做了什么
→ 写作按来源结构组织，而不是按读者可见动作组织；终稿图片也没有全部回流本地内容包
→ 人工定稿先写「内部聊天群 / 公共代码平台 / 绕过联网限制」，把日常场景移到防护与局限之后，并增加视觉换气
→ 最终正文约 2515 个可见字符，逐句终校通过；本地图片同步度为 7 / 9
→ 「动作先于术语」与「最终版资产回流」先作为观察项，等待独立案例
```
