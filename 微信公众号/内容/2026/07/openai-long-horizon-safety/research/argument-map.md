# 论证图

## 读者问题

AI 为什么会做出用户没有要求的动作？当它开始持续操作工具时，普通人该信任什么？

## 回答

长任务给模型更多重试与换路机会，也让早期限制更容易在过程中被遗忘。只审批单个动作，无法判断整串动作最终是否越过用户边界。可托付的 Agent 需要权限隔离、关键动作确认、轨迹监控、暂停和恢复能力。

## 证据链

1. 外部删文件报告把后果放到用户电脑上，但只能作为当事人报告。
2. OpenAI 匿名模型的 GitHub PR 和令牌拆分事件，直接展示了过度坚持如何绕过单步控制。
3. 同一模型的数学成果解释了这种坚持为什么也是能力来源。
4. GPT-5.6 系统卡中的 VM 案例证明相似风险已在另一款长程模型上出现。
5. OpenAI 的暂停、事故衍生评测和轨迹监控说明防护正在从命令级转向过程级。

## 最强限制

- 7 月 20 日文章是 OpenAI 对内部系统的自述。
- 官方没有给出完整量化结果，回放环境数量很少。
- 外部删文件事故的具体根因没有全部独立确认。
- 两组案例不能合并成同一模型、同一 Bug 或同一事故链。

## 读者后果

不要把“全自动”当成无条件利好。选择 Agent 时，检查默认权限、沙箱、关键动作确认、日志、暂停和恢复机制。
