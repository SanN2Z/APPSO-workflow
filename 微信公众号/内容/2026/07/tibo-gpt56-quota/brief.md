- **目标读者**：关注 AI 新模型和行业竞争，但不会逐页阅读英文发布材料的中文读者。
- **读者盲区**：默认没完整看过 GPT-5.6 发布，不认识 Tibo，也不熟悉 Benchmark、`max` / `ultra`、token 单价和 Claude 的额度规则。
- **单一读者问题**：模型很强，但任务做到一半没额度，能力还算不算真正可用？
- **单一标题钩子**：任务中断 / 能不能把活做完。标题不再同时承载 Tibo、人名、三个词、GPT-5.6、Benchmark 和第二结论。

- **一句话承诺**：读完后，读者能用“峰值能力 + 四个产品化条件”判断一款 AI 是否真的适合长期工作，而不只看发布页跑分。

- **Brief 状态**：证据编辑已于 2026-07-12 完成前置事实卡，主编据此锁定；后续事实变化须退回证据编辑。
- **当前状态**：`editorial_review`。结构性重写期间 `fact_checked` 重新置为 `false`；图片权利未清前 `rights_checked` 保持 `false`。

## 核心因果主张

峰值能力决定模型理论上能做到什么；可获得性、工作连续性、成本可预测性和入口占有，决定这份能力能否稳定变成用户的日常产出。Claude 的额度重置主要改善工作连续性，也短暂改善可获得性；它是最容易被用户感知的信号，但不是“可用智能”的全部。

## 分析前的 60 秒事实卡

事实卡只建立共同背景，不在卡片里宣布胜负。具体名称、价格、上线范围和措辞以 `research/fact-sheet.md` 的当日复核结果为准，至少回答：

- GPT-5.6 有哪些档位，各自解决什么需求；
- 三档标准 API 价格的量级与梯度；
- `max` 和 `ultra` 分别是在给单模型更多预算，还是让多个 agent 并行；
- ChatGPT Work 与 Codex 的入口发生了什么变化；
- Claude reset 重置的是什么，不是什么。

## 统一框架

- **峰值能力**：模型在合适配置下会不会做，决定上限。
- **可获得性**：用户现在能不能拿到、谁能用。
- **工作连续性**：任务能不能从开始一直做到交付；本次额度 reset 主要落在这一维。
- **成本可预测性**：开始前能否大致估算一个任务最终会花多少钱，而非只看 token 单价。
- **入口占有**：模型是否进入用户每天打开的工作台、文件、工具、权限和上下文。

“可用智能”只作为后四个产品化条件的总称。正文、标题、小标题和配图必须使用相同名称；峰值能力单列，不能被画进四条件里造成混淆。

## 最强限制与替代解释

- GPT-5.6 发布会预定开播与 Claude reset 截图时间接近，不足以证明 Anthropic 因竞争临时拍板；Anthropic 没解释动机，同期服务事件也只能作为背景，不能反推原因。
- reset 不等于永久扩容、无限使用或 API 限流变化。
- 厂商跑分只能证明厂商在特定配置下报告了什么；配置不同、题集可能损坏，不能当统一裁决。
- token 单价不等于完成任务的总成本；重试、工具调用、等待和人工验收都会改变账单。
- 入口与用户规模多为厂商自报，能说明产品方向，不能直接证明长期留存。

## 结构与每节任务

| 顺序 | 段落任务 | 判断 | 主要证据 | 限制 | 读者后果 |
|---|---|---|---|---|---|
| 1 | 开场 | 一次额度 reset 之所以引发垃圾话，是因为任务中断已经成了真实竞争点 | ClaudeDevs 截图、Tibo 回复 | 不推断内部动机 | 圈外读者先看懂冲突 |
| 2 | 事实卡 | 先知道发布了什么，再讨论谁更值得用 | 三档、价格、max/ultra、Work、reset 定义 | 厂商信息不等于独立结论 | 不看发布会也能跟上 |
| 3 | 尽早给框架 | 聪明只是上限，四个产品化条件决定能否日常使用 | 文字定义 + 1+4 框架图 | 新概念必须由后文逐项验证 | 给读者一把贯穿全文的尺子 |
| 4 | 峰值能力 | 跑分能回答“会不会做”，不能单独回答“能否稳定交付” | 厂商六项评测、独立榜单、SWE-Bench Pro 审计 | 配置不同、独立数据未齐、题集缺陷 | 暂缓“全面碾压”判断 |
| 5 | 可获得性与连续性 | 拿得到且不中断，能力才会进入真实任务 | 上线范围、Claude reset 与额度规则 | reset 是短期动作，不等于永久提额 | 额度墙会迫使用户临时换工具 |
| 6 | 成本可预测性 | 便宜的 token 不一定带来便宜的交付 | 三档价格、max/ultra 工作方式 | 缺少统一任务总成本实测 | 团队采购不能只看单价 |
| 7 | 入口占有 | 每天打开的工作台比一次榜单领先更容易形成黏性 | ChatGPT Work / Codex 统一入口 | 用户规模为厂商自报 | 文件、权限、上下文提高迁移成本 |
| 8 | 回扣与结尾 | 额度不是全部，却最先把“能否完成工作”暴露给用户 | 四个条件回收 | 不把一次 reset 外推成胜负已定 | 长期赢家要把能力稳定变成产出 |

## 结尾任务

先回到 Tibo 的阴阳，再解释为什么双方产品动作比垃圾话更诚实。最后两三段必须回答标题，明确额度只是工作连续性的信号；最后一句落在“谁能最稳定地把能力变成用户日常产出，谁才更可能长期留下”，不再用“这场仗，请继续打”收尾。

## 必须准确表达

- `I smell fear` 直译是“我闻到了恐惧”，在此处是 Tibo 的贴脸阴阳，可译成“哇，给全员续杯了，我好怕怕哦～”。
- 厂商自报、第三方结果、作者判断、推断和玩梗在正文中各守边界。
- 所有时效性数值以 `as_of` 当日复核为准；无法复核则降低语气或删除。

## 不要做

- 不写成已证实的 Anthropic 内部应激反应。
- 不用单一厂商跑分宣布全面碾压。
- 不把 token 单价直接等同于完成任务的总成本。
- 不照搬参考文章的句子、独特比喻或收束方式。
- 不让一张公式图代替文字定义。
- 不把“多加几个梗”当成人话修复。
