# 内容复盘增补：从功能盘点转向统一任务横评

- 日期：2026-07-28

- 下次复核：2026-08-04

## 反馈

用户要求先做差异化调查，再用同一道任务比较千问办公、WorkBuddy 与 Codex；文章从官网功能指南改为场景化、用户视角的横评体验。结果尚未完成时，可以先写「为什么测、测什么、如何控制变量」，但不得预设胜负。

## 机制

```text
按产品菜单盘点功能
→ 读者知道产品能做什么，却不知道为什么要多装一个
→ 同类办公 Agent 的基础能力已经高度重叠，单项功能不足以形成选择依据
→ 改用同一任务、相同交付格式和原生模式横评
→ 以来源有效性、文件完整度、人工干预和返工时间判断实际价值
→ 等三组真实产物回收后再写结论
```

## 已完成修复

- 新建横评 Brief，不再沿用旧功能指南结构；
- 起草约 1700 字的结果前半篇，把篇幅留给实测结果；
- 明确 WorkBuddy 为国产桌面产品对照、Codex 为通用 Agent 基线；
- 设置千问办公官方数据能力的第二轮消融；
- 结果、标题结论、适用人群与不足继续留空。

## 验证

- 前半篇包含 3 个结果占位，没有产品优胜结论；
- 第一轮明确为默认模型、不开额外 Skill、不接自定义 API；
- 交付物和观察指标可以对应实际回收文件；
- 反例：如果稿件只是帮助读者查找入口或设置功能，菜单式指南仍然更直接，不能把横评结构推广到所有产品说明稿。

## SOP 处理

本条只保留在当前案例，不修改中央 SOP。待至少出现第二个「同类功能高度重叠、官网盘点无法形成选择依据」的独立案例后，再考虑提升为范围明确的规则。
