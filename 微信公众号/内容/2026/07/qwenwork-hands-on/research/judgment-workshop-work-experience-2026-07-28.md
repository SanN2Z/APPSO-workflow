# 千问办公体验稿判断记录

## 共同处境

内容工作者经常在浏览器、群聊、本地文件、来源表和稿件之间搬运材料。收到反馈后，还要回头同步标题、提纲、正文和事实依据。

## 当前主判断

「AI 住进电脑」不能由桌面客户端或文件生成证明。对内容工作者来说，要看公开来源、判断、稿件和反馈能否在一项任务中连续推进，同时不越过资料和发布权限。

## 支撑判断

1. 会生成文字，不等于能保持来源等级和事实边界。
2. IM 远程接管、本地文件与应用快照，才是千问办公区别于普通网页聊天工具的主要体验点。
3. 中心判断改变后的结构重写，比首次生成更能检验上下文与一致性。
4. Skill 和定时任务必须换材料复跑，不能只看创建成功。

## 放弃的方向

- 虚构的 60 人活动筹备；
- 一个早晨并行完成多项工作的想象场景；
- 为了覆盖官网六项能力而强塞 PPT、网页和 1688；
- 未核实的技能数量、子 Agent 和具体学术案例；
- 在实测前写「AI 真的住进来了」。

## 读者看完应重新理解

桌面 Agent 的价值不是再提供一个写作框，而是减少来源、反馈和文件之间的手工接线；它的成熟度也要用事实一致、修改成本和权限来衡量。

## 已确认的决策点

1. 稿型是产品体验稿；
2. 功能范围以千问办公官方资料为边界；
3. 只用一项连续任务；
4. 截图以可执行的文字占位；
5. 测试场景来自作者实际的 AI 热点选题和写稿工作。
