## 共同输入

- 读者：正在评估办公 Agent、手里有调研、运营、文件整理或周期报告任务的普通职场用户。
- 读者问题：千问办公能替用户完成哪一段具体工作，交回的结果能否直接进入下一步？
- 唯一核心判断：千问办公已经能把搜索、制表、写作和网页制作组织成一组可继续编辑的文件，适合终点明确的多步骤任务；来源分层仍需人工复核，1688、小红书等业务数据入口在本次免费账号中尚未完成验证。
- 一句话故事主线：把一项编辑部调研交给千问办公，沿着任务发出、等待、打开文件、核查页面文案和寻找业务数据入口的过程，判断它减少了哪些手工搬运，又把哪些责任留给了人。
- 读者追问链：交了什么任务 → 等待期间是否需要接管 → 最后拿到什么 → 文件能否直接使用 → 成品里的事实是否可靠 → 手机和电脑能否协同 → 官网宣传的数据入口当前能否使用 → 下一次适合交什么任务。
- 建议篇幅：每篇正文约 2200—2800 字。
- 稿型：APPSO 公众号单品体验稿。
- 停止条件：事实需要竞品横评、当前账号未验证的功能或不存在于证据包中的用户故事才能推进时，删除该段，不补写。

## 冻结事实

### 用户实测

- 默认显示的「高级模式」，没有额外安装 Skill，没有接自定义 API，也没有追加提示词。
- 编辑部调研任务生成了 Excel、Markdown、HTML、JSON 和看板预览图等产物。
- 长任务等待感明显，执行过程中没有频繁要求人工接管。
- 微信消息能够触发桌面端开始检查文件并建立任务；现有截图只能证明任务启动和监控同步，不能证明最终整理质量。
- 自我调研网页任务先询问页面风格、内容重点和语言，随后生成可打开的 HTML 页面。
- 生成页使用了「不只是助手，而是工作流的联合创始人」「ACS·智能体协同架构」「外科手术级融合」等文案。
- QoderWork、悟空和 MuleRun 的整合线索有媒体报道；截至冻结核查，当前官方产品页未找到「ACS」和「外科手术级融合」两种说法。
- 当前免费账号的环境自检未识别到身份明确的小红书官方数据源；第三方 Skill 不等同于官网所称专业数据源。

### 官方材料复核

- 2026-08-03 复核千问办公官网：支持 PPTX、Word、Excel、HTML 等产物，并宣传 1688、小红书等专业数据源。
- 2026-08-03 复核官方帮助中心：任务可包含多轮交流、附件、执行过程和最终产物；生成文件进入 Agent 工作区，可在网盘预览、编辑或下载。
- 2026-08-03 复核官方 IM 文档：支持钉钉、飞书、Lark、微信、企业微信、Slack、WhatsApp；桌面端保留进度查看和接管能力。
- 厂商页面只证明产品主张，不能替代本次账号实测。

## 禁写边界

- 不公开 WorkBuddy、Codex 与千问办公的三方耗时、完成度或排名。
- 不写「最强」「最完整」「行业第一」等总评。
- 不把一次任务外推为长期稳定性。
- 不把官网数据源宣传写成当前免费账号已经跑通。
- 不把第三方小红书 Skill 写成阿里第一方入口。
- 不把任务启动截图写成桌面整理已经成功。
- 不用功能清单撑文章，不补造朋友、客户、商家或普通用户故事。
- 不用「不是……而是……」「不只是……更是……」、洞察揭晓、万能升华、作者舞台指令和罐装共情组织观点。

## 三条叙事路线

- A｜交付物路线：从任务结束后留下的一组文件进入，沿体验时间顺序推进。
- B｜事实接缝路线：从一张很像官网的生成网页进入，倒查它如何把真实材料和自创文案缝在一起。
- C｜手工搬运路线：用「每一步能否少一次手工搬运」检查手机、桌面、文件、网页和业务数据入口。

## 表达任务

- 开头直接呈现动作或结果，不播报行业背景。
- 每个判断落到文件、页面、入口、来源或人工复核动作。
- 结尾只回答下一次适合交什么任务，以及仍需观察什么。
- 本轮不预设金句。
