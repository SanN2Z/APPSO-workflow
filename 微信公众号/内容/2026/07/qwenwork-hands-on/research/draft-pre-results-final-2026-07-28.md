# 办公 Agent 已经够多了，千问办公为什么还要再来一个？

过去半年，办公 Agent 已经从新鲜玩意变成了一条有点拥挤的赛道。

WorkBuddy、百度搭子 DuMate 和豆包都在往桌面、本地文件与办公软件里走。读材料、做 PPT、整理 Excel，甚至从手机给电脑派任务，都不再新鲜。

千问办公来得不算早。它的官网也列着一长串熟悉的词：电脑操控、Skill、连接器、企业协作、定时任务……

但电脑里已经装过一个办公 Agent 的人，为什么还要再装一个？

只看演示，几款产品很容易长成同一个样子：用户丢下一句话，Agent 忙一阵，最后吐出一份看起来完整的报告。差距通常藏在演示结束以后——来源能否追溯，文件是否方便修改，第一次结果不合格要返工几轮，下周再跑会不会卡在登录、权限或格式上。

会做，只是第一关。能交出一份可检查、可修改、可重复使用的结果，才决定它是工作台，还是一个更会动鼠标的聊天框。

## 千问办公想证明的，不该是某一个功能

从官方资料看，千问办公的潜在差异在一条完整的交付链。

它把本地文件和浏览器接进桌面端，又准备了 1688、小红书等数据入口；任务完成后，可以生成 Word、Excel、PPT，也能做成 QwenWork Pages，再通过钉钉、飞书或微信送回聊天。

这些能力单独拆开，大多已有同类产品覆盖。千问办公需要证明的是：它能否把「找资料—整理数据—分析判断—生成文件—展示结果」接得更顺。

官网写的是定位，真实任务才能看出哪一段少了搬运，哪一段只是换了入口。

## 三款 Agent，做同一道编辑部任务

这次把同一份任务分别交给千问办公、WorkBuddy 和 Codex。

WorkBuddy 是较成熟的国产桌面办公 Agent；千问办公是这次观察的新品；Codex 则作为通用 Agent 基线。如果同样的调研和本地交付，通用 Agent 也能完成，差异就不能简单归因于「会调用工具」。

三款产品收到的任务是：

> 为编辑部选题会完成一份「国内 AI 办公 Agent 用户反馈与产品差异观察」。核查千问办公、WorkBuddy、百度搭子和豆包的官方功能与价格，收集公开用户反馈，分析高频好评、常见抱怨和适用场景，最后交付来源台账、分析稿和可离线打开的可视化网页。

这很像编辑、市场或运营经常遇到的临时工作：材料散在不同页面，最后不能只交一段回答，还得给出一套别人能继续看、继续改的成果。

## 第一轮不开 Skill，先看开箱能做到哪一步

第一轮统一使用新任务和默认或推荐模型，不安装额外 Skill，不接自定义 API，也不手动补数据源。任务开始后，除必要的高风险确认外，不再追加提示词扶着它往前走。

三款产品必须交付相同的 6 份文件。结果出来后，除了检查来源、数字和文件能否正常使用，还会记录完成时间、失败与重试、人工干预，以及把成果改到可汇报状态需要多久。

积分只做记录，不直接横向换算。不同产品对 Credits 的定义并不相同，简单比较扣了多少，很容易把模型成本和产品效率混在一起。

第一轮结束后，千问办公还会单独再跑一次。这次打开它官方提供的小红书等数据能力，其余条件不变，用来判断增量究竟来自 Agent 本身，还是阿里给它接上的数据和工具。

在结果出来之前，还不能断言千问办公更好。

目前只能先确定一件事：比较办公 Agent，不能再数谁的功能按钮更多。要比的是一份能验收的交付物，以及人为了把它用起来，还要返工多少次。
