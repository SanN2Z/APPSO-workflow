# 办公 Agent 已经够多了，千问办公为什么还要再来一个？

这半年，办公 Agent 已经从新鲜玩意变成了一条有点拥挤的赛道。

WorkBuddy 能读本地文件、做文档和 PPT，也把微信、飞书等入口接进了桌面；百度搭子 DuMate 能操作 Office、WPS 和网页里的业务系统；豆包也把任务执行带进了浏览器和办公场景。

到了这个时候，千问办公再出现，最容易写成一篇官网功能盘点：电脑操控、应用快照、Skill、连接器、企业协作、定时任务……

菜单很长，但它没有回答一个更实际的问题：电脑里已经装过一个办公 Agent 的人，为什么还要再装一个？

毕竟，「能做 PPT」「能整理 Excel」「能远程给电脑派任务」，都已经不是千问办公独有的能力。只看演示视频，几款产品甚至很容易长成同一个样子：用户丢下一句话，Agent 在屏幕上忙一阵，最后吐出一份看起来很完整的报告。

真正拉开差距的，往往是演示结束之后的部分。

资料从哪里来？关键数据能不能追溯？生成的文件是否方便继续修改？第一次结果不合格，要返工几轮？同一套流程下周再跑，还会不会卡在登录、权限或者格式上？

对办公 Agent 来说，会不会做只是第一关。能不能交出一份可检查、可修改、可重复使用的结果，才决定它最后是工作台，还是一个更会动鼠标的聊天框。

## 千问办公来得不早，它想接的是一条更完整的链路

从官方资料看，千问办公值得测试的地方，也不在某一个孤立功能。

它把本地文件和浏览器放进桌面端，又准备了 1688、小红书等数据入口；任务完成后，可以生成 Word、Excel、PPT，也能继续做成可访问的 QwenWork Pages；如果接入钉钉、飞书或微信，任务还能从聊天窗口发起，再把结果送回原处。

单独拆开看，这些能力大多已有同类产品覆盖。千问办公真正需要证明的是：它能不能把「找资料—整理数据—分析判断—生成文件—展示结果」接成一条更短的路线。

这也是它和 WorkBuddy、DuMate 等产品最值得比较的地方。

WorkBuddy 的优势更接近一个开放的桌面工作台：可选模型多，可以接入自定义 API 和本地模型，也有已经成形的技能与腾讯办公生态。DuMate 更强调 Office、WPS、本地文件和企业业务系统之间的自动化。千问办公则把阿里系数据入口、可编辑交付物、网页发布和 IM 协作摆在了一起。

这些差异写在官网上还只是产品定位。只有放进同一项工作，才能看出哪一段真的少了搬运，哪一段只是换了入口。

## 所以，这次不给它们做一道「展示题」

这次测试没有让三款 Agent 各自挑擅长的案例，而是把同一份任务分别交给千问办公、WorkBuddy 和 Codex。

其中，WorkBuddy 代表目前较成熟的国产桌面办公 Agent；千问办公是这次要观察的新品；Codex 虽然不是直接的国产办公竞品，但可以作为通用 Agent 的参照——如果同样的调研和本地交付，通用 Agent 也能完成，那么产品的价值就不能只归因于「它会调用工具」。

三款产品收到的是同一条任务：

> 为一次编辑部选题会，完成一份「国内 AI 办公 Agent 用户反馈与产品差异观察」。核查千问办公、WorkBuddy、百度搭子和豆包的官方功能与价格，收集并整理公开用户反馈，分析高频好评、常见抱怨和适用场景，最后交付一份来源台账、一篇分析稿和一个可以离线打开的可视化网页。

这道题有意把几类办公工作压在了一起：公开资料调研、来源核验、表格整理、文本分析，以及最后的可视化汇报。

它不算日常工作里最简单的一道题，却足够接近编辑、市场、运营经常面对的临时任务：材料散在不同页面，时间不多，最后不能只交一段回答，还得给出一套别人能接着看、接着改的成果。

## 第一轮不开 Skill，先看「开箱即用」

为了避免把生态能力和 Agent 本身混在一起，第一轮统一使用原生模式：新建任务、使用默认或推荐模型，不安装额外 Skill，不接自定义 API，也不额外补充数据源。

在任务开始后，也不继续用提示词扶着它往前走。除非产品要求确认高风险操作，否则不给第二轮提示，不替它修改搜索关键词，也不在半路手动补链接。

这有点苛刻，但很接近一个新用户第一次打开产品时的真实状态。

三款 Agent 还要交出相同的 6 份文件：

1. 一份可以筛选和追溯来源的 Excel 台账；
2. 一篇写清发现、证据和限制的 Markdown 分析稿；
3. 一个双击即可离线打开的 HTML 数据看板；
4. 一份记录步骤、失败和人工干预的运行日志；
5. 一份统一格式的指标文件；
6. 一张看板预览图。

规定交付格式，不是为了增加难度。恰恰相反，它可以把「看起来做完了」变成几项可以直接检查的问题：文件能不能打开，来源是不是真的存在，数字能不能对上，图表能不能读，结果离开聊天窗口后还能不能继续使用。

【配图 3｜统一交付目录示意，画面中应能看到 6 个约定文件名。若某款产品没有完成某项，保留缺失状态，不手动补齐。】

## 比的不是谁写得更像，而是谁让人少返工

结果出来后，比较不会只看网页漂不漂亮。

更重要的记录包括：总共用了多久，失败和重试了几次，需要人工确认多少次，找到了多少条有效来源，出现了多少处事实或数字错误，Excel 是否方便继续筛选，HTML 能否离线打开，以及一个编辑把它改到可汇报状态还要花多少时间。

积分也会记录，但不会直接横向换算。不同产品的 Credits 定义、模型价格和套餐权益并不相同，简单比较「谁扣得少」容易得出一个失真的结论。

第一轮之后，千问办公还会单独多跑一次。

这一次只打开它官方提供的小红书等数据能力，其余任务和交付要求保持不变。这样才能回答一个更具体的问题：千问办公的优势究竟来自 Agent 本身，还是来自阿里给它接上的数据和工具；这些入口又是否真的减少了搜索、清洗和返工。

【结果待补 1｜三款产品原生模式的完成时间、文件完整度、有效来源、错误、人工干预和返工时间。】

【结果待补 2｜三份 HTML 看板的首屏与关键图表对比；图片之间加入各自产物说明，不连续堆图。】

【结果待补 3｜千问办公原生模式与官方数据能力增强模式的消融对比。】

在结果出来之前，还不能断言千问办公更好，也不能因为它拥有更长的功能菜单，就认定它更适合办公。

目前唯一可以先确定的是：比较办公 Agent，最小单位不该再是一个功能按钮，也不是一段顺利跑完的 Demo，而是一份真正能验收的交付物，以及人类为了把它用起来，还要返工多少次。
