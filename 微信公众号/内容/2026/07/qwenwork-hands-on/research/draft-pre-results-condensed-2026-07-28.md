# 办公 Agent 已经够多了，千问办公为什么还要再来一个？

这半年，办公 Agent 已经从新鲜玩意变成了一条有点拥挤的赛道。

WorkBuddy 能读本地文件、做文档和 PPT，也把微信、飞书等入口接进了桌面；百度搭子 DuMate 能操作 Office、WPS 和网页里的业务系统；豆包也开始替用户在浏览器和办公场景里执行任务。

千问办公在这个时候出现，最容易写成一篇官网功能盘点：电脑操控、应用快照、Skill、连接器、企业协作、定时任务……

但电脑里已经装过一个办公 Agent 的人，为什么还要再装一个？

「能做 PPT」「能整理 Excel」「能远程给电脑派任务」，都不是千问办公独有的能力。几款产品的演示也很相似：用户丢下一句话，Agent 忙一阵，最后吐出一份看起来很完整的报告。

差距往往藏在演示结束以后。

资料能不能追溯？文件是否方便继续修改？第一次结果不合格，要返工几轮？同一套流程下周再跑，会不会卡在登录、权限或者格式上？

对办公 Agent 来说，会做只是第一关。能交出一份可检查、可修改、可重复使用的结果，才决定它最后是工作台，还是一个更会动鼠标的聊天框。

## 千问办公想证明的，不该是某一个按钮

从官方资料看，千问办公值得测试的地方不在单项功能，而在整条交付链。

它把本地文件和浏览器接进桌面端，又准备了 1688、小红书等数据入口；任务完成后，可以生成 Word、Excel、PPT，也能继续做成 QwenWork Pages，再通过钉钉、飞书或微信送回原来的聊天。

这些能力单独拆开，大多已有同类产品覆盖。千问办公需要证明的是：它能否把「找资料—整理数据—分析判断—生成文件—展示结果」接得更顺。

这也是它和 WorkBuddy 的差异可能出现的地方。WorkBuddy 更像一个开放的桌面工作台，可选模型多，也能接入自定义 API、本地模型和腾讯办公生态；千问办公则把阿里系数据入口、可编辑交付物、网页发布和 IM 协作摆在了一起。

写在官网上的仍然只是定位。只有放进同一项工作，才能看出哪一段真的少了搬运，哪一段只是换了入口。

## 三款 Agent，做同一道编辑部任务

这次测试把同一份任务分别交给千问办公、WorkBuddy 和 Codex。

WorkBuddy 是较成熟的国产桌面办公 Agent；千问办公是这次要观察的新品；Codex 不是直接的国产办公竞品，但可以作为通用 Agent 基线。如果同样的调研和本地交付，通用 Agent 也能完成，那么差异就不能简单归因于「会调用工具」。

任务也没有刻意迎合任何一款产品：

> 为编辑部选题会完成一份「国内 AI 办公 Agent 用户反馈与产品差异观察」。核查千问办公、WorkBuddy、百度搭子和豆包的官方功能与价格，收集公开用户反馈，分析高频好评、常见抱怨和适用场景，最后交付来源台账、分析稿和可离线打开的可视化网页。

这很像编辑、市场或运营经常遇到的临时工作：材料散在不同页面，时间不多，最后不能只交一段回答，还得给出一套别人能继续看、继续改的成果。

【配图 2｜统一任务的交付目录，画面应显示来源台账、分析稿、HTML 看板、运行日志、指标文件和看板预览图。缺失的文件保留缺失状态。】

## 第一轮不开 Skill，先看开箱能做到哪一步

第一轮统一使用新任务和默认或推荐模型，不安装额外 Skill，不接自定义 API，也不手动补数据源。任务开始后，除必要的高风险确认外，不再追加提示词扶着它往前走。

三款产品必须交付相同的 6 份文件：Excel 来源台账、Markdown 分析稿、离线 HTML 看板、运行日志、指标文件和看板预览图。

规定格式，是为了把「看起来做完了」变成几项能直接检查的问题：文件能否打开，来源是否真实，数字能否对上，图表是否可读，结果离开聊天框后还能不能继续使用。

结果出来后，还会记录完成时间、失败和重试、人工干预、有效来源、事实错误，以及把成果改到可汇报状态需要多久。积分只做记录，不直接横向换算，因为不同产品对 Credits 的定义并不相同。

第一轮结束后，千问办公还会单独再跑一次。这次打开它官方提供的小红书等数据能力，其余条件不变，用来判断增量究竟来自 Agent 本身，还是阿里给它接上的数据和工具。

【结果待补 2｜三份 HTML 看板的首屏和关键图表；图片之间加入各自产物说明。】

【结果待补 3｜千问办公原生模式与官方数据能力增强模式的消融对比。】

在结果出来之前，还不能断言千问办公更好。

目前只能先确定一件事：比较办公 Agent，不能再数谁的功能按钮更多。真正要比的是一份能验收的交付物，以及人为了把它用起来，还要返工多少次。
