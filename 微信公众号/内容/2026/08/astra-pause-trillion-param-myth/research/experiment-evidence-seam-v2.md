# 10 万亿参数回来了，一次推理到底会用掉多少？

一台写着「2.8 万亿参数」的模型，处理一个 token 时，实际激活 1040 亿参数。其余约 96%，在这一步没有参与前向计算。

这组反差已经出现在公开模型里。Kimi K3 的官方模型卡就列着这两个数字：总参数 2.8T，每个 token 激活 104B。

再看最近刷屏的「10 万亿参数」。OpenAI Astra 被传为 10T，OpenAI 尚未公布它的参数量。Financial Times 则报道称，字节跳动正在预训练一个新模型，最终规模最高可能达到 10T，目前仍处于早期阶段。

10T 很适合写进标题，却回答不了一个更贴近产品的问题：模型每处理一个 token，究竟会调用其中多少参数？

## 参数池很大，每次只走一条窄路

参数是模型在训练中学到的权重。总参数统计全部权重，激活参数统计处理一个 token 时，实际参与这次前向计算的那部分权重。token 可以简单理解为模型读写文字时处理的基本单位。

MoE，也就是混合专家模型，加入了一个路由器。一个 token 进来，路由器只选择部分专家参与计算，其余专家留在参数池里。

可以把总参数想成一座图书馆的全部藏书，激活参数是回答眼前这个问题时被取到桌上的书。藏书很多，每次不必全部摊开。这个类比只解释总量与本次调用量的差别，书的数量不能直接换算成模型智力。

OpenAI 的 gpt-oss-120b 也是一个公开例子。它有约 117B 总参数，每个 token 激活 5.1B，比例约为 4.4%。模型名里的「120b」描述了参数池，单次计算实际走过的是其中一小部分。

Kimi K3 把总量与激活量的差距带到万亿级。它共有 93 层，每个 MoE 层配置 896 个路由专家。处理一个 token 时，模型选择 16 个路由专家，另有 2 个共享专家。总参数累计了整台模型的所有层，896 说的是单个 MoE 层的专家数量，因此不能直接用 2.8T 除以 896 计算单个专家大小。

激活参数更接近每个 token 的计算规模。一次请求的速度和成本还会受到输入长度、硬件、并行方式、量化和缓存影响。没有被激活的参数也要存放，专家之间的通信、路由和负载均衡同样占用资源。

MoE 仍然要支付这些系统成本，但参数池可以扩张得更快，每个 token 的计算量不必按同样比例膨胀。

## 10T 这个纪录，五年前已经出现过

这个门槛早在五年前就被跨过了。

2021 年提交的 M6-10T 论文，已经训练出一个 10T 的 MoE 模型。团队使用 512 张 NVIDIA V100，耗时大约 10 天。模型共有 48 层，每个 MoE 层放入 10240 个专家，`d_model` 为 1024，`d_ff` 为 9984。

把它和 Kimi K3 放在一起，差别一眼就能看出来。M6-10T 有 48 层，每个 MoE 层布置 10240 个专家。Kimi K3 有 93 层，每个 MoE 层配置 896 个路由专家，并为每个 token 选择其中 16 个。两台模型都可以拥有巨大的总参数，组织这些参数的办法相差很远。

M6-10T 的论文记录了训练 loss 和 log perplexity，并把不同下游任务能否改善留作开放问题。它完成了一项很难的训练工程：用当时的硬件把 10T 稀疏模型跑通。产品表现仍要等待后续测试。

大模型行业后来没有沿着总参数榜一路冲刺。模型要进入产品，还要面对推理速度、服务价格和硬件利用率。一个漂亮的 10T 纪录，离稳定、便宜、好用的模型还有很长一段系统工程。

## 模型缩小过一轮，机房又给 10T 留了位置

Epoch AI 在 2024 年的一篇分析中估计，GPT-4 约有 1.8T 参数，GPT-4o 约为 200B，Claude 3.5 Sonnet 约为 400B。后两个数字由输出速度、API 价格和硬件经济学推算，可能存在约 2 倍误差。

这些估算描出了一段容易被参数新闻忽略的变化：前沿模型曾经缩小。参数更少，通常更容易把输出速度和服务价格压到产品可以承受的范围。基础模型的总参数不再一路上涨。

一年后，Epoch AI 的另一篇分析判断，这条路可能快要碰到边界。GPT-5 的训练算力低于上一代；如果继续增加后训练投入越来越难，GPT-6 可能需要明显高于 GPT-5、甚至超过 GPT-4.5 的训练算力。

训练算力和参数量不能直接换算。新增预算可以花在更多数据、更长训练或更大模型上。不过，硬件厂商已经在为大参数池安排位置。阿里云 7 月发布灵骏真武 M890 超节点时给出的说法是，一台超节点实例可以承载十万亿参数级 MoE 大模型推理。

训练预算如果重新上涨，MoE 可以把新增容量分散到更多专家，推理时仍只调用一部分。模型权重要占用存储，专家通信也会带来压力。M890 的发布显示，硬件供应商已经开始为十万亿级 MoE 准备承载空间。

## 参数榜该多写一列

总参数没有过时。它关系到模型装下多少权重、训练需要多少资源、部署时要准备多大存储。更多容量经过有效训练，也可能带来能力提升。

但对 MoE 模型来说，总参数只是参数表里的第一列。旁边至少还要写出每个 token 激活多少参数。gpt-oss-120b 是约 117B 对 5.1B，Kimi K3 是 2.8T 对 104B。两个数字并排，读者才知道这台模型的参数池有多大，以及一次计算大致会动用多少。

再往后，公开评测会显示这些容量换来了什么。速度和价格决定它能不能成为日常产品。层数、模型宽度、专家组织与路由方式藏在数字下面，训练质量最终把它们变成能力差异。

等 Astra 或字节的新模型真正公开时，10T 仍会是最醒目的那一行。先找每个 token 的激活参数，再看公开评测、速度和价格。如果页面上只有总参数，我们知道的仍只是这台模型存下了多少权重。
