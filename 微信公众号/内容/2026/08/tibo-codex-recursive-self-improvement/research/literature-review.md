# RSI 文献综述与证据边界

## 检索结论

近三年的变化不是某篇论文突然实现了「递归自我改进」，而是过去分散的几条路线开始汇合：LLM 能写代码，Agent 能运行实验，训练流程能接受合成数据与模型评分，基础设施又提供了快速、自动、可量化的反馈。循环因此从「模型在一轮回答里检查自己」逐渐向「系统修改包围自己的工具与训练流程」外扩。

尚没有公开证据证明一个系统已经同时具备以下四点：自主选择值得研究的问题；设计并训练通用能力更强的继任者；可靠判断继任者确实更强且没有通过指标投机；连续重复该过程并让人类介入持续下降。现有成果位于这四点的不同子集。

## 跨文献综合

### 1. 自改对象正在外扩

最早可执行的系统通常只改提示词或一段代码。随后，自改对象扩展到 Agent 工作流、训练数据、奖励模型、评测器和后训练流程。Tibo 的说法再把推理内核、负载均衡、产品界面与云端 Agent 纳入同一个系统边界。不同路线都在谈「自己」，但「自己」指向的实体并不相同。

### 2. 外部可验证性决定进展速度

代码能否通过测试、内核是否更快、模型 loss 是否下降，都能较快获得机器反馈，所以编码、系统优化和封闭数学任务率先出现循环。研究方向是否重要、实验结论是否可泛化、安全性是否退化，则很难被单一指标完整表达。越接近开放科学研究，评测器越容易成为瓶颈。

### 3. 当前最像 RSI 的不是一只孤立模型，而是一套生产系统

OpenAI 的 Sol 案例、AlphaEvolve 与 Anthropic 的自动研究都包含模型、工具、沙盒、评测器、计算集群和人类工程师。把镜头只对准模型权重，会看不到真实反馈正在发生；把整个组织都叫作「AI 自己」，又会掩盖人类仍在定目标、造评测与批准上线。正文因此采用系统图景，同时逐层标注人类接口。

### 4. 「递归」不保证「加速」

循环可以变慢、过拟合或走偏。RE-Bench 的时间预算结果说明短时试错优势不自动转化为长程研究优势；无外部反馈的自我纠错和递归生成数据则说明错误也能被放大。真正值得追踪的是每一轮改进能否扩大下一轮的有效研究吞吐，而不是系统有没有调用自己一次。

## 写作采用的判断框架

对任一「AI 已经开始自我改进」的新闻，依次追问：

1. 它改的是一次回答、Agent 代码、训练数据、权重，还是整套研发基础设施？
2. 目标由谁选择，成功标准由谁定义？
3. 评测能否被投机，结果是否经过独立复现或生产验证？
4. 这次改进是否让下一轮改进更快、更便宜或更可靠？
5. 循环能否持续多轮，并让人类介入真正下降？

只有越往后仍能给出肯定答案，才越接近严格意义上的 RSI。
