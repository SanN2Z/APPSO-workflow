## 因果复盘

```text
抽象概念被排成「四层阶梯」
→ 读者把不同维度误认成同一条进度条，并把 AI 参与研发等同严格 RSI
→ 修改对象、持久性、循环次数和人类介入程度被压进一条轴；案例又没有统一判据
→ 改用「四类改进对象 × 闭环强度」，先设三道递归门，再用 4 个案例回答同一组问题
→ 独立审稿 Agent 在未参与写作的条件下提出问题；修订后按原通过条件复验，CR-01—CR-09 全部 pass
→ 适用于边界模糊、同一术语覆盖多类系统的科技科普；若领域本身已有公认单轴成熟度模型，不必机械改成二维框架
```

```text
配图数量与技术检查全部达标，用户仍整体否决视觉
→ 文章充满通用 3D 图和深色科技卡片，既不像 APPSO，也把网上原图的真实语境抹掉
→ 上游把公司稿误标为 `generic`；随后以「统一风格」替代三类视觉路由；信息图没有把已登记 Prompt 与 Logo 送进 Image2
→ 固定为 `source_original`／`clumsy_doodle`／`infographic` 三条路线，逐图先分类；每篇至少两类；APPSO 信息图绑定完整规范、Logo、计划、receipt 与 manifest
→ manifest v3 与 validator 负责结构硬门；原尺寸、手机宽度和用户视觉验收继续负责语义与审美，不能再拿 `warnings=0` 代替
→ 适用于本仓库新建或实质改图的微信公众号文章；X 单帖和研究中间图不执行至少两类
```
