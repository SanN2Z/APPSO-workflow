## 因果复盘

```text
事实限制句跟着每一组资料出现
→ 读者每前进一步都要先读编辑自证，新闻节奏被打断
→ 把内部 claim 分类误当成公开文章必须逐条展示的结构
→ 内部保留完整事实映射，正文只在样本规模、数据条款等会改变使用决定的位置写边界
→ `sources.md` 可逐段回映，公开稿冷读仍能复述主线
→ 适用于这类已完成内部核查的事实快讯；医疗、法律、金融等高风险建议仍需在读者可见处写必要限制
```

```text
资料截图、AI 图和自制信息图没有明确分工
→ 要么整篇像截图堆砌，要么只剩概念插画，读者看不出哪些是事件现场、哪些是编辑解释
→ 视觉阶段只按「有没有图」思考，没有先按证据、解释和气氛分配职责
→ 官方／社区截图承担公开现场，自查页承担本文独有材料，数论信息图承担精确边界，笨拙涂鸦承担自我调查的反差
→ 7 张正文图均有独立信息任务，去掉任一图仍不破坏文字事实链
→ 与 `amazon-ai-old-books` 的混合视觉反馈形成第二个相似案例，先继续观察，不立即推广为通用规则
```

```text
用普通公众号 API 的过滤规则判断公司纵向滑动素材
→ 过早得出「无法嵌入」结论，忽略公司已有的浏览器转换器和编辑器 DOM 通道
→ 没有先区分密封草稿发布、浏览器复制粘贴与编辑器注入三种交付合同
→ 回到公司浏览器排版 SOP，并直接核对公开转换器的 `image-carousel-vertical` 输出
→ 还原出固定 300 px 高、内层 `overflow-y:auto`、最多 9 张图片的真实结构；本稿生成 3 张连续切片和独立预览
→ 用户明确要求把本地工具固定到 SOP；推广为 `PROJECT-WECHAT-VERTICAL-SCROLL-HANDOFF-001`，公司浏览器 SOP 只保留降级指针
```

```text
本地页面能滚动，但图片仍引用磁盘路径
→ 视觉预览成立，公众号富文本交付不成立
→ 把「浏览器里看见效果」误当成「剪贴板载荷自包含」
→ 使用仓库统一 `scroll-handoff` 命令，将已登记 PNG 通过内容状态、权利、平台与资源门禁后编码为 Base64，并写入 `text/html` 剪贴板
→ 版本化离线单文件包含 3 张图、复制按钮与构建回执；定向回归通过
→ 规则进入公众号发布 SOP；粘贴后的公众号手机预览仍是最终验收点
```

## 经验分级

### 仅保留在本案例

- 「牛照镜子」与空白工牌只服务 Ox Alpha 的命名和自我调查反差。
- 数论题第 32／33 对边界是本稿的自有案例，不迁移为模型综合能力测试模板。
- 本任务的图片使用确认只覆盖本稿与 WeChat，不构成其他内容包的通用转载许可。
- 爱范儿转换器的实现核对只用于恢复本稿交付路径；未经实机草稿验证，不把当前公开前端结构写成永久平台保证。

### 继续观察

- 已完成内部事实映射的 APPSO 快讯，可否默认把大多数事实边界留在 `sources.md`，公开正文只保留会改变读者行动的限制。
- 事件型公司稿是否适合稳定采用「公开截图提供来源触感 + 自制信息图解释数字 + AI 图承担气氛」的混合视觉分工。

### SOP 候选

- 暂无。本轮不修改通用 SOP 或 APPSO adapter。
