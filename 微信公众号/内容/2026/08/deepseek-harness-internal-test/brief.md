# Brief

## 当前决定

- 选题：从 DeepSeek Harness 定向内测的一句 Fable 5 玩笑，追问 AI 能现搭项目后，为什么报名仍要求 GitHub ID 与已经做过的开源代表作。
- 任务类型：用户确认大纲后的结构重写。
- 稿型：热点吃瓜 + 克制分析。
- 写作模式：personal。
- 目标读者：关心 AI 热点，但不熟悉 Agent 工程的中文读者。
- 唯一读者问题：AI 都能在一小时里现搭项目了，为什么 DeepSeek 还盯着慢慢做出来的旧作品？
- 唯一核心判断：AI 可以缩短项目从空白到能跑的时间，却不能现场生成真实项目积累下来的失败、修复与取舍。DeepSeek 这张定向内测门票最有意思之处，是它重新显出了这种慢经验的价值。
- 读者带走：以后看作品与履历，代码量会越来越不够说明问题；项目遇到过什么、为什么这样修、怎样证明修好，更能显示判断力。

## 事实与判断

已核事实：

- 用户提供的公开 X 截图显示，LinearUncle 转发 Tianyi Cui 的招募帖，并开玩笑称准备让 Fable 5 花一小时现场搭一个。
- DeepSeek Harness 团队成员 Tianyi Cui 定向邀请 Agent Harness 相关开源项目开发者参加内测，要求提交 GitHub ID 与开源代表作，可回复或私信联系。
- DeepSeek-V4-Flash-0731 官方模型卡写明，公开 Code Agent 任务使用待发布的 DeepSeek Harness minimal mode。
- 模型卡结果是厂商自报，不能把成绩归因于 Harness。

作者判断：

- GitHub ID 与开源代表作可以提供可检查的失败、修复与取舍记录。
- 做过同类开源项目的开发者更可能给出可复现、可继续修正的反馈，因此适合承担「专业拆台」角色。

替代解释与未知：

- DeepSeek 没有公开说明筛选动机；高质量 bug、兼容性测试、发现人才等解释都可能成立。
- 产品形态、正式发布日期、价格、是否开源和测试协议未知。

## 写作边界

- Harness 最多用一个普通人段落解释为「AI 干活时使用的工作台」。
- 不展开权限、上下文压缩、重试、工作目录和验收技术链。
- 不写成跑分分析、Harness 百科或开源项目清单。
- 不升华成 Agent 战争、时代转折、生态战略或模型供应商转型。
- 事实限定只写到会改变读者理解的程度，不让事实边界生成章节。
- 目标正文 1600—2200 个中文字符；能短说清就不补篇幅。
