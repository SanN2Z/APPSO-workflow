# DeepSeek Harness 开内测，Fable 5 现搭一个还来得及吗？

## 点开报名条件，我的仓库名白想了

我看到 LinearUncle 那条转发时，第一反应不是分析，是笑。

Tianyi Cui 在 X 上为 DeepSeek Harness 招募定向内测，LinearUncle 顺手开了个玩笑：准备让 Fable 5 花一个小时现场搭一个。我脑子跟得比模型还快，已经替这个不存在的仓库想起了名字，连 README 上那句「built in one hour」都安排好了。

毕竟现在让 AI 在一小时里攒出一个能跑的项目，听上去真不离谱。页面搭起来，命令跑起来，演示录下来，报名材料这不就有了？

![LinearUncle 转发招募帖并拿 Fable 5 开玩笑](assets/x-linearuncle-fable5-joke.png)

然后我点开原帖，笑容停在了加载完成的那一秒。

招募对象指向 Agent Harness 相关开源项目的开发者，报名要交 GitHub ID，还要附已经做过的开源代表作，可以回复或私信联系。GitHub ID 我有，刚出生 60 分钟的仓库也可以有；但「代表作」三个字，像是给临时作业加了一道安检门。

项目名白想了。

## 这套 Harness 还没发布，已经先替 V4 跑过分

我不死心，又顺着线索往回翻，想看看这东西到底走到了哪一步。结果在 DeepSeek-V4-Flash-0731 的官方模型卡里，翻出了另一个有点反常的顺序：公开 Code Agent 任务使用的，正是待发布的 DeepSeek Harness minimal mode。

对外界来说，它的产品形态、正式发布日期、价格、是否开源和测试协议都还不知道；在 DeepSeek 的评测流程里，它却已经上过工位了。幕布还没拉开，后台机器先转了起来，现在团队又开始找人进去晃桌子。

把模型想成坐在电脑前干活的人，Harness 就是它手边那张工作台：把文件、终端、任务进度和结果检查接起来，让模型给出的代码变成一连串真正执行过的动作。我这次倒回模型卡，已经顾不上看 V4 又高了多少分，只想确认它当时坐在哪张桌子前。

![DeepSeek Harness 公开信号时间线](assets/timeline-harness-public-signals.png)

这里得踩一脚刹车。模型卡里的结果是 DeepSeek 自报，也没有给出足够依据，让人把成绩归功于 Harness。现在能确认的只有使用关系，不能顺手补上一条因果关系。

## 一个小时能搭出 Demo，搭不出「踩坑史」

我把招募条件和模型卡并排放着看，那个让人泄气的「代表作」反而变得合理了一点：一小时项目能证明模型此刻造得有多快，旧项目留下的东西，却能说明第一次跑通以后发生过什么。

![模型、Harness 与真实任务之间的工作关系](assets/harness-system-stack.png)

假设 Fable 5 现场搭好一个代码助手，示例仓库里一路绿灯。换到一个维护了几年的旧项目，它碰上一处只在老环境里出现的错误；修掉以后，另一个功能又坏了。开发者只好回退、找原因、补测试，再解释为什么最终保留这版改法。一个小时能生成一份修复，却生成不了这段失败、追问与验证。

这些经历平时散在 Issue、提交记录、测试和讨论里。代码本身当然重要，但真正让一个旧项目成为「代表作」的，往往还有它如何撞墙、如何改道，以及作者拿什么证明这次没有修出新的坑。

DeepSeek 没说会不会逐项查看这些痕迹。我更愿意把 GitHub ID 和开源代表作理解成一种可检查的经验入口：新仓库能展示生成速度，长期项目才有机会展示人在真实约束里做过的取舍。

AI 把「从空白到能跑」压得越来越短，也让后半段的证据显得更贵了。

## DeepSeek 找来的，可能是一群专业拆台的人

我再把招募对象代进内测现场，画面就更具体了。维护过开源项目的人拿到新工具，通常不会满足于看一次顺利演示。他们会换个仓库、换种用法，盯住那个「怎么又卡了」的瞬间，再想办法把偶发怪事整理成别人可以复现的问题。

说得好听，这是测试经验；说得直白一点，这群人很适合专业拆台。

![开源开发者把新工具放进真实项目里测试](assets/doodle-open-source-builders-test.png)

这种拆台的目标很实际：尽早找到演示里碰不到的边角。一个真实维护过项目的人，既知道哪里容易出错，也更可能说清楚错在什么条件下、改完该怎样验收。内测要的应该是一批能继续往下修的反馈，单留一句「看起来不错」没多少用。

当然，这仍然是我的判断。DeepSeek 没有公开说明筛选动机；想收集高质量 bug、做兼容性测试，或者顺便发现合适的人才，都可能成立。我们现在还不能替团队把答案选死。

所以，Fable 5 现搭一个还来得及吗？代码来得及，经历来不及。现搭的 Demo 依然能说明 AI 有多快，可这张内测门票追问的是另一样东西：你以前遇到过什么，为什么那样修，修完又如何证明结果可靠。

仓库名可以一小时现想，代码也会越来越快；踩坑史只能慢慢长，经历没有快进键。
