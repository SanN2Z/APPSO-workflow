# Round 02 frozen input

## 唯一读者问题

AI 都能在一小时里现搭一个项目了，为什么 DeepSeek Harness 的内测仍要求 GitHub ID 和已经做过的开源代表作？

## 唯一核心判断

AI 可以快速生成一个能跑的项目，但无法现场生成真实项目积累下来的失败、修复与取舍。DeepSeek 这张定向内测门票最有意思之处，是它把这种慢慢长出来的经验重新变成了筛选条件。

这是作者判断。DeepSeek 没有公开说明筛选动机；高质量 bug、兼容性测试、发现人才等都可能成立。

## 固定标题

DeepSeek Harness 开内测，Fable 5 现搭一个还来得及吗？

## 固定小标题

1. 点开报名条件，我的仓库名白想了
2. 这套 Harness 还没发布，已经先替 V4 跑过分
3. 一个小时能搭出 Demo，搭不出「踩坑史」
4. DeepSeek 找来的，可能是一群专业拆台的人

## 固定故事路径

LinearUncle 的 Fable 5 玩笑与作者反应
→ 点开原帖，看见 GitHub ID 与开源代表作门槛
→ 倒回模型卡，发现待发布 Harness 已用于 V4 Code Agent 评测
→ 回答为什么一小时 Demo 代替不了旧项目
→ 分析开源开发者为什么适合挑问题
→ 回答标题，并落到「代码变快，经历不能快进」

## 可用事实

- 用户提供的公开 X 截图显示，LinearUncle 转发 Tianyi Cui 的招募帖，并开玩笑称准备让 Fable 5 花一小时现场搭一个。
- DeepSeek Harness 团队成员 Tianyi Cui 定向邀请 Agent Harness 相关开源项目开发者参加内测，要求提交 GitHub ID 与开源代表作，可回复或私信联系。
- DeepSeek-V4-Flash-0731 官方模型卡写明，公开 Code Agent 任务使用待发布的 DeepSeek Harness minimal mode。
- 模型卡结果是厂商自报。正文不展开跑分比较，也不把成绩归因于 Harness。
- 产品形态、正式发布日期、价格、是否开源、测试协议和筛选动机仍未知。

## Harness 的解释上限

正文最多用一个普通人段落解释 Harness：它是模型干活时使用的工作台，把文件、终端、任务进度和结果检查接起来。不得拆成上下文、权限、重试、工作目录、验收等技术清单。

最多允许一个 3—4 句的假设翻车例子，作用只是让读者理解「跑通 Demo」与「经历真实任务」的差别。不得恢复上一版的长故障链。

## 读者带走什么

开发者与普通 AI 用户都能理解：当 AI 让代码骨架越来越容易生成，旧项目的价值会更多体现在它遇到过什么问题、为什么这样修，以及修完后能不能证明结果可靠。

不要升华成 Agent 战争、时代转折、生态战略或模型供应商转型。
