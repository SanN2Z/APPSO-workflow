# DeepSeek Harness 开内测，Fable 5 现搭一个还来得及吗？

## 1. 点开报名条件，我的仓库名白想了

AI 圈最近有个很懂大家心理的玩笑。

DeepSeek Harness 团队成员 Tianyi Cui 发帖，定向邀请做过 Agent Harness 相关开源项目的开发者参加内测。LinearUncle 转发后说，准备让 Fable 5 花一个小时，现场搭一个出来。

![LinearUncle 转发招募帖并拿 Fable 5 开玩笑](assets/x-linearuncle-fable5-joke.png)

这思路太顺了：既然 AI 写代码越来越快，开源代表作也可以临报名再做。仓库名先起得像模像样，README 写漂亮一点，Demo 跑起来，门票不就有了吗？

我甚至已经替这个临时项目想了几个名字。再点开原帖，仓库名白想了。

招募要求提交 GitHub ID 和开源代表作，可回复或私信联系。前者不只是一串用户名，点进去还连着提交记录、Issue、修复和协作痕迹；后者也不是刚刚新建的空仓库。AI 确实能在一小时内搭出一个项目，但很难顺手补出一段真的发生过的项目经历。

这张门票查的，似乎不只是「你会不会做」，还在看「你以前到底做过什么」。

## 2. 这套 Harness 还没发布，已经先替 V4 跑过分

顺着招募帖往回查，我又翻到 DeepSeek-V4-Flash-0731 的官方模型卡，事情忽然多了一层意思：公开的 Code Agent 任务，已经使用了尚未发布的 DeepSeek Harness minimal mode。

对普通用户来说，可以把 Harness 理解成模型干活时用的工作台。它把文件、终端、任务进度和结果检查接起来，让模型不只是在聊天框里给代码建议，而是能围着一个任务真正动手。至于 DeepSeek 这套工作台具体长什么样，目前还没人能从公开信息里拼出全貌。

![Harness 在模型与真实任务之间充当工作台](assets/harness-system-stack.png)

于是出现了一个挺反常的顺序：产品形态、正式发布日期、价格、是否开源和测试协议都还未知，它却已经先出现在 V4 的公开评测里；现在，团队又开始找一批有开源项目经历的人内测。

![DeepSeek Harness 已公开出现的信号时间线](assets/timeline-harness-public-signals.png)

这里要压住脑补。模型卡里的结果是厂商自报，只能确认测试用过这套 Harness，不能据此把成绩归功于它。DeepSeek 也没有公开解释筛人的动机。能确定的只有：在东西正式露面前，团队想让做过真实项目的人先来试。

## 3. 一个小时能搭出 Demo，搭不出「踩坑史」

为什么不直接收一批刚做好的 Demo？因为「能跑一次」和「被真实任务折腾过」之间，隔着一段没法压缩的时间。

假设一个新项目今天演示顺利，明天换台电脑就报错，作者才发现自己默认了某个本地配置。修好后，旧功能又坏了，于是他补上一条测试，免得同样的问题再回来。Demo 展示的是结果；这些失败、修复和防复发的记录，才说明作者是否知道结果为什么可靠。

AI 可以帮人更快写出骨架、补齐代码，甚至当场把报错修掉。可它不能替一个项目经历真实用户、奇怪环境和长期维护，也不能替作者预先拥有那些当时做过的取舍。

这对不写代码的人也不陌生。以后再看一个人的作品或履历，「做过某项目」这句话可能越来越容易生成，真正拉开差距的，是继续往下问：哪里翻过车，为什么这样改，改完拿什么证明没把别处弄坏？回答里露出来的，才是判断力。

所以旧项目没有因为 AI 能现搭新项目就失去价值。它的价值正从「有多少代码」，移向「留下多少可信的决策痕迹」。

## 4. DeepSeek 找来的，可能是一群专业拆台的人

开源开发者特别适合干一件事：对着一个看似顺利的系统，迅速找到最不顺利的用法。

他们维护过别人真的会安装、修改和催更的东西，见过依赖变化、环境差异和模糊需求把漂亮 Demo 拧成麻花。面对一套新 Harness，他们更可能追问文件有没有改对、任务是不是表面完成、结果能不能复现，而不是看到终端亮起绿字就收工。

![开源开发者带着真实项目经验测试 Harness](assets/doodle-open-source-builders-test.png)

我更愿意把这次定向邀请理解成：DeepSeek 不只需要会把项目搭起来的人，也需要知道项目通常会从哪里坏掉的人。当然，这仍是判断，不是官方结论。团队可能想收高质量 bug、测兼容性，也可能顺便发现合适的人；公开信息还不足以替它选定唯一答案。

那么，Fable 5 现搭一个还来得及吗？搭出一个能跑的项目，也许来得及；搭出一个被真实需求折腾过、还能说清每次取舍的项目，来不及。

代码可以变快，经历不能快进。
