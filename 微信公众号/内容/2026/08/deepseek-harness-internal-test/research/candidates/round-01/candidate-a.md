# 一小时搭出一个 Agent，为什么还换不来 DeepSeek 的内测门票？

看到 DeepSeek Harness 招募内测者，我的第一反应也是：「我也想现场搭一个。」截图里，LinearUncle 已经把这念头说成玩笑：准备让 Fable 5 花一小时写一个再来。可邀请的门槛紧跟在后面——只面向做过 Agent Harness 相关开源项目的开发者，联系时还要附 GitHub ID 和开源代表作。

这道门槛把问题从「现在能不能生成一个」换成了「以前究竟撞过什么」。一套新仓库可以展示作者想让 Agent 怎样工作；一套经过真实任务折腾的旧项目，才可能留下它没有按设想工作的证据。两者都能运行，拿给测试团队看的信息量却不一样。

我更愿意把这里的「代表作」理解成一份压缩过的工程履历。稀缺的不是提交次数，也不是首页上功能模块的数量，而是代码被现实反驳以后，开发者留下了什么。

## 真正稀缺的，是错误发生过以后

模型给出下一步，Harness 要把上下文、记忆和工具递到它手上，还会碰到权限、重试与结果验收。于是，一个页面顺利跑通，只能证明理想路径存在。任务一长，麻烦才会从接缝里冒出来：上下文漏掉旧约束，工具返回成功却没有产出完整结果，权限拦截后 Agent 仍继续规划，重试把一次副作用执行两遍，最后一句「已完成」也可能没有经过真正的验收。

这些不是 DeepSeek 已公开的测试题，而是我对 Harness 项目为什么需要失败史的解释。做过这类项目的人，往往不只见过报错，还被迫回答下一层问题：错在模型判断、上下文组织、工具接口、执行权限，还是验收条件？要不要重试，重试会不会制造新风险？修好一个案例后，怎样防止它在下一版悄悄回来？

所以，失败史也不是贴几张红色日志截图。真正有说服力的记录，会连起触发条件、运行轨迹、归因、修复和回归测试。它还应该保留取舍：为了少丢上下文而增加了多少成本；为了自动恢复而引入了什么重复执行风险；为了安全收紧权限后，又牺牲了哪些任务能力。代码可以重新生成，经历过这些反驳并作出选择的过程，很难靠一张刚上线的首页替代。

这也是此次邀请值得细看的地方。前一天，DeepSeek-V4-Flash-0731 官方模型卡已经写明，公开基准中的 Code Agent 任务使用待发布的 DeepSeek Harness minimal mode，并披露了 max reasoning effort、temperature 1.0 和 top_p 0.95。它只说明 Harness 进入了厂商自报结果所用的评测配置，不能当作独立复现，也不代表产品已经发布或开源。

第二天，DeepSeek Harness 团队成员 Tianyi Cui 又把邀请发给有开源代表作的同类开发者。把两条信息放在一起，我的判断是：筛选者可能在寻找能提交高信息量故障报告的人，而不只是给出「好用」或「不好用」的体验结论。它也可能兼有架构比较或人才发现的考虑；公开信息没有给出测试协议，无法确认确切动机。

## 代表作应该让别人看到什么

如果你也在展示一个 Agent 项目，演示视频和可运行首页可以做入口，证据主体最好换成一个完整单元：「任务—失败—归因—取舍—验收」。

先给出一项可复现的真实任务和环境约束，再保留经过必要脱敏的关键轨迹。不要只写「模型不稳定」，要标出故障发生在哪一层，以及你凭什么这样判断。接着链接到对应的 issue、提交或测试，说明改了什么，也说明这次修复付出了什么代价。最后重新跑旧案例，并给出机器可查或人工可核的验收条件，证明「完成」不是 Agent 自己宣布的。

代表作不需要塞进所有日志。挑两三个不同层次的案例，往往比列十项功能更有判断价值：一个展示上下文怎样丢失，一个展示工具失败后怎样恢复，再用一个展示错误的完成信号怎样被验收规则拦住。读者看到的就不再是一张功能菜单，而是开发者识别问题、约束系统和承担取舍的方式。

如果项目刚刚生成，也不必伪造一段久经考验的历史。可以主动设计压力情境：让工具超时、让权限被拒、在任务中途打断、故意制造「输出存在但任务未完成」的假阳性。把它们明确标成构造测试，公开当前还没覆盖的边界。这样仍不能替代真实任务积累，却比假装项目已经成熟更诚实，也更方便后来的人复现。

## 一小时到底够做什么

一个小时或许足够得到仓库骨架、可运行主路径、最小的轨迹记录，以及第一组构造出来的失败案例。它得不到反复执行长任务后积累的边角故障，也得不到多轮修复留下的取舍，更不能自动变成一份被回归测试证明过的恢复能力。

因此，如果你已经有旧项目，申请或展示时别只截最新首页：把最有代表性的失败案例、修复提交和验收结果连起来。如果你只有刚搭出的新项目，就准确写出它跑通了什么、还没有经历什么，并附上下一步要撞的压力情境。

一小时当然有用。它适合把系统搭到可以被检验，也适合让第一次失败清楚地发生；它不够替你制造一段旧项目才会留下的失败史。DeepSeek 这张门票真正稀缺的部分，或许就在那段历史里。
