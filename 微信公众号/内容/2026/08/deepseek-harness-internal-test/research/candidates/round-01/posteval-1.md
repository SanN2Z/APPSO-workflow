# 选稿后独立盲评 1

- 选择：X
- 信心：中

## 判定理由

### 公共价值

X 不只给出「一小时原型不能替代长期经验」这个结论，还用「开发时钟／运行时钟」区分两类时间，并用一条权限拒绝、上下文压缩、重试、工作目录变化与验收误判相互叠加的故障链，说明为什么单个正常动作会组合出「假完成」。读者因此得到一个可迁移的判断工具：评估 Agent Harness 时，不能只看首次跑通，还要看轨迹、恢复与验收是否经受过连续任务。这比单纯讨论谁能拿到内测资格更有公共价值。

Y 的「失败史是一份压缩过的工程履历」也有价值，尤其是「任务—失败—归因—取舍—验收」这一展示单元，对准备开源代表作的人很实用。但它把邀请门槛进一步解释为筛选高信息量故障报告者，文章的大部分实用建议都建立在这个尚未证实的筛选逻辑上；即使有明确降格，核心用途仍比 X 更依赖该推断成立。

### 段落必要顺序

X 的主干顺序基本不可互换：先建立两只钟，再限定首次跑通能证明什么，随后用故障链展示运行时风险如何累积，最后才推出应记录哪些轨迹以及一小时工作的合理止点。尤其是假想故障链不是装饰性案例，它承担了从抽象判断到可验证机制的关键过桥作用。模型卡段落略微打断机制展开，但负责把通用讨论重新钉回 DeepSeek Harness，仍有必要。

Y 先断言旧项目留下的信息量更大，再展开一般性的失败类型，之后才补模型卡与邀请这两项公开材料，事实底座出现得偏晚。「代表作应该让别人看到什么」一节中的多组清单可适度删减而不改变主结论，说明部分段落承担的是扩写与应用，而非论证不可缺少的一环。

### 材料取舍

X 选择一条完整故障链，而不是平铺很多 Agent 风险名词；权限、重试、上下文与验收四类材料彼此产生后果，能具体证明「长尾来自组合」。它又把一小时能做的事收束到原型、观测点和构造测试，没有把一次演示贬成无价值，也没有把开源经历神化成资历年限。

Y 对申请材料的建议更直接，但从失败类型、证据链、案例选择到压力情境连续列举，存在可压缩的同义推进。相比之下，X 用较少的材料完成了「为什么会坏—需要留下什么—一小时能做到哪里」的闭环。

### 事实与推断纪律

两篇都正确限制了模型卡能证明的范围，也都没有把招募动机写成已知事实。X 还在进入案例时写明「想象一个具体任务」，随后再次声明这是假想故障链、并非 DeepSeek 已披露架构；正文与 FACT MAP 的分类一致。Y 也明确把「失败史价值」和招募动机列为作者判断，但正文的「前一天／第二天」是精确时序事实，其 FACT MAP 没有提供对应日期支撑，纪律略弱一档。

## 重大事实阻断项

- X：没有发现会推翻核心论证的重大事实阻断项。LinearUncle 的玩笑未定位到稳定原帖，只能维持为「用户提供截图中的转述」，不能升级成已核原话。正文中的「随后出现」仍需在发布前核对两项材料的真实发布时间。
- Y：「前一天／第二天」构成精确的一日时序，但 FACT MAP 未记录日期，发布前必须核实；若无法核实，应改成不带日距的并列关系。LinearUncle 的玩笑同样只能按截图转述处理。
