# 选稿后独立盲评 2

- 选择：文本 X
- 信心：中

## 可见正文盲评

### 具体公共价值

文本 X 给出的核心增量，是把「生成速度」与「可靠性证据的积累速度」拆成两只钟：一小时原型能够建立可执行假设，却不能替代长任务中故障出现、复现、修正和回归验证所需的运行时间。它随后把这个判断落实为读者可执行的后果——先埋轨迹记录点、记录权限与重试原因、展示实际验收项，并主动做一次故障注入。即使读者不申请此次内测，这套区分也能帮助其判断一个 Agent 项目究竟证明了什么。

文本 Y 的「任务—失败—归因—取舍—验收」证据单元同样有直接用途，尤其适合准备申请材料或展示项目的人。但它的公共价值更依赖一个尚未被公开信息证实的解释：筛选者重视代表作，可能是为了寻找有失败史、能提交高信息量报告的人。正文虽对这一点作了限定，后半篇仍主要围绕这个解释提供申请与展示建议，适用面比文本 X 的可靠性判断略窄。

### 段落的必要顺序

文本 X 的主链条是：内测门槛提出问题 → 两只钟建立判断 → 第一次跑通为何不足 → 一条组合故障如何制造「假完成」 → 应保留哪些轨迹、怎样复现与回归 → 一小时内外各自能得到什么。权限、上下文压缩、重试、工作目录变化和验收失真并非并列举例，而是前一步改变后一步条件，读者必须按此顺序读，才能理解「单个部件正常也会组合出失败」。结尾因此是在收束已证明的边界，而非重新喊一次观点。模型卡段落略有插入感，但承担了把文章重新锚回 DeepSeek Harness 的作用。

文本 Y 的顺序大体是：门槛 → 失败史的价值 → 两条公开信息 → 代表作展示方法 → 一小时边界。问题在于，它先用多段建立「失败史稀缺」的判断，之后才补模型卡与邀请之间的关系；论据到得偏晚。中间若删去一到两段对「真实失败史不可替代」的重复说明，核心结论和后文操作清单仍然成立。文章还在「解释这次邀请」与「教读者包装代表作」之间切换，后半段虽实用，却不是前面每一层材料都必然导出的唯一去向。

### 材料取舍

文本 X 选择了一条完整的假想故障链，而不是罗列常见问题。这段材料让读者看到权限拦截、摘要丢约束、带副作用的重试、测试范围缩小和只看退出码验收如何相互放大，直接证明「运行时间暴露组合长尾」这一主张。随后关于轨迹、复现、回归和故障注入的材料都在回答同一故障链留下的问题，取舍集中。

文本 Y 选择了更宽的故障类别和更完整的项目展示清单，行动建议较丰富；代价是上下文丢失、工具失败、权限、重试和假完成主要以列表出现，未充分展示它们为何会联动。三类代表案例、构造压力情境、申请材料组织等建议都各自有用，但共同分走了篇幅，使「为何一小时换不来门票」的因果证明不如文本 X 扎实。

### 事实与推断纪律

文本 X 明确把故障链标为假想案例，不冒充 DeepSeek 已披露架构；也把官方模型卡严格限制为「Harness 参与厂商评测配置」，没有据此声称 Harness 的独立贡献、产品形态或测试协议。对内测方可能寻找 bug、比较架构或发现人才，也只列为可能性。关键事实、作者判断和未知项边界清楚。

文本 Y 同样明确区分厂商自报、作者对筛选动机的判断、构造测试与真实失败史；它在截图来源的表述上甚至比文本 X 更明确。不过，正文使用了「前一天」和「第二天」来建立模型卡与邀请的精确时序，而 FACT MAP 没有登记两件事的发布日期或这一相对时间关系。这使一条承担推断桥梁的事实暂时无证据对应。

## FACT MAP 复核结论

两份 FACT MAP 都覆盖了邀请对象与申请材料、LinearUncle 的玩笑、模型卡中的 Harness minimal mode 及参数，并把筛选动机、故障史价值和一小时原型边界归入作者判断。复核后不改变对文本 X 的选择。文本 X 的主要推断都在正文中显式降格；文本 Y 的整体纪律也合格，但精确时序漏记使其在本轮比较中落后。

## 重大事实阻断项

- 文本 Y：「前一天／第二天」的精确相对时序未获其 FACT MAP 支持。发布前必须用一手来源核对两条信息的发布日期；无法核对时，应改成不承诺精确日序的表述。
- 两篇共同限制：LinearUncle 的说法只来自用户提供的截图，FACT MAP 均注明未定位到稳定原帖。这不阻断本轮选稿，但发布时不得把它扩写成已完成项目、已报名或获得内测资格；若要作为关键事实强化，需补稳定原始来源。
