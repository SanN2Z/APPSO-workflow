# 正文初读

A 的主结论清楚：把首批门票发给做过 Harness 的开发者，可能是为了更快暴露运行框架的问题；同时，内测邀请不能被读成产品发布或开源。它对跑分和项目实例收得较紧，事实、推断、未知项也大体分开。不过，「为什么找同行」在第一节已经答完，随后关于模型卡、外部 Harness 接入和部门招聘的内容，更像对项目进度的并列补充；结尾又把此前明确标作推断的招募目的压缩成「这轮邀请说明」，语气略有变硬。

B 的阅读路径更清楚：先说明「模型会答」为何不等于「任务会完成」，再列出上下文、工具、恢复和验收等故障问题，随后才回答为什么 GitHub ID 与开源代表作会成为门槛。读者合上文章后，既能复述「同行更可能定位故障层、给出复现路径」，也能复述「目前不能据此确认产品形态、发布日期、开放方式或是否开源」。初读偏向 B，依据是因果顺序，不是语气偏好。

# 必要顺序与删节测试

A 最强的连接，是 Harness 的功能定义之后用「因此」推出开发者会继续追问上下文、工具、权限、重试和验收。若把这两个相邻段落交换，故障清单会先于概念解释出现，读者仍能理解，但需要事后补足它们为什么同属 Harness 问题。A 后半部分的模型卡、外部接入指南与招聘信息则有较强的可移动性，互换后核心论证不会明显失效。

B 最强的连接，是「内测还要回答哪些棘手问题」紧接「这也解释了 GitHub ID 和开源代表作为什么会成为报名材料」。若交换这两个相邻段落，「这也解释了」会失去最直接的前件，申请门槛先出现、测试任务后补充，同行资格与故障诊断之间的因果关系会明显变弱。B 的后一段更像被前一段提出的问题逼出来。

材料取舍上，A 略胜：两篇都没有抄录跑分表，也没有堆项目名称，但 A 使用的材料类型更少，仍足以回答核心问题。A 最可删除的是「这个动作还有一层有限的对照」一段；删去外部 Harness 接入和部门招聘背景，不影响对门票门槛的解释。B 最可删除的是「这次邀请不是孤立动作」一段；它有助于交代项目所处阶段，但删去后，「为什么找同行」以及当前未知项仍然成立。

# 事实、推断与未知项回忆

## A

- 作者推断：要求开源代表作，可能是为了找到能定位故障层、提供复现路径并判断框架取舍的专业反馈者，也便于通过公开产物判断相关能力。
- 未知项：DeepSeek Harness 的最终产品形态与技术架构。

# 事实护栏

A 无重大事实阻断项。它明确把成绩归为厂商自报，没有把「to be released」写成已发布或开源，没有把第三方项目写成入选者或合作方，也没有补写产品细节或使用 LinearUncle 玩笑。需要留意的只是结尾「这轮邀请说明，DeepSeek 当前需要的反馈……」比前文的「合理目的」「仍然只是推断」更确定；结合全文仍可识别为作者解释，尚不足以构成把已确认动机写成事实的阻断项。

B 无重大事实阻断项。它明确说明跑分是厂商自报、「to be released」不等于开源、第三方项目不代表报名或入选，并把生态摸底、寻找合作对象以及获得专业反馈都写成可能性。关于「把模型外层运行系统作为独立工程推进」是由招聘、模型卡和邀请连续信号得出的作者判断，并未冒充 Tianyi Cui 或 DeepSeek 的原话。文中也没有使用 LinearUncle 玩笑。

# 选择

结论：B

信心：中
