# DeepSeek Harness 的第一批门票，为什么发给同行？

8 月 1 日，DeepSeek 团队成员 Tianyi Cui 公开邀请做过 Agent Harness 开源项目的开发者参加 DeepSeek Harness 内测。申请者需要附上 GitHub ID 和代表作，可以回复或私信联系。

这张邀请最值得看的，不是「内测」两个字，而是门槛：DeepSeek 没有先问你是不是重度用户，而是先问你造过什么。代表作在这里不只是简历，它也暴露了开发者处理过哪类 Agent 难题。

## 他们能测出什么

Harness 不是模型本身。它处在模型与任务之间：决定模型拿到哪些上下文、记忆和工具，允许执行哪些命令，失败后怎样重试，做完又如何验收。同一个模型被放进不同 Harness，实际完成任务的过程可能很不一样。

因此，做过 Harness 的开发者看到一次失败，不只会说「模型答错了」。他们更可能继续追问：上下文是不是丢了，工具有没有选错，权限是否卡住，重试机制有没有把小错放大，验收条件是否含糊。

公开项目的侧重点也确实很分散：有人做记忆和自我改进，有人做系统观测，有人做本地桌面助手，也有人做多 Agent 调度。这不能用来猜 DeepSeek 会做哪种产品，却能说明首批申请者可能带来不同的故障经验。由此推断，先找同行，一个合理目的就是更快暴露运行框架的问题；但 DeepSeek 没有公开说明招募动机，这仍然只是推断。

## 自研 Harness 走到哪一步了

目前最硬的一条证据，来自 DeepSeek-V4-Flash-0731 的官方模型卡。模型卡称 7 月 31 日版本强化了 Agent 能力，并注明公开 Code Agent 任务使用了 DeepSeek Harness 的 minimal mode、最高推理强度、temperature 1.0 和 top_p 0.95。Harness 的状态写的是「to be released」。这些能力与成绩都是厂商自报，代码、系统提示词、运行轨迹和完整复现条件也没有随模型卡公开。

换句话说，自研 Harness 已经进入 DeepSeek 展示 Agent 结果的评测流程，但外部还无法把模型能力和运行框架的贡献拆开，也无法按完整条件复现。一天后的内测邀请，让它从模型卡脚注里的工具，变成了一个开始寻找外部测试者的项目；这依然不是公开发布。

这个动作还有一层有限的对照。DeepSeek 此前公开提供的，是把自家模型接入 Codex 等外部 Harness 的指南。6 月 21 日，Tianyi Cui 又称 DeepSeek Harness 是新成立的部门，正在招聘研究员、工程师和产品经理。现在能确认的，是 DeepSeek 在继续兼容外部框架之外，也在建设并测试自己的运行层；还不能据此推演它要取代谁，或断言它会成为一个独立商业产品。

## 最窄，也最有用的结论

这轮邀请说明，DeepSeek 当前需要的反馈，不只是「好不好用」，还包括「这套框架在哪里会坏」。把门票先发给造过类似系统的人，与这个测试阶段相符。

但名单里没有产品答案。截至材料冻结时，正式名称、界面、发布日期、价格、是否开源、首批人数和测试协议都没有公布，也不知道它是否只服务 Coding Agent。「to be released」更不等于已经开源。现在最值得记住的不是又一款 Agent 产品即将横空出世，而是 DeepSeek 正把影响 Agent 表现的外层运行框架，交给有建造经验的人做受邀测试。再往前一步，都是等待证据的猜测。
