## 因果复盘

```text
优惠名称、金额和期限齐全，但正文仍显得干
→ 读者知道「有什么」，却不知道「何时领、哪里会失效、什么动作会继续扣钱」
→ 研究层只完成权益枚举，没有把产品条款转成开通、认证、使用和关闭四个实际动作
→ 将豆包额度周期、OpenAI 账号归属、GitHub 学生包、阿里云余额规则和 HAI 关机账单嵌入对应场景
→ `sources.md`、`research/fact-sheet.md` 与 `research/draft-claim-map.md` 已逐条记录；待用户审阅正文
→ 适用于优惠指南和订阅清单；纯新闻快讯不必强行展开全部生命周期
```

```text
用户要求在其整版改写上做增量修改，但交付稿覆盖了原句
→ 用户声音和已投入的编辑劳动丢失，必须重新返工
→ canonical prose 被错误降格为「风格参考」，局部补丁被扩大成整版重写
→ 恢复用户全文并锁定 U1—U6；只允许错字、事实纠错和邻接增补
→ 检查用户稳定引用与段落顺序；OpenAI 地区句单独记录事实性改动
→ 适用于用户已提交实质正文的共写场景；用户明确要求重写时不受此限制
```

## 经验分级

### 仅保留在本案例

- 「火锅」「GitHub 有点抠」「亏了一个亿」来自用户本轮改写的真实声音，只服务于这篇稿子，不沉淀成固定「薅羊毛体」。
- 本文补充隐秘信息时只收会改变领取动作的规则，不扩成覆盖所有学生软件的大全。
- 本轮「覆盖用户正文」是已有共写规则的执行失败，留在案例中，不新增重复 SOP。
- 「本科生先做一个 coding agent 小项目」是本文的作者判断，只在本案例使用；不推广为所有学生工具稿的固定结构。
- coding agent／Harness 路线未通过本稿冷读，不再作为本文的默认增量方向。
- 新增科研工具时采用「一个通用主场景 + 一个窄场景 + 两项资格补充」，只作为本文的局部修复，不推广为固定工具稿结构。
