## 已否决路线的历史记录

## 共同处境

本科生已经习惯用聊天助手问问题、改文字，但许多人还没有接触过能进入项目、读取文件、修改代码和运行命令的 coding agent。

## 标题与承诺

- 锁定标题：大学生的 AI 开学薅羊毛清单来了：有人送会员，有人直接送算力
- 首屏承诺：先按开学后的真实任务梳理福利，再把读者送到第一个可完成的 coding agent 项目。
- 标题处理：保留用户现有标题，不用 DeepSeek 或 Harness 替换福利清单的主承诺。

## 核心判断

对本科生来说，开学季优惠的价值不只在于省会员费。更值得借这个低成本入口完成第一个小项目，开始练习怎样和 Agent 分工、检查和迭代。

## 支撑判断

1. 日常问答、资料整理、编程协作和云算力属于不同任务层，原有福利清单继续负责选择入口。
2. coding agent 与普通聊天助手的关键差别，是它可以进入项目并执行读取文件、修改代码和运行命令等动作。
3. Vibe Coding 不等于把任务全部交给 AI。目标、任务拆分、验收和是否采用改动仍由人决定。
4. DeepSeek Harness 当前的热点价值，在于帮助读者理解模型之外的工具、上下文和工作步骤；developer preview 状态决定了它只作进阶探索。

## 路线选择

### 路线 A：福利清单为主，只在编程段补一个工具框

- 得到：改动最小，标题与正文高度一致。
- 放弃：coding agent 仍像附加产品名，无法承载作者真正想推荐的能力。

### 路线 B：羊毛是入口，Agent 是能力线（曾选，后否决）

- 得到：保留福利清单的热点入口，在写代码与云资源之间加入小项目、Vibe Coding 和 Harness，形成从聊天到项目的变化。
- 放弃：正文会变长，需要严格控制安装和配置细节。
- 用户确认：2026 年 8 月 20 日，用户回复「行，你出一稿试试，我改的那些你别动」。

## 开场与叙事

- 开场发动机：沿用用户现有的开学订阅开支场景，不重写首屏。
- 首屏压力：学生领到的权益不同，但光领会员还不能回答怎样把 AI 用进真实项目。
- 叙事发动机：问题升级。
- 一句话主线：先解决「有什么羊毛可领」，再追问「领完以后怎样从聊天走进项目」，最后用 Harness 解释这种协作还依赖哪些工具和步骤。

## 最强对手

- 反对意见：多数非计算机专业本科生并不需要命令行和 Harness，加入后会把实用福利清单写成极客教程。
- 正面回应：正文只展示一个普通学生可用的小项目，不写安装命令；DeepSeek Harness 单列为 developer preview 的进阶热点，不列为第一站。

## 表达与边界

- 写作模式：personal。只使用用户明确表达过的真实使用判断，不虚构具体大学经历或项目成果。
- 声音锚点：用户现有正文逐字锁定；新增段落使用常用词，每句只承担一个主要意思。
- 不写：完整安装教程、API 配置命令、模型跑分、规避地区限制、把 Vibe Coding 写成不用理解代码、把 Harness 写成稳定学生产品。
- 不预设金句、原创比喻或段尾升华。
