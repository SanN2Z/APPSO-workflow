# 2026-07-28 晚间补充雷达

本轮补扫 7 月 27 日以来的新信号，并与今天已有的 SSI、Agent 逐动作授权、水下机器人、纽约数据中心和 Meta AI 选题去重。

默认读者是对 AI 与科技行业感兴趣、但不会自己部署万亿参数模型的中文读者。本轮只回答一个问题：现在新出现的材料里，哪一条已经足以支撑一篇有新判断的公众号稿？

## 先说结论

如果沿用现有选题池，优先推进 **Kimi K3**。此前的「7 月 27 日开放权重」已经从预告变成可核文件：官方仓库、技术报告、96 片权重文件和自定义许可证均已上线，Hugging Face 仓库页面显示总量为 **1.56 TB**。这让文章可以从跑分转向一个更具体的问题：一个模型「可以下载」，离普通公司「可以掌控」还有多远？

如果只看真正的新题，主推 **Enigma 的百台机器人公开实验**。它不是再放一段剪好的机器人演示，而是把 100 多台机器人放到网页另一端，让公众尝试用文字、语音、视频或拖拽与真机交互。最值得写的不是 7100 万美元融资，而是这家公司把产品发布会同时做成了一场人机交互实验和数据采集。

**Anthropic 对开放权重的正式表态**价值也很高，但应该并入现有 `open-weight-policy-boundary`，不另开一篇相似稿。

## 主推：Kimi K3 真正放出以后，「开放」先撞上 1.56 TB

- **新事实**：Moonshot AI 已公开 Kimi K3 的官方 GitHub、技术报告、Hugging Face 权重和 Kimi K3 License。官方模型卡称其总参数为 2.8 万亿、每个 token 激活约 1040 亿参数，支持 100 万 token 上下文，并在训练阶段采用 MXFP4 权重与 MXFP8 激活量化。
- **最直观的细节**：Hugging Face 仓库页面显示总量为 1.56 TB，共有 96 片主要权重文件。开放权重在法律上让使用者多了一层控制权，但在工程上并没有自动变成「下载后在电脑上运行」。
- **核心判断**：开放权重的讨论不能只问「放没放」，还要拆成四层：能否下载、能否负担部署、能否修改、能否按自己的商业方式使用。Kimi K3 已经跨过第一层，也给出了部署与修改路径，但存储、算力、推理系统和自定义许可证仍决定了谁能真正掌控它。
- **许可证边界**：许可证允许使用、复制、修改、部署、微调和再分发，但不是标准 Apache 或 MIT 许可证。经营 Model as a Service 且连续 12 个月总收入超过 2000 万美元者，需要先与 Moonshot AI 另签协议；达到特定超大产品规模时还存在显著展示「Kimi K3」名称的要求。
- **跑分边界**：官方表格混合了厂商自测、第三方榜单和不同 Agent harness；多项结果使用最高推理档位，不能直接写成「全面超过 GPT 或 Claude」。真正值得做的是统一任务、预算和 harness 的实测。
- **可用标题**：
  - 《Kimi K3 权重终于放出来了，但光模型文件就有 1.56 TB》
  - 《2.8 万亿参数真的放出来以后，开放权重先撞上了硬件现实》
  - 《可以下载，不等于可以掌控：Kimi K3 开放权重后的第一道门》
- **下一步**：先做两条线的最小实测：官方 API 的知识工作 / 编码任务，以及第三方托管入口的相同任务。没有相同预算和 harness 前，不做模型强弱总排名。
- **一手来源**：[Kimi K3 官方仓库与模型卡](https://github.com/MoonshotAI/Kimi-K3)；[Hugging Face 权重仓库](https://huggingface.co/moonshotai/Kimi-K3/tree/main)；[Kimi K3 License](https://github.com/MoonshotAI/Kimi-K3/blob/main/LICENSE)。

## 真正新增：把 100 多台机器人挂上网页，产品发布会也是训练场

- **新事实**：Enigma 于 7 月 27 日从隐身状态公开，并宣布完成 7100 万美元种子轮融资。公司与 TechCrunch 均称，其公开实验允许全球用户在线与 100 多台自研机器人交互；机器人位于以色列和加州的机库，可执行绘画、持剑对抗和简单化学操作等任务。
- **最有意思的不是融资**：实验会比较人们究竟更愿意用文字、语音、示范视频，还是点击、拖拽来指挥机器人。公司明确希望用这些真实交互寻找更自然的界面，并反过来改善机器人基础模型。
- **核心判断**：机器人公司的冷启动问题不只缺动作数据，也缺「普通人到底会怎样表达意图」的数据。Enigma 把一场面向公众的在线活动，同时变成界面研究、使用意图调查和真机训练材料入口。
- **为什么适合公众号**：有具体人物和动作，也有很容易理解的冲突——如果告诉机器人怎么洗碗需要 15 分钟，人类宁愿自己洗。Physical AI 的下一个门槛可能不是让机器人再多会十个动作，而是把指挥机器人的成本降到拧音量旋钮那么低。
- **可用标题**：
  - 《一家新公司把 100 台真机器人挂上网页，让全世界替它找交互方式》
  - 《融资 7100 万美元后，他们先让网友遥控机器人打架》
  - 《机器人不会用，可能和机器人不会做一样麻烦》
- **事实边界**：模型能力、跨硬件通用性和「全部自研」目前主要来自公司自述；本轮尚未完成在线活动的独立实测。公开实验能收集哪些数据、是否进入训练、如何取得参与者同意，也需要读条款后再写。
- **来源**：[Enigma 官网](https://www.enigma.inc/)；[公开实验入口](https://www.robots.online/)；[TechCrunch 对创始人的采访](https://techcrunch.com/2026/07/27/enigma-raises-70m-to-make-controlling-a-robot-as-easy-as-adjusting-the-volume/)。

## 高价值补稿：Anthropic 不是支持禁令，而是把限制搬到了别处

- **新事实**：Dario Amodei 7 月 27 日正式回应开放权重争议，明确称 Anthropic 从未主张全面禁止开放权重模型，也认为能力不危险的开放权重模型是一种公共品。
- **但三道限制没有松**：Anthropic 仍支持限制先进芯片与芯片制造设备流向中国、打击产业级蒸馏，并要求所有达到足够能力的模型在发布前接受强制安全测试，无论开放还是闭源。
- **核心判断**：争论已经不再是简单的「支持开放权重还是反对开放权重」，而是在训练资源、蒸馏、发布测试和商业使用四个环节分别设门。Anthropic 反对的是按权重开放与否一刀切，但并不反对更严格的上游与发布控制。
- **处理建议**：直接补进 `open-weight-policy-boundary`，与 NVIDIA、Microsoft 等公司的开放权重公开信形成正面交锋。现有稿若只写「美国公司集体支持开放」，现在已经不完整。
- **边界**：文中对中国、军事用途、蒸馏与生物风险的描述是 Dario 与 Anthropic 的政策判断，不是已经得到独立证明的事实。
- **一手来源**：[Anthropic：Our position on open-weights models](https://www.anthropic.com/news/position-open-weights-models)。

## 快速实用备选：Claude 的「分享」不是「私密转发」

- **新事实**：WIRED 报道称，一些由用户主动生成公开分享链接的 Claude 对话曾进入 Google 和 Bing 搜索结果。Anthropic 的 `robots.txt` 虽然禁止爬取分享页，但部分页面没有搜索引擎建议使用的 `noindex` 标记；报道发布时，Google 结果已消失，Bing 仍能检索到约 612 条。
- **核心判断**：很多 AI 产品把「生成一个链接」设计得像私密转发，但只要链接是公开 URL，没有访问控制，它就可能被引用、抓取或进入搜索索引。`robots.txt` 是给爬虫的请求，不是隐私边界。
- **可用标题**：《你发给同事的 Claude 分享链接，可能被搜索引擎看见》
- **边界**：这些不是未分享的私人会话，而是用户主动生成了公开 URL 的对话；不能写成「Anthropic 泄露了所有 Claude 聊天」。Anthropic 尚未回应，正式落稿前要重查分享页响应头、当前索引状态和产品提示文案。
- **来源**：[WIRED 调查](https://www.wired.com/story/private-claude-chats-exposed-in-google-and-bing-search-results/)；[Claude 官方分享说明](https://support.claude.com/en/articles/10593882-sharing-and-unsharing-chats)；[Google 的 `noindex` 说明](https://developers.google.com/search/docs/crawling-indexing/block-indexing)。

## 趋势储备：安全模型开始分层调度，不再让最贵模型包办全部任务

- **新事实**：微软 7 月 27 日发布 MAI-Cyber-1-Flash，并把它放进多 Agent 漏洞发现与修复系统 MDASH。官方称，小模型处理最多 90% 的任务，最难的 10% 再交给 GPT-5.4；组合系统在 CyberGym 上达到约 96%，相对微软当前 MDASH 配置节省约 50% 成本。
- **核心判断**：企业 Agent 的竞争正在从「接入最强模型」转向「让不同模型只处理自己最划算的部分」。长期、全天运行的安全任务把 token 成本从价格表问题变成系统架构问题。
- **为什么暂不主推**：近期已经有 OpenAI × Hugging Face 安全事件、Google Flash Cyber、Open Secure AI Alliance 和开放模型网络安全差距等多条相近材料，账号容易连续撞题。
- **硬边界**：96% 是 **MAI-Cyber-1-Flash + GPT-5.4 + MDASH harness** 的组合成绩，不是单个小模型成绩；50% 节省也是相对微软自家现有配置，不能外推为对所有前沿模型便宜一半。
- **一手来源**：[Microsoft AI 发布说明](https://microsoft.ai/news/introducing-mai-cyber-1-flash-inside-mdash/)；[微软 Project Perception 说明](https://blogs.microsoft.com/blog/2026/07/27/rethinking-security-for-the-age-of-ai/)。

## 今日观察：MCP 最大版本还差「正式发布」这一步

- **已确认**：MCP 官方在 5 月发布候选版，预告最终规格于 7 月 28 日发布。草案删除协议级 session、初始化握手与 `Mcp-Session-Id`，把核心改成无状态请求；Tasks、MCP Apps 等能力转为扩展，并加入至少 12 个月的弃用窗口。
- **可写判断**：MCP 要从开发者新玩具变成普通云基础设施，关键不是继续加能力，而是让服务可以被普通负载均衡、缓存和追踪系统处理。
- **当前边界**：截至本轮访问时，官方规格导航仍把新版本显示为 `draft`，不能写成「MCP 2026-07-28 已正式发布」。等正式版本页、changelog 与 Tier 1 SDK 支持同时确认后，再做开发者向短稿或 X。
- **一手来源**：[MCP 2026-07-28 候选版说明](https://blog.modelcontextprotocol.io/posts/2026-07-28-release-candidate/)；[当前规格草案与变更表](https://modelcontextprotocol.io/specification/draft/changelog)。

## 本轮不建议另开

- **Amazon 调整 Nova 模型战略**：目前核心新增仍是匿名信源报道，官方产品页和退役公告尚未形成对应证据，只进入观察队列。

- **把 Anthropic 声明另写成一篇立场快讯**：它的价值在于改变现有开放权重稿的论证结构，不在于再做一篇公司表态摘要。
- **只按 Kimi K3 官方跑分写「国产第一」**：不同模型使用了不同 harness、推理档位和引用来源，先做同任务、同预算实测。
