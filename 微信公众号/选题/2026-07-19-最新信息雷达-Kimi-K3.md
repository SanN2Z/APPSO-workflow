# 2026-07-19 最新信息雷达：Kimi K3

扫描截点：北京时间 2026 年 7 月 19 日 11:29。

## 先说结论

当前最值得追的就是 **Kimi K3**，而且已经不是中文圈自嗨。它仍在 Techmeme 头部议程里，AP、Axios 等海外媒体持续跟进；Arena 的盲测结果又把它推到了前端编程榜第一。

不过，模型发布本身发生在 7 月 16—17 日。今天的新鲜度主要来自海外传播、独立结果和“美国 AI 领先是否被追平”的争论继续升温，不能写成 7 月 19 日刚发布。

K3 真正有分量的地方不是单个 benchmark，而是一次性组合了五件事：

- 2.8 万亿总参数的超大规模 MoE；
- 原生图片和视频理解；
- 最高 100 万 token 上下文；
- 面向编程、科研和知识工作的长任务 Agent；
- 承诺在 7 月 27 日前发布完整权重。

官方自己也承认，K3 综合表现仍落后 Claude Fable 5 和 GPT-5.6 Sol。比较准确的判断是：**第一梯队出现了一个即将开放权重的新成员，而不是 Kimi 已经全面登顶。**

## 现在怎么用

### 普通用户：网页直接试

入口：[Kimi.com](https://www.kimi.com/)

1. 新建会话；
2. 点击输入框上方的模型选择器；
3. 普通复杂任务选 `K3`；
4. 大范围资料搜索、批量处理选 `K3 Swarm`；
5. 上传图片、视频、PDF、Word、Excel 或代码文件后直接描述交付物。

官方建议切到 K3 后新开会话，因为旧模型建立的上下文缓存会失效；继续在旧会话里硬聊，刚切换时消耗更高。

K2.6 更适合快速问答。K3 适合让它真正交付文件、网页、研究结果或长任务；K3 Swarm 适合能拆成大量平行搜索和批处理的任务。

### 最值得先跑的三个测试

#### 1. 截图变网页

上传一张喜欢的网页截图：

> 参考这张截图做一个可运行的响应式网页。先识别布局、字体层级、颜色和组件，再实现。启动本地预览后查看截图，逐轮修正视觉差异。不要只交代码，最后给我可运行项目、启动命令和仍未对齐的细节。

这个任务最能测试 K3 的“视觉进入编程闭环”：不是看图后一次性吐代码，而是看运行结果再改。

#### 2. 多资料变交付物

上传论文、访谈、财报或产品材料：

> 先建立来源清单，逐条提取可核事实和互相冲突的信息；再做一份带引用的研究报告，并同时生成可编辑的 PPTX 和一页交互式网页。事实、厂商自报和你的判断分开写。缺证据的地方明确留空，不要补剧情。

它同时测试百万上下文、工具调用和最终文件是否真的可编辑。

#### 3. 大代码库长任务

> 先扫描仓库并生成架构图，只提出实现计划，不修改文件。计划确认后实现这个功能，运行测试，遇到失败先定位原因再修。保留用户已有改动，最后列出实际修改、测试输出和未覆盖风险。

不要只用一道算法题测 K3。它的主要卖点是长程执行，最好给它一个需要读仓库、改代码、跑命令和返工的真实任务。

### 开发者：Kimi Code CLI

Windows PowerShell 官方安装命令：

```powershell
irm https://code.kimi.com/kimi-code/install.ps1 | iex
```

Windows 首次使用前需要安装 Git for Windows，因为 Kimi Code 使用其中的 Git Bash。安装后：

```powershell
Set-Location D:/your-project
kimi
```

进入后依次使用：

```text
/login
/init
/model
```

在 `/model` 中选择 `k3`，最好再用 `/new` 开一个新会话。Kimi Code 中，Moderato 及以上会员可用 K3；Allegretto 及以上才解锁最高 100 万上下文。当前这台电脑尚未安装 `kimi` 命令。

新版本 Kimi Code CLI 已从 Python 迁移到 TypeScript / Node.js。官方文档提示，新版 CLI 的新用户目前不要把 VS Code 插件当首选入口；直接使用终端 CLI 更稳。

### API：模型名就是 `kimi-k3`

国际开放平台的 OpenAI 兼容地址：

```text
https://api.moonshot.ai/v1
```

最小 Python 调用：

```python
import os
from openai import OpenAI

client = OpenAI(
    api_key=os.environ["MOONSHOT_API_KEY"],
    base_url="https://api.moonshot.ai/v1",
)

response = client.chat.completions.create(
    model="kimi-k3",
    reasoning_effort="max",
    messages=[{"role": "user", "content": "用一句话介绍 Kimi K3。"}],
)

print(response.choices[0].message.content)
```

官方价格为每百万 token：缓存命中输入 0.30 美元、未命中输入 3 美元、输出 15 美元。API 当前文档仍写明 `reasoning_effort` 只支持 `max`；网页和 Kimi Code 的产品更新页已经出现 `low / high / max` 三档，说明各入口正在分批对齐，不能把网页设置直接照搬到 API。

## 为什么大家把它叫“王炸”

### 1. 它不是只在厂商 PPT 上好看

K3 在 Arena 的前端代码盲测里排到第一，超过 Claude Fable 5 和 GPT-5.6 Sol 的相应条目。这个结果来自用户盲选，比厂商自测多一层独立性。

边界也很清楚：这是前端网页生成这个特定任务，不是通用智力总榜。Artificial Analysis 的综合测试把 K3 放进第一梯队，但仍在 Fable 5 和 GPT-5.6 Sol 之后。

### 2. 它盯上的是最值钱的长任务

官方案例不只展示写函数，还展示了 48 小时芯片设计、科研代码复现、交互式研究网站、游戏与 3D、视频剪辑。全部是“读很多材料—调用工具—持续返工—交一个成品”的任务。

这些案例目前主要是厂商演示，不能直接等同于普通用户的稳定成功率。但产品方向很明确：K3 想争的不是聊天框里的一次回答，而是 Coding Agent 和知识工作 Agent 的长时间占用。

### 3. 它准备把第一梯队能力变成可下载权重

完整权重计划在 7 月 27 日前发布。今天还不能下载、自部署或检查权重，因此当前更准确的称呼是“已发布产品与 API、承诺开放权重”。真正的开放节点要等权重、许可证和技术报告一起落地。

即使权重发布，2.8 万亿参数也不代表普通电脑能本地跑。官方建议 64 张以上加速卡组成的 supernode 级部署；“开放”解决的是所有权和可改造性，不是家用显卡门槛。

## 推荐选题

现在最值得做一篇“实测 + 解释”稿，而不是复述参数：

> **Kimi K3 真正的王炸不是 2.8 万亿参数，而是它开始用一个即将开放权重的模型，正面争夺 Claude Code、Codex 和知识工作 Agent 的地盘。**

建议先用同一个真实任务同时跑 K3、当前 Codex 和 Claude：给它们同一份资料或同一套代码仓库，比较最终交付、返工次数、耗时、额度消耗和人工接管点。单看 benchmark 已经没有多少新增价值。
