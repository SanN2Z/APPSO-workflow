# 2026-07-21 Opta 世界杯稿：初稿—终稿复盘

适用内容包：`../../内容/2026/07/spain-opta-world-cup-prediction/`

## 结论先行

这轮不是把初稿“润色得更像公众号”，而是重做了选题问题、证据结构和读者路径。

初稿想证明“Opta 比聊天模型靠谱”；最终发表版回答的是：“AI 和数据模型可以提高预测质量，但猜中一次、命中率高或进入博彩生产系统，都不等于普通人获得稳赚优势。”

真正的升级有四层：

1. 从决赛前最后一张截图，扩展到开赛前至决赛前的完整概率轨迹；
2. 从“统计模型好、语言模型差”的二元判断，扩展到任务、数据、协议和评分口径；
3. 从一次赛果，扩展到连续样本、平局失败模式、个人小额实验和生产应用；
4. 从重复“AI 不是神”，改成用赔率利润回答开头“能不能靠它赚钱”。

## 三、结构和中心判断怎么变了

### 初稿

```text
决赛结果
→ 其他 AI 预测很差
→ Opta 如何模拟
→ 语言模型与模拟引擎不同
→ Opta 更诚实
```

优点是短，冲突明确。问题也很集中：泛指其他 AI 失败、把世界杯模型写成可复现、用一场决赛反推模型可靠，而且没有图片和来源。

### 公司交付稿

```text
赛果
→ 六阶段预测轨迹
→ 预测任务分类
→ 连续比赛成绩
→ Opta 数据体系
→ 博彩业应用
→ 平局短板与个人实验
→ 长期系统才有价值
```

它把证据补齐了，但后半段数次重说“不能只看一次命中”，博彩、个人实验和总结段的关系也不够紧。

### 最终发表版

```text
西班牙夺冠
→ 决赛二选一有什么好吹
→ 开赛前前四恰好成为真实四强
→ 能不能靠它赚钱
→ 完整概率轨迹
→ 不同预测协议
→ 平局短板和个人实验
→ 博彩系统与普通人优势的差别
```

终稿选择了一个普通读者会主动追问的问题：“既然这么准，我能不能拿它赚钱？”方法、准确率、平局和博彩业都围绕这条线服务，文章因此从技术说明变成了有欲望、有反例、有后果的解释稿。

## 六、这些修改背后的根因

### 1. 初稿从“AI 结论”出发，不是从当天新闻出发

初稿先想证明 Opta 更靠谱，再选择决赛作例子。最终稿反过来：先交代冠军和刷屏预测，再让读者质疑“二选一有什么好吹”。时效不是标题里的日期，而是当天结果让哪份旧证据突然值得重看。

### 2. 初稿没有定义预测任务

夺冠、90 分钟胜平负和淘汰赛晋级都叫“预测”，但答案空间和评分方式不同。终稿用一次真实投注未中，把抽象口径错误变成可感知损失。这是全文最重要的方法修正。

### 3. 初稿把“模型跑得稳”写成“模型预测得准”

2.5 万次模拟降低的是抽样波动，不会自动修正底层概率。初稿还写了“可复现”，但外部没有完整代码、输入和权重。终稿加入体重秤类比和不可复算边界，纠正了技术过度承诺。

### 4. 初稿靠单场命中和泛指失败案例站队

“其他 AI 一塌糊涂”没有可查对象；“西班牙赢了”也不足以证明 59.6% 校准。最终稿换成连续记录、固定协议、平局失败样本和简单基线，论证从情绪比较变成协议比较。

### 5. 中间稿证据齐了，但读者问题不够集中

中间稿把轨迹、模型比较、博彩、平局、个人案例和长期系统依次摆出，信息丰富却像报告。终稿用“能不能靠它赚钱”串起这些材料，并把博彩移到结尾，材料从并列变成因果推进。

### 6. “AI 味”主要来自结构，不是某几个词

中间稿每节都有判断、解释和小结，最后又用十余段复述中心论点。终稿减少小标题、删除总结整节，并把“为什么重要”交给具体数字和实际损失。口语只是表层，信息增量和段落依赖才是主要变化。

### 7. 图片太晚进入流程

初稿没有图，中途才反复补图片、视频、图注和格式，导致“JPG 是不是视频”“媒体提问快照是什么意思”等返工。以后 brief 阶段就应锁定每张图的论证任务，交稿时必须是实际文件而非计划。

### 8. 协作没有提前标出受保护段落

用户亲自改好开头后，明确要求“别大动”。这说明多人协作时必须标注已确认段落和允许修改范围，避免每轮模型都重新优化已经通过的文字。

### 9. 公司稿与个人稿最初没有及时分叉

共享事实不等于共享成稿。个人账号如果只做换词，会继续复用公司的问题、结构、图片和判断。最终另建内容包是正确动作；但个人稿视觉尚未落地，不能称完整发布包。

## 七、终稿仍值得记录的问题

这些问题不否定成稿，但应作为下一篇的回归用例：

1. 最终 Markdown 有多处断裂加粗，如 `**「****猜中冠军****」****和...`，也有半角问号、`Opta预测`、`模拟pipeline`、`90分钟内0:0` 和段尾分号。
2. 叙述主体在“我”“APPSO”之间切换，下一稿应提前选定作者还是编辑部视角。
3. “59.5% 与其说是预测，不如说是算术”过头。决赛仍需估计两队胜率，只是已知赛果减少了不确定性。
4. “大模型预测足球整体命中率大多在六成多”只由两套口径不同的公开记录支撑。更稳妥的写法是“这两套公开记录中”。
5. “这套预测技术博彩公司也一直在用”可能把 Stats Perform 的数据与产品服务，写成博彩公司直接使用同一套世界杯夺冠模型。
6. “光蒙也有一半准头”是有效吐槽，但只有等概率随机二选一时预期才是 50%。
7. “梅西最后一舞”若无本人明确表态，应标为报道修辞而非确定事实。
8. 8 个媒体位置只有部分有可见图注；发布后的本地归档也无法重建真实视频组件。
9. 本地 `asset-manifest.yml` 对部分官方图与 X 视频仍记为 `needs_review`。公司内部若另有授权，应把凭证补回本地记录；不能仅凭已经发表倒推权利已清。
10. 最终标题没有粘贴回来，无法完成标题层面的版本复盘。

## 八、进入 SOP 与不进入 SOP 的内容

已经进入 `../SOP/时效热点-AIGC解释稿.md`：

- 事件时间、官方宣布时间与重新发酵时间分开记录；
- 预测前先定义题目、信息截止点、结果空间和评分；
- 有连续更新时建立完整轨迹，不只截最终节点；
- 不可比准确率不得排榜；
- 模拟稳定性不得写成模型准确性；
- 一次命中不得证明长期可靠；
- 陌生机构背景控制在改变读者判断所需的最小长度；
- 个人案例只承担一个边界，并同步写限制；
- 视觉必须落盘，poster 与视频分开；
- 结尾必须新增信息；
- 用户确认段落设受保护区；
- 公司稿与个人稿使用独立内容包。

暂不固化为通用规则：

- 每篇都用世界杯、博彩或赚钱作钩子；
- 每篇都必须做六节点时间线；
- 每篇都必须加入个人经历或视频；
- 每篇都把国内与国外分组；
- 每篇都使用“封神”“开天眼”等口语。

这些只是本稿的有效选择，不是可机械复用的模板。
