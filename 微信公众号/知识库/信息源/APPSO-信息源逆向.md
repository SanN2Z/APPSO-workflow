# APPSO 信息源逆向

- 建档日期：2026-07-10
- 样本范围：近期 25 篇标题与稿型，17 篇可访问正文。
- 结论边界：只能还原公开文章呈现出的来源结构，无法知道编辑部订阅列表、群聊、采访关系和未公开线人。

## 结论先行

APPSO 的公开来源栈已经基本清楚，但不能说“全部摸清”。其内容优势来自六层材料的组合，而不是某个秘密网站：

```text
官方发布 / 文档
→ 当事人和开发者社交原帖
→ GitHub、论文、招聘页等原始材料
→ 自家实测和历史对照
→ 独立评测与可信媒体补证
→ 采访、活动和知情人士渠道
```

前五层可以复制；最后一层属于媒体关系和长期积累，只能逐步建设。

## 公开样本中出现的来源层

| 来源层 | 在文章中的用途 | 观察到的形式 | 我们的用法 |
|---|---|---|---|
| 官方发布 | 确认发布、能力、价格和入口 | 发布博客、文档、演示视频、跑分表 | 作为首要事实源，但标成厂商自报 |
| 社交原帖 | 找热点、人物反应和产品案例 | X、LinkedIn、小红书、网友截图 | 作为线索和舆情；引语必须回到原帖 |
| 原始材料 | 从普通新闻中挖出新角度 | GitHub、论文、招聘页、模型卡 | 直接读原文，不只引用媒体摘要 |
| 自家实测 | 把参数变成读者能感知的差异 | 相同提示词复测、前后版本对照、真实工作流 | 记录版本、设置、预算、失败案例 |
| 独立验证 | 反驳或校准厂商叙事 | Epoch AI、Artificial Analysis、公开榜单 | 必须阅读方法和口径，不能只抄排名 |
| 自有渠道 | 获得独家信息和人物判断 | 编辑采访、线下活动、知情人士、内部纪要 | 无法靠订阅复制；逐步建立采访名单 |
| 可信媒体 | 补充融资、人事、供应链和传闻 | 晚点、彭博、路透等报道 | 只做二次确认或线索，不冒充一手 |

## 代表性证据

### 方法与案例稿

[Fable 5 方法稿](https://www.ifanr.com/1671120)同时使用了多个 X 创作者案例、小红书案例、GitHub 开源仓库、Claude 官方博客和官方演示视频。它的工作方式不是等一篇媒体报道，而是先在社交平台发现异常案例，再回到项目仓库和官方方法文档解释为什么。

### 产品实测稿

[腾讯 Hy3 实测](https://www.ifanr.com/1671041)把腾讯发布信息和厂商跑分作为背景，核心证据是对 Preview 与正式版使用相同任务复测，并加入 GitHub 代码项目。这个来源组合适合产品稿，但厂商榜单仍应与独立结果分开。

### 原始数据再解释

[DeepSeek 招聘稿](https://www.ifanr.com/1670994)从 DeepSeek 招聘页抓取岗位，再结合 Epoch AI 对中美实验室招聘信息的研究，把一条招聘公告转成职业与教育判断。这里最值得学的是“把非新闻原始材料变成选题”。

### 论文解释稿

[Claude 隐性表征稿](https://www.36kr.com/p/3884890869182729)的核心材料来自 Anthropic 论文，再通过神经科学类比转译。同步稿正文没有稳定展示论文直达链接，说明我们不能把“文章提到论文”当作引用完整。

### 早报与独家

近期早报同时出现官方公告、编辑采访、其他媒体报道和“APPSO 从知情人士处了解到”等表述。例如[一篇近期早报](https://www.ifanr.com/1657048)在官方内部邮件之外加入了未公开组织调整信息。这类私域来源构成 APPSO 的一部分速度优势，但外部无法验证其完整网络。

## APPSO 真正的来源优势

1. **社交雷达密度高**：不是只关注公司官方账号，还盯产品负责人、工程师、投资人和高质量创作者。
2. **会读非新闻材料**：招聘页、GitHub README、脚注、系统卡和产品定价页都能成为选题起点。
3. **有自己的测试库存**：新版本上线后，可以用旧提示词和旧结果快速复测。
4. **有组织记忆**：新新闻会链接旧稿、旧访谈和历史发布，不从零解释。
5. **有采访与线下关系**：直接采访和活动现场能够产生公开订阅源没有的信息。

## 公开稿件的来源风险

- 多个社交案例只写平台和账号名，没有稳定的原帖直达链接。
- 图片图注承担了大量来源说明，同步到其他平台后可能丢失链接或上下文。
- 厂商跑分、作者实测和第三方结果有时靠段落位置区分，没有统一标签。
- “据知情人士”无法由读者独立复核，只能依赖媒体信誉。
- 早报追求速度，来源质量可能从官方公告到二手传闻跨度很大。

因此，我们不应照搬其来源呈现方式。每条重要事实仍要在 `sources.md` 留直达链接、访问日期、来源类型、支持表述和限制。

## 对我们的直接启示

- APPSO 可以作为选题雷达和叙事参考，不能成为最终事实源。
- 看到它的新闻后，先逆向到官方博客、文档、论文、GitHub、原帖或监管文件。
- 建立自己的“同任务复测库”，比单纯增加媒体订阅更能形成长期差异。
- 逐步维护采访对象表：产品负责人、研究者、开发者、独立评测者和真实用户。
- 对无法复核的独家消息，明确写“据某媒体报道”，不改写成已确认事实。
