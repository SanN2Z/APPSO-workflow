# Gemini 主笔交接模板（试跑 v2）

适用：主理人明确要求试用 Gemini 主笔，已有可写的事实材料。不自动替换当前主笔或已确认正文。

将本模板填入一次性 handoff JSON 的 `prompt`；`external_shareable: true` 表示操作者已检查外发范围，不是文件自身授予权限。只交允许外发的材料。内部核查表保留在本地 `verification_notes` 或来源文件中；工具只发送 `prompt`，不会把其余 JSON 字段自动拼入提示词。

1. 本轮任务：稿型、目标读者、要解决的问题、本轮写哪几个单元。
2. 已确认的叙事顺序：每节承担什么，前后如何连接。沿用 L2／L3 已锁定的故事合同。
3. 正文材料：列出本轮需要讲的已核事实、体验和通常归属，保留会改变读者理解的限定。每条用事实 ID 回指本地核查表。审计过程、计时边界和未查明事项留在核查表；只有本轮确需表达的限制才进入提示词，不把整张核查表交成正文提纲。
4. 图片表：按顺序列出标记与画面已经传达的信息。正文补体验、差别和判断，避免把画面逐项念一遍。
5. 声音要求：直接提供本轮获准使用的作者样句和普通说话约束，不整包发送内部文风库。删除重复解释和段尾总结时，直接删，不把被删意思压进上一句；每个案例不必补一句金句或总结。
6. 锁定内容：逐字保存的段落，列入 `locked_fragments`。不得因试模型而重开已确认决定。
7. 交付：只返回本轮正文；不新增来源、测试经历或模型排名。需核实的材料放在正文外的待核列表，不能自行补成事实。
8. 审校交回：Codex 回映事实、核对锁定内容与图片标记，只报有位置和理由的问题。需要修稿时，先冻结允许修改的 `id`、`old` 原文与问题，原主笔仅返回对应的 `id`、`old`、`new` 补丁。通过 `gemini-writer apply-patches` 装配成新文件；保留首次输出及差异。匹配不唯一、越界修改或锁定段落被改时停止装配，不以全文重写绕过。

正常写作仍逐节确认；用户明确要求试写整版时可生成独立试写版。原稿冻结，试写版不取得 canonical 身份。最多 1 次修复，最终由主理人决定采用范围。模型、effort、实际调用路线和原始返回都留证；未调用不得写成「Gemini 已写」。
