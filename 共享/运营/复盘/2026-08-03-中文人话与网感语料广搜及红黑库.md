# 中文「人话」与网感语料广搜及红黑库

日期：2026-08-03

## 结论

这轮没有建立一份「年轻人常用词」清单。这样的清单更新快、语境窄，强行使用后很快会变成另一种 AI 腔。

项目采用红黑双层：

- 黑库沿用现有 24 组公众号项目禁用，作者正文命中后必须删除、具体改写或记录窄豁免。
- 红库收录 18 类表达动作。它们只在当前稿件有真实事实、动作、对象、数字、摩擦或判断时鼓励使用。
- 红库最低命中数为 0，不按篇、段或章节配额，不允许照抄例句、伪造第一人称或把黑词换成红色套话。

机器可读真源是 [wechat-red-black-corpus.yml](../../../.agents/skills/self-media-ops/references/wechat-red-black-corpus.yml)，人工语义夹具是 [wechat-red-corpus-regression.yml](../../../.agents/skills/self-media-ops/references/wechat-red-corpus-regression.yml)。

## 搜索范围

本轮交叉查看了中文社区讨论、创作者经验、编辑规范、GitHub 写作规则、网络语言监测与中文风格研究。来源只用于提炼机制和边界；语料库不保存第三方正文、评论全文或长引语。

### 中文社区与创作者

- [V2EX：AI 生成的文章怎么避免 AI 味](https://www.v2ex.com/t/1227075)：用户直接指出「不是 A，而是 B」常常替读者虚构了一个原本不存在的 A；讨论中也有人提醒，只换近义词不会修复内容和语气。
- [V2EX：AI 味很浓](https://www.v2ex.com/t/1202017)：社区对聊天机器人残留、罐装赞美、固定格式和均匀节奏很敏感；真正有效的笑点通常依赖当前情境。
- [V2EX：如何提升编写文档能力](https://www.v2ex.com/t/832014) 与 [AI 辅助写文档](https://www.v2ex.com/t/1213591)：功能性文字优先服务意图、消歧、来源、评审和交付，工具输出仍需对具体读者重写。
- [人人都是产品经理：什么是说人话的文案](https://www.woshipm.com/copy/1496125.html/comment-page-1)：文章将「人话」落在具体的人、生活小事、情绪和细节上，而非表面口语化。这里仅采用该机制，不复制文案案例。

### 编辑规范与 GitHub

- [少数派当前文风规范](https://manual.sspai.com/rules/style/) 要求表达有实际信息作用，流行语、隐喻和对比服从上下文，事实与来源优先。
- [少数派选题指南](https://manual.sspai.com/guide/idea/) 鼓励把科技议题连接到日常工作和生活，并写出作者真实的观点、发现和经验。
- [中文技术文档写作风格指南](https://github.com/ruanyf/document-style-guide) 强调肯定句、主动语态、明确指代、常用表达和单段单任务。仓库声明为 public domain，本项目仍只保存链接和转述。
- [中文文案排版指北](https://github.com/sparanoid/chinese-copywriting-guidelines) 提供中文互联网排版共识；排版本身不能替代信息任务。

### 网络语言与学界边界

- [国家语言资源监测与研究网络媒体中心](https://nlp.ccnu.edu.cn/) 与年度网络用语发布说明显示，热词是特定年份、平台和语料窗口的快照。年度榜单只进入观察池，不自动成为红词。
- [LSICC 非正式中文语料研究](https://arxiv.org/abs/1811.10167) 显示非正式中文在词汇和句法上与正式语料存在差异，而且不同社区内部并不一致。
- [中文文本风格迁移研究](https://aclanthology.org/2021.ccl-1.26/) 把内容保持与风格改变同时列为任务目标，支持「先保住事实和意思，再改表达」，不支持只换几个词。
- [AI 高频词研究](https://aclanthology.org/2025.bea-1.71/) 显示固定词汇表跨模型和场景的泛化有限。因此黑库是本项目的编辑配置，红库是本项目的正向动作库，两者都不是作者身份检测器。

## 红库的 18 类表达动作

| ID | 表达动作 | 有效时在做什么 |
|---|---|---|
| WX-RED-001 | 动作先于评价 | 先让读者看见谁做了什么，再给判断 |
| WX-RED-002 | 具体对象接住抽象名词 | 把能力、生态、交付落到文件、字段和入口 |
| WX-RED-003 | 时间、地点和任务入场 | 用真实截止点与任务建立压力 |
| WX-RED-004 | 实测顺序如实保留 | 保留成功、失败、重试和人工介入的先后 |
| WX-RED-005 | 结果和缺口并排 | 在同一尺度上写可用范围与不足 |
| WX-RED-006 | 有限第一人称承担判断 | 明确作者做了什么、没测什么、能负责什么 |
| WX-RED-007 | 可核数字代替程度词 | 给出分子、分母、时间或数量 |
| WX-RED-008 | 失败与卡点直写 | 说清停在哪里、等多久、缺什么 |
| WX-RED-009 | 未知项写到边界 | 区分未披露、未测试、未找到和不能判断 |
| WX-RED-010 | 问题由证据逼出 | 前一条事实真的制造了下一问 |
| WX-RED-011 | 读者代价落到动作 | 把抽象影响写成剩余步骤、时间和选择 |
| WX-RED-012 | 异议和修正直给 | 直接回应一个真实异议并说明修正 |
| WX-RED-013 | 普通动词压过业务黑话 | 用打开、补、等、发、改等动作替代空抽象 |
| WX-RED-014 | 场景自己长出笑点 | 笑点来自真实错位，并继续说明问题 |
| WX-RED-015 | 短句承担真实转折 | 短句标记中断、决定、纠正或后果 |
| WX-RED-016 | 作者反应有来由 | 反应绑定可见触发点和后续动作 |
| WX-RED-017 | 问题模型贯穿后文 | 一个朴素问题持续筛选后续证据 |
| WX-RED-018 | 圈内活词有对象 | 「卡住」「跑一遍」「翻车」紧邻具体结果且少量使用 |

## 红项不是红词

同一个表面词可以在不同语境里一红一黑：

- 「任务跑到第 11 分钟，停在权限确认页」提供了时间、位置和卡点，是有效动作。
- 只写「流程卡住了」仍然没有对象、尺度和后果，不能因为含有「卡住」就算红项。
- 「翻车」后面立刻说明哪一列、多少行出错，且目标读者理解该词，可以少量保留。
- 每节固定放一个「翻车」「封神」或问句，会把红库变成新模板，必须判退。

因此红库的判断单位是「语境中的信息任务」，不是词频。采用红项后仍要执行黑库扫描、语用必要性、删除、跨题移植、朗读和相邻重复测试。

## 权利与维护边界

- 只登记 URL、内部索引、人工转述的观察与本项目原创例句。
- 不保存第三方正文、评论全文、原始 HTML 或足以替代原作的长引语。
- 圈内活词每次按读者、平台和日期重审；年度热词不自动进入红库。
- 用户明确不喜欢时可立即进入黑库；用户明确喜欢时，只有补齐适用语境、信息任务和反模板边界后才能进入红库。
