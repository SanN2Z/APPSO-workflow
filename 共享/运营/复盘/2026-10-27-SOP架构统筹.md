# 内容 SOP 架构统筹

日期：2026-10-27。资料属性：internal。处置：`E0 / project_configuration`。

来源：主理人要求按视频产品体验的多轮反馈优化制作流程，随后提出「全局的 SOP 需不要统筹优化一下架构」。本次在现有分层上统一入口与职责，适用于日常内容生产，不启动 ARIS 研究。

## 发现与采用

| 实际问题 | 采用的结构 |
|---|---|
| SOP README、总入口、Skill 和品牌 adapter 同时列任务菜单，新增专项需要多处接线 | README 管文件职责；总入口供人查任务；Skill 做助手分流；品牌专项由品牌 adapter 的菜单维护 |
| 账号、稿型、素材用途和交付阶段混排，容易误加载品牌风格或提前进入发布流程 | 先识别平台／账号／阶段／交付物，再组合核心档位、账号配置、专项和交付模块 |
| 产品实测图与作者另制配图都可能由 AI 生成，工具选择容易混淆 | 实测素材按被测产品路径取得，编辑配图按 Image2 与品牌风格执行；发布校验保持现有规则 |
| 特定工具试跑嵌入核心正文 | Gemini 试跑完整说明由专项保存，核心保留原标题与触发指针；默认主笔及授权范围不变 |
| 总入口把公众号的默认飞书预览写成共用交付顺序 | 按当前用户指定载体执行；未指定时查目标平台默认；公众号交接与外部写入各按其阶段进入 |

## 文件职责

- `共享/运营/SOP/README.md`：唯一的文件职责与维护位置说明，含组合关系图。
- `共享/运营/SOP/工作流使用入口.md`：人用任务导航，指向平台／账号配置和专项真源。
- `.agents/skills/self-media-ops/SKILL.md`：助手识别任务并分流，APPSO 子任务不在此另维护目录。
- `共享/运营/SOP/内容工作流.md`：保留核心合同、现有 PROJECT 规则 ID 与硬门，增加模块组合边界。
- `共享/运营/SOP/Gemini 主笔试跑.md`：保存现有按需试跑的完整执行说明。
- `共享/运营/SOP/Image2 生图工作流.md`：明确编辑配图的适用对象。
- APPSO 视频专项及其品牌路由沿用已采用配置；单稿的任务 ID、输入、费用、文件和原始反馈继续留在内容包。

本次包括 SOP、路由、素材合同及对应校验与测试；工具注册、依赖、账号、发布动作和内容正文保持原有范围。原有无关未提交修改保留。项目配置的采用不代表已经证明减少返工。

## 场景走查

- APPSO 视频体验稿：助手进入品牌 adapter，再加载视频专项；CLI 负责可覆盖的生成任务，Web 负责工作台实测和全局图。
- 个人公众号学习笔记：进入个人账号配置，不继承公司 Logo、公司文风或视频制作配额。
- X 使用已有视频：按 X 写作与当前交付范围执行，不加载公众号预览或强制制作多条新片。
- 用户只换一张图并更新 ZIP：沿用已有作品，修改指定素材及交付载体，不重新启动全文共创和视频生成。
- 用户指定 HTML 审阅：完成 HTML，不先创建飞书文档；未指定载体时仍按目标平台原有默认。
- 普通写作：不加载 Gemini 试跑；明确要求 Gemini 时能从原入口进入完整模块。
- 进入 `ready` 或实际外部写入：原有事实、权利、状态与授权合同继续生效，文档适用范围说明不能绕过校验。

条文与入口走查检测路径断裂、触发遗漏、内容丢失与范围误用；素材校验的实现验证按 `CORE-PORTABILITY-001` 执行相关回归、工具链检查和冷 clone。实际效率与返工效果由后续内容任务复核。

## 素材合同与实现

素材校验器保留三条视觉路线，并分别识别原始产品生成结果、真实产品截图与标准绘图工具制作的数据图。原始 AI 实测结果使用 `source_original`、`product_test_output` 与规范 `ai_generated` 类型，保留生成记录、模型、日期和输入；数据图使用 `infographic`、`data_visualization`，保留实际数据与渲染脚本。APPSO 图表的登记 Logo 要求继续执行。

合同、核心说明、品牌 adapter、制作专项与内容包模板使用相同定义。原图 AI 重画、未确认的输入改编权、发布权利、平台不匹配、缺生成记录、缺数据与绘图脚本、缺品牌 Logo，以及文章只用一类视觉路线仍会阻断发布。原实测稿的听审、权利等状态另行维护，工具支持相应素材不等于该稿已就绪。
