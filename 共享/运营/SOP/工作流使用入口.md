更新：2026-09-07。这里负责导航；具体规则只在链接指向的真源维护。

## 一篇稿怎么做

1. **定任务。** 在内容包 brief 里写清读者、要讲的事、与已有稿的区别、交付位置。用 [self-media-ops](../../../.agents/skills/self-media-ops/SKILL.md) 选择快讯、分析或局部修改路径。
2. **查资料，同时找图。** 事实进 sources，图的用途和候选进 visual-notes。优先能看清人物、原话、产品或操作结果的原始材料。选图标准见 [APPSO 内容生产 SOP](<../../../APPSO-数字资产/03-SOP/APPSO 内容生产 SOP.md>)。
3. **写与改。** 快讯用已核事实包；分析稿先定一个判断。已有正文收到修改意见时先定位小节、首句或图片，只改指定范围。去 AI 味以删多余解释为主。
4. **制作图文。** 官方图与帖子保持原始画面；笨拙涂鸦和信息图分别用自己的受控 Prompt。用实际正文位置和手机宽度看效果。
5. **交付。** 默认飞书协作预览；公众号排版走扩展或本地交接工具。长图、GIF、头尾图分别验收，具体入口见下表。飞书写入或公众号覆盖按当前任务授权执行。
6. **留记录。** 原稿、素材和代码保留原位，项目卡链接成果与关键修改。反复出现的问题再改 SOP，不把每次润色都变成新规则。

完整流程、状态和事实门：[内容工作流](内容工作流.md)。

## 桌面材料如何使用

桌面 `公众号` 文件夹作为来源留存。内容相同的规范和 Logo 只保留一个仓库真源；快讯参考原文与去 AI 味 Prompt 已存入[来源目录](../../参考/桌面公众号流程/README.md)。完整来源、SHA-256 和执行入口由[工作流输入清单](../../../tools/workflow-source-assets.json)登记。

参考原文不自动成为写作指令。快讯原文中的固定字数、热梗频率和强行反转，与现在的写作要求不一致，实际执行使用上表的快讯 Prompt。

2026-09-07，主理人明确要求这些流程、Prompt 与工具统一进入私有仓库。换机不用再从桌面找原件；不需要逐份重新确认分级。账号凭据、登录态与运行缓存仍由本机配置。

## 需要再打包时

提交后运行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools/workflow.ps1 export-workflow
```

在 output 下生成工作流源码包、1.10.3 插件包和带提交号的校验记录。只打包已提交文件，不包含文章正文、录屏、依赖或登录配置。工作流包用于备份和查阅；新机器完整安装仍优先私有 Git clone 后运行 bootstrap。插件包解压后，直接加载能看到 manifest.json 的那层目录。
