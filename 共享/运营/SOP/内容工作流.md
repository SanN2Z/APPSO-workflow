# 可迁移内容工作流

版本：3.0

更新日期：2026 年 7 月 25 日

## 目的

用最短流程完成内容任务。安全规则保留，但只在对应风险出现时检查；品牌、平台、视觉、发布和复盘不常驻普通写稿流程。

## 单一真源

| 内容 | 真源 |
|---|---|
| 安全、保密、外部操作和 Git | 根 `AGENTS.md` |
| 跨平台生命周期与核心规则 | 本文件 |
| 任务分流 | `self-media-ops/SKILL.md` |
| 平台写法 | 目标平台 `AGENTS.md` / `CONTEXT.md` |
| APPSO 专属规则 | `APPSO-数字资产/` |
| 生图、排版和发布实现 | 对应专项 SOP 与脚本 |
| 单稿事实、正文、素材和反馈 | 目标内容包 |

其他文件只保留触发条件、配置或指针，不复制完整流程。

## 七步主流程

```text
任务分流
→ 必要调研
→ 核心判断讨论（仅分析长稿）
→ 初稿
→ 事实与编辑审校
→ 排版交付
→ 实质反馈复盘
```

| 阶段 | 做什么 | 什么时候停止 |
|---|---|---|
| 1. 分流 | 判断平台、稿型、读者问题和交付目标 | 任务仍不明确时 |
| 2. 调研 | 记录会改变正文的事实、来源和限制 | 核心判断缺证据时 |
| 3. 判断 | 仅分析长稿讨论共同处境、主判断和证据 | 用户尚未确认时 |
| 4. 初稿 | 只写一个中心问题，按平台组织材料 | 事实不足或主旨分叉时 |
| 5. 审校 | 依次处理事实、结构、人话、语法和图片权利 | 有阻断项时 |
| 6. 交付 | 选择一种排版或草稿通道，先本地检查 | 没有外部写入授权时 |
| 7. 复盘 | 记录实质反馈和修复，判断是否跨稿成立 | 只有单次措辞偏好时 |

## 任务模式

| 模式 | 最小路径 |
|---|---|
| 想法 | 建立最小 `draft.md`，不创建整套内容包 |
| 调研 | `draft.md` + `sources.md` |
| 普通改字 | 目标稿件 + 相关局部检查 |
| 新稿 | brief、sources、draft；其余按阶段增加 |
| 分析长稿 | 新稿路径 + 判断共创 |
| 生图 | 视觉计划 + manifest + Image2 预检 |
| 进入 `ready` | 完整事实、权利、审校、终校和平台校验 |
| 交付或发布 | 发布配置、授权和真实记录 |
| 实质反馈 | 单稿 retrospective；达到晋升条件后才碰中央 SOP |

## 状态

`idea → research → draft → fact_checked → editorial_review → ready → published → archived`

| 状态 | 最低含义 |
|---|---|
| `idea` | 有题目或问题，尚未承诺交付 |
| `research` | 正在建立来源和事实底座 |
| `draft` | 正文已形成，仍允许结构调整 |
| `fact_checked` | 时效、数字、引语、身份和口径已复核 |
| `editorial_review` | 正在处理结构、人话、语法、视觉与平台适配 |
| `ready` | 所有发布门通过，等待用户决定是否发布 |
| `published` | 有真实链接或用户明确确认 |
| `archived` | 本轮结束，后续问题另开周期 |

状态写在 `draft.md` frontmatter。`publish-record.md` 只记录真实交付和发布事件。

## 核心规则

### CORE-PROMISE-001｜一个承诺

- 触发：标题、开头、正文或结尾出现多个并列主旨。
- 动作：只留一个读者能复述的问题，其他内容降为证据或删除。
- 通过：标题、证据和末句回答同一个问题。

### CORE-FACTCARD-001｜最小事实底座

- 触发：判断依赖读者不熟悉的主体、事件或术语。
- 动作：分析前补足理解判断所需的最少事实。
- 通过：圈外读者能说清谁、发生了什么、为什么与后文有关。

### CORE-HUMAN-001｜材料关系优先

- 触发：文章按来源分成几份小报告，或靠套话、短句和口语硬做节奏。
- 动作：先明确每段承担事实、机制、限制或后果中的哪项工作，再处理句子。
- 通过：隐藏小标题后仍能复述材料的推进关系或共同比较尺度。

### CORE-COPYEDIT-001｜最终正文终校

- 触发：结构和事实稳定，准备进入 `ready`。
- 动作：逐句检查语法、指代、比较、连接、标点和术语，并锁定正文哈希。
- 通过：无 open 缺陷，正文与终校哈希一致；正文再改就重新终校。

## `ready` 硬门

- 事实和来源可追溯，时效信息已重开核查。
- 发布图片在包内，来源、权利和允许平台明确。
- 公司、个人和不同平台的成稿没有混用受限表达或资产。
- 中文排版、临时路径、凭据和敏感信息检查通过。
- 结构、人话、AI 痕迹诊断和逐句终校没有阻断项。
- 目标平台校验器通过；警告已处理或说明。

## 反馈升级

```text
原始反馈
→ 单稿症状与修复
→ 第二个独立案例或严重安全事件
→ 明确触发、动作、通过条件和反例
→ 修改最窄的权威真源
```

普通措辞偏好留在案例。只有跨稿机制或事实、权利、隐私、凭据、发布等严重问题进入 SOP。
