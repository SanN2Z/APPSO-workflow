# 可迁移内容工作流

版本：2.2

更新日期：2026 年 7 月 23 日

## 定位

本文件定义与品牌、平台和工具无关的内容生产核心。项目专属规则通过 adapter 接入，避免把 APPSO、微信公众号、X、具体目录或某次反馈写死在通用流程里。

## 两层架构

### Portable core

- 内容状态与进入 / 退出条件。
- brief、来源、正文、素材、审校、发布和复盘的交付合同。
- 事实、版权、语法、敏感信息和外部操作硬门。
- 反馈入库、SOP 升级、回归检查和归档节奏。

### Project adapters

- 根 `AGENTS.md`：项目边界、状态、保密和 Git 规则。
- 平台 `AGENTS.md` / `CONTEXT.md`：读者、稿型、长度、视觉和发布方式。
- `APPSO-数字资产/`：公司栏目、品牌、实习反馈和内部 SOP。
- `.agents/skills/self-media-ops/`：生产执行器。
- `.agents/skills/content-retrospective/`：反馈复盘与 SOP 进化执行器。
- `.agents/skills/insight-to-asset/`：跨周期洞察实验与资产化执行器。

迁移到新项目时优先复用 portable core，再为新品牌、平台、状态字段、目录和审批人建立 adapter。

## 洞察到资产的上游入口

内容工作流解决「如何完成和复盘一次内容周期」；[洞察实验室](../../研究/洞察实验室/README.md)解决「一个跨周期机制是否真的成立」。二者通过引用连接，不复制真源：

```text
抽象判断
→ 范围、机制、预测和反证
→ 一个现实内容实验
→ 内容包 retrospective
→ 支持 / 反对 / 中性证据
→ 局部支持 / 修正 / 否定
→ 可复用资产
→ content-retrospective 晋升门
```

洞察记录不能直接把规则写进 SOP。只有现实反馈被忠实记录、机制达到相应证据等级，并具备适用范围、失败信号和回归检查后，才由 `content-retrospective` 修改最窄的权威真源。

## 生命周期

```text
idea → research → draft → fact_checked → editorial_review → ready → published → archived
                                      ↘ feedback / retrospective ↗
```

状态只表达已经通过的门，不表达「正在努力」。目录保持稳定，状态写入内容元数据与发布记录。

| 状态 | 最低进入条件 | 退出条件 |
|---|---|---|
| `idea` | 有读者问题和选题来源 | 值得调研且不重复 |
| `research` | 建立事实与来源表 | 核心表述有足够证据 |
| `draft` | brief、结构和主要素材任务明确 | 正文完成自检 |
| `fact_checked` | 时效、数字、引语、身份和口径复核 | 事实缺陷关闭 |
| `editorial_review` | 人话、结构、冷读、逐句终校和版权检查开始 | 所有发布门通过 |
| `ready` | 事实、版权、语法、路径、敏感信息和平台预览通过 | 获得发布授权 |
| `published` | 有真实链接或用户明确确认 | 完成复盘和保存必要数据 |
| `archived` | 复盘完成，后续动作转入新任务 | 需要重启时建立新周期 |

## 标准交付合同

每个内容单元至少能恢复以下信息，文件名可由 adapter 映射：

- **Intent**：读者、唯一问题、承诺、排除项和期限。
- **Evidence**：来源、访问日期、支持表述、口径和限制。
- **Copy**：当前正文真源、版本和状态。
- **Assets**：文件、来源、权利人、修改、平台和权利状态。
- **Review**：事实、结构、人话、语法、版权和平台门禁。
- **Release**：目标账号、外部动作授权、真实链接和日期。
- **Retrospective**：反馈、版本 diff、因果链、SOP 变更和下次复盘日。

派生产物必须可从真源重建，不能反向成为编辑真源。

## 十阶段闭环

| 阶段 | 核心动作 | 主要产物 | 失败时 |
|---|---|---|---|
| 1. 准入 | 定义今天新增、读者问题和来源可得性 | 选题卡 | hold / reject |
| 2. 调研 | 拆原子事实，区分事实、自报、第三方、推断和玩梗 | 来源表、事实表 | 保持 `research` |
| 3. 锁稿 | 只保留一个标题承诺和中心问题 | brief、论证图 | 不写完整稿 |
| 4. 视觉 | 为每张图定义论证任务和权利状态 | 素材任务、manifest | 权利未清不进入 `ready` |
| 5. 写作 | 按平台 adapter 组织正文 | draft | 回到 brief 修正 |
| 6. 人话审校 | 自检、AI 模式诊断、修复和独立冷读 | review | 重大缺陷保持 open |
| 7. 逐句终校 | 检查语法、指代、比较、标点和术语，锁正文哈希 | copyedit | 正文改动后重跑 |
| 8. 发布准备 | 校验路径、预览、字段和外部动作 | preview、release config | 默认 dry-run |
| 9. 发布记录 | 只在授权后执行并记录真实结果 | publish record | 不猜测发布状态 |
| 10. 复盘进化 | 收集反馈、数据与 diff，验证并升级 SOP | retrospective、SOP change | 单例留在案例 |

## 反馈闭环

稿件交付、发布或收到用户修改意见时，使用 `content-retrospective`：

```text
原始反馈
→ 原子反馈台账
→ 症状 / 损失 / 根因 / 修复 / 验证
→ case_only / watch / SOP candidate
→ 规则合同
→ 回归检查
→ 后续案例验证
```

默认至少 2 个独立案例证明同一根因，才升级为通用 SOP。事实、版权、隐私、凭据、发布和不可逆外部操作可按严重性单案升级。用户或编辑的具体句子、公司终稿和内部数据不进入通用模板。

## 可执行核心规则

### CORE-PROMISE-001｜唯一内容承诺

- 触发：标题、开头、正文框架或结尾出现多个并列主旨。
- 动作：在 brief 锁定一个可复述承诺，其他钩子删除或下沉为证据。开头从第一段开始服务该承诺；结尾只兑现原承诺，未在 brief 承诺的方法、清单或第二结论不得临时加入。
- 通过：冷读者能复述唯一问题；开头、证据和末句都服务它；结尾回答同一承诺并新增信息。
- 失败：复述出现多个主旨，开头迟迟不进入主要承诺，或最后一句重复 / 抢走中心判断；观点稿完成收束后又启动一套个人方法论。

### CORE-FACTCARD-001｜最小共同事实底座

- 触发：后文判断依赖陌生产品、机构、事件或协议。
- 动作：在分析前补足改变理解所需的最小事实，不固定为「60 秒」或特定卡片形式。
- 通过：圈外冷读能说清主体、发生了什么和理解判断所需的关键事实。
- 失败：读者必须依赖发布会、旧稿或私有提纲才能理解后文。

### CORE-HUMAN-001｜结构性人话检查

- 触发：开头口语但正文报告化、段落重复小结、结尾复述或笑话抢走判断。
- 动作：先修复段落工作与材料关系：线性论证按读者下一问推进，平行证据共享明确的问题、指标或比较尺度；隐藏小标题检查顺序或并列关系是否仍成立；再检查抽象词、自然转场、短句任务、口语落点、强修辞稀缺性、全文声音与结尾。
- 通过：独立冷读能重建问题、判断、证据、限制、读者后果和末句信息；线性材料有可复述的依赖，平行材料有统一比较尺度，每个独立短句和口语都有具体信息任务。
- 失败：只能靠换词改善；按来源写成可任意交换的几份小报告；口语均匀撒布或强对比反复承担转场；删掉结尾反而让主旨更强。

### CORE-COPYEDIT-001｜逐句终校与正文哈希

- 触发：结构、事实和人话检查稳定，准备进入发布审计。
- 动作：逐句检查并登记缺陷；修复后重跑全篇，锁定最终正文哈希。
- 通过：无 open copyedit 缺陷，正文与终校哈希一致，内容包验证通过。
- 失败：正文改动后沿用旧签字，或以冷读代替句法检查。

## 固定节奏

- 每次交付或发布：初始化本轮复盘记录。
- 每次收到反馈：同一工作会话完成登记与去向判断。
- 发布约 7 天后：复核早期评论、数据和执行问题。
- 每周：处理到期复盘与 SOP 候选。
- 每月：审计 SOP 重复、冲突、失效规则和迁移候选。
- 每季度或迁移前：拆分 portable core 与 project adapters，删除受限证据并做新项目适配测试。

## 迁移检查

- [ ] 状态、角色、路径和平台名已参数化。
- [ ] 保密等级和外部操作授权有 adapter。
- [ ] 事实、版权、语法和发布门仍可验证。
- [ ] 核心 skill 不依赖原公司终稿或私有数据。
- [ ] 至少有一个最小内容包模板和一个反例测试。
- [ ] SOP 规则能追溯来源案例，但迁移包不暴露受限内容。
- [ ] 新项目明确配置读者、平台、审批人、发布工具和数据口径。
