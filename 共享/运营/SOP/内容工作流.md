# 可迁移内容工作流

版本：5.4

## 目的

用最短流程完成值得写的内容。把「想什么」「与用户锁定什么」「并行产生哪些候选」「选哪一篇」和「能不能交付」拆开：不让第一条写作路径自动成为终稿，也不让硬门反过来支配文章结构。

## 五层主流程

```text
自由判断层：这件事值不值得写
→ 写前定调层：公众号分析稿与用户锁定故事合同和表达任务
→ 并行候选层：有哪些真正不同的完整写法
→ 匿名评选层：哪一篇值得继续，或者一篇都不要
→ 硬门检查层：胜出稿能不能准确、安全地交付
```

| 层 | 做什么 | 什么时候停止 |
|---|---|---|
| 1. 自由判断层 | 读材料、补必要研究，找出来源之外的新增判断、证据关系和读者后果 | 只能复述来源、放大热点或讲通用背景时，停在 `research`；不要用完整结构掩盖价值不足 |
| 2. 写前定调层 | 公众号新分析稿先与用户锁定故事合同：一句话主线、叙事发动机、四格叙事链、最强对手、标题方向与暂定小标题。高显著性修辞只记录具体表达任务 | 共创尚未确认，任一节写不出下一节为何必须回答，或最强对手为空且未降级时，停在本层，不启动候选正文 |
| 3. 并行候选层 | 冻结同一份读者、材料、事实边界、叙事链与故事合同，调用多个隔离写作 Agent 并行生成 3—5 篇完整候选；默认 3 篇。候选冻结前只自查事实边界与骨架差异 | 候选共享同一骨架，差异只能用「更口语／更正式」描述，或事实越出冻结边界时，整批不进入评选；按缺陷退回第一或第二层 |
| 4. 匿名评选层 | 隐去作者与提示词，由 2 个未参与生成的评审 Agent 并行冷读；分别判断事实纪律、论证与叙事、跨题可移植的表演句，每人选择 1 篇或「一篇都不要」。意见分歧时，只对入围稿做一次独立决选；禁止把落选稿拼成一篇 | 没有候选同时通过事实边界、必要顺序、材料取舍和重大表演句检查时，选择「一篇都不要」；不能为了完成流程硬选最好看的烂稿 |
| 5. 硬门检查层 | 只对胜出稿核事实与权利，运行一次完整结构／表达诊断，冷读后逐拍对照叙事链，并检查候选稿到成稿的具体性守恒；修复后只复核修复点，终校前扫描一次项目词表 | 任一阻断项未关闭时，不进入 `ready`；硬门只决定能否推进，不替文章生成观点和章节 |

五层是工作模式，不替代内容状态。`idea` / `research` 主要发生在第一、二层；候选生成与评选发生在第三、四层，文件暂存于 `research/candidates/<round>/`；只有胜出稿才原样进入 `draft.md`；`fact_checked` / `editorial_review` / `ready` 主要接受第五层检查。正文一旦暴露「不值得写」的问题，可以从任何状态退回第一层。

写前定调层的触发、豁免、共创内容和通过条件以 `PROJECT-WECHAT-JUDGMENT-001` 为唯一真源。用户确认或修改并锁定前，不生成完整候选，不把空白问题丢给用户。

候选层优先并行：默认同时启动 3 个隔离写作 Agent；只有材料确实支持更多互斥执行路线时才扩到 4—5 篇。所有候选共享用户已确认的故事合同、四格叙事链与叙事发动机，但不得读取其他候选或共享句子级计划；差异应落在人物／场景选择、信息揭示顺序、技术压缩和具体叙事执行上。每名候选作者冻结前只确认事实没有越出冻结边界、没有复用冻结输入之外的现成骨架。受并发槽位限制时分成最少波次，不让一个 Agent 顺序连写多篇。评审同样并行启动，生成 Agent 不得参与评选。

普通公众号分析稿走 40 分钟文本快线。必要广搜、价值初筛和写前叙事／表达定调发生在 Pre-T0；用户确认故事合同且材料足以开工的时刻才记为 T0，到一篇经过选稿和胜出稿必要事实复核、可供用户阅读的正文交付为 T1。默认预算为 0—8 分钟补检并冻结候选输入、8—22 分钟 3 个写作 Agent 单波并行、22—28 分钟 2 个评审 Agent 单波盲选、28—38 分钟只核胜出稿、38—40 分钟整理交付。可以提前完成，不为凑满 30 分钟而等待；用户讨论等待不冒充出稿耗时，也不得用增加串行 Agent 或跳过事实检查来假装达标。

排版交付和实质反馈复盘发生在五层之后。它们是生命周期动作，不是创作层。

## 任务模式

| 模式 | 最小路径 |
|---|---|
| 想法 | 建立最小 `draft.md`，先做价值判断，不创建整套内容包 |
| 调研 | `draft.md` + `sources.md`；记录哪些证据会改变判断 |
| 普通改字 | 目标稿件 + 相关局部检查 |
| 新分析稿 | 第一层通过后按 `PROJECT-WECHAT-JUDGMENT-001` 进入写前定调；用户锁定故事合同后，才并行生成至少 3 篇候选，候选只做事实边界与骨架差异自查，盲选胜出后写入 `draft.md` |
| 分析长稿 | 默认走五层流程；微信公众号稿在胜出稿阶段运行一次完整结构／表达诊断，终校前再执行一次项目词表附录扫描 |
| 结构性重写 | 保留已核材料，先重开并与用户确认故事合同及表达任务，再并行生成 3—5 篇完整候选；不让原稿自动占据种子位 |
| 其他稿型明确要求共创 | 可使用同一共创门；它帮助锁定选择，不替代价值判断 |
| 明确要求文风实验 | 第四层已经选出实质初稿后，才可选用笨拙写作实验；完整人话诊断仍按胜出稿硬门执行 |
| 生图 | 视觉计划 + manifest + Image2 预检 |
| 进入 `ready` | 完整事实、权利、审校、终校和平台校验 |
| 交付或发布 | 发布配置、授权和真实记录 |
| 实质反馈 | 单稿 retrospective；达到晋升条件后才碰中央 SOP |

## 状态

`idea → research → draft → fact_checked → editorial_review → ready → published → archived`

| 状态 | 最低含义 |
|---|---|
| `idea` | 有题目或问题，尚未承诺交付 |
| `research` | 正在建立来源和事实底座 |
| `draft` | 正文已形成，仍允许结构调整 |
| `fact_checked` | 时效、数字、引语、身份和口径已复核 |
| `editorial_review` | 正在处理结构、人话、语法、视觉与平台适配 |
| `ready` | 所有发布门通过，等待用户决定是否发布 |
| `published` | 有真实链接或用户明确确认 |
| `archived` | 本轮结束，后续问题另开周期 |

状态写在 `draft.md` frontmatter。`publish-record.md` 只记录真实交付和发布事件。

## 核心规则

`CORE-VALUE-001` 是第一层停写门；`PROJECT-WECHAT-JUDGMENT-001` 与 `CORE-CHAIN-001` 锁定第二层；`CORE-SELECTION-001` 管理第三、四层；胜出稿由 `PROJECT-WECHAT-RHYTHM-001`、`PROJECT-WECHAT-PRAGMATIC-001` 与 `PROJECT-WECHAT-CONCRETE-001` 完成一次结构／表达诊断，`PROJECT-WECHAT-AI-LEXICON-001` 只在终校前追加一次词表扫描；`PROJECT-WECHAT-RED-CORPUS-001` 仅作可选正向参考；`CORE-TIME-001` 约束确认后的文本墙钟时间。任何规则都不能把材料不足的选题包装成长文。

### CORE-VALUE-001｜值得写门

- 触发：准备把热点、帖子、模型卡、论文、产品更新或一组来源写成分析稿。
- 动作：先用自己的话回答四件事：来源已经告诉了读者什么；本文新增的非显然判断是什么；哪组证据关系支持或限制它；这个判断会改变读者的理解、选择或下一步行动什么。再写出最强替代解释。
- 通过：新增判断不是来源改写或通用常识；至少一条证据会真实改变判断强度；读者后果具体；反证出现时知道怎样改口。事实、判断和推断彼此可辨。
- 失败：只能补背景、讲定义、扩大叙事、重复厂商口径，或靠钩子、网梗、第一人称和完整结构制造「像一篇文章」的感觉。此时停在 `research`，允许降级成事实简报或不写。
- 反例：纯事实快讯、状态通知和资料索引不要求非显然判断，但必须诚实标明稿型，不能伪装成分析长稿。

### CORE-PROMISE-001｜一个承诺

- 触发：标题、开头、正文或结尾出现多个并列主旨。
- 动作：只留一个读者能复述的问题，其他内容降为证据或删除。
- 通过：标题、证据和末句回答同一个问题。

### CORE-HOOK-001｜首屏压力

- 触发：已经通过 `CORE-VALUE-001` 的分析稿先播日期、公司、融资、履历或背景，读者看完首屏仍不知道哪里反常、有什么代价或为什么要继续看。
- 动作：只选一个可见动作或事实，在首屏形成「发生了什么 → 哪里不对劲或尚未解决 → 后文要追什么」；履历、历史和定义延后到第一次真正需要它们的位置。
- 通过：冷读者看完前三段，能说清主体正在做什么、局面哪里反常，以及继续读会得到什么答案。去掉名气、金额和热点词的光环后，那个具体冲突仍然成立。纯事实快讯可以直接报事件。

### CORE-CHAIN-001｜叙事链与写后对照

- 触发：公众号分析稿进入写前定调，以及胜出稿定稿前。
- 数据结构：故事节拍必须以「叙事链表」记录，每一节四格全部必填：① 本节新增的事实或动作；② 它让局面发生了什么变化；③ 它留下了什么未解决的问题；④ 下一节为什么必须回答这个问题。第 ④ 格写不出来，说明两节是并列关系：合并、重排，或改用「平行比较」结构并声明共享尺度。
- 平行比较例外：明确承诺清单或对照的稿型可以使用并列章节，但必须在链表头部声明唯一共享尺度，即同一问题、同一量纲或同一决策用途；每节都在这把尺子上给出结论。
- 写后对照：胜出稿进入 `editorial_review` 时，审核者先独立冷读，再把成稿逐节映射回叙事链表，逐拍检查「上一节留下的问题，这一节是否真的在回答」。遮住小标题读，任何一节能前移或删除而文章不塌，判结构缺陷打回。成稿偏离链表本身不是缺陷，但偏离后链条断裂是缺陷，且偏离须在 `review.md` 记录。
- 叙事发动机：从谜团揭示、人物追求、问题升级、实验验证、对照决策五种发动机中选一条为主，全文只允许一条。
- 通过：叙事链四格完整；线性稿逐节形成「回答上一问并逼出下一问」的依赖，平行稿逐节使用同一尺度；写后映射已记录且没有开放的链条断裂。
- 失败：节拍表退化为只有「写什么／不写什么」的内容清单；成稿与链表无人对照；用「文章大体顺」代替逐拍检查。

### PROJECT-WECHAT-JUDGMENT-001｜公众号写前共创门（试运行项目配置）

- 触发：公众号新分析稿与结构性重写，通过价值门后默认触发写前共创门。豁免：事实快讯、状态通知、纯翻译、固定数据表、资料索引、普通改字；用户在当前任务明确说「直接写」时跳过并记录。
- 动作：完成必要广搜后，Codex 主动提交写前共创包，不把空白问题丢给用户。共创包至少包含一个推荐方案：读者真正要解决的问题、唯一核心判断、一句话故事主线、读者追问链、`CORE-CHAIN-001` 四格叙事链、叙事发动机、开场压力、结尾落点、必要事实锚点和明确不写的方向；另列本文最强的反例或对手（最强替代解释、最硬反方证据或最可能推翻主判断的案例），并指出在第几拍正面接它。故事节拍成立后再补 2—3 个标题和暂定小标题；重点修辞另写具体表达任务和指向。存在真实分歧时再给最多 2 个替代框架。根据用户反馈修改并记录到 `research/judgment-workshop.md`。
- 通过：用户明确确认或修改后的标题方向、核心判断、故事主线、追问链、叙事发动机、四格叙事链和暂定小标题均已记录；最强对手非空，或稿件已明确降级；重点修辞有具体任务或明确不预设；`user_confirmed: true`，并有确认日期；候选轮次引用这份锁定记录。
- 失败：未讨论就出现完整候选或正文；只问「你想怎么写」而不提供推荐方案；只列漂亮小标题却说不清前后依赖；用户已经修改中心但冻结输入仍保留旧框架；用禁写边界清单删光反方材料，使文章从设计阶段就没有对手。
- 反例：纯事实快讯可以在事实核验后直接成稿；讨论中用户明确说「按你的方案直接写」即视为当轮确认，不必为了形式继续追问。
- 回归：候选轮次必须记录故事合同引用与用户确认日期；若连续 3 篇中讨论成本高于避免的结构返工，或用户确认后仍连续 2 篇要求更换中心，复核并收窄该门。

### PROJECT-WECHAT-PRAGMATIC-001｜语用必要性（试运行项目配置）

- 触发：公众号分析稿胜出并进入 `editorial_review` 的一次完整诊断；检查高显著性转折、抽象判断、总结、隐喻、指示词或疑似「金句」。本规则不依赖关键词命中或 AI 检测分数。
- 动作：引用具体句子，并依次回答：作者此刻必须传递的具体任务是什么；抽象词与「这里／背后／这一刻」指向什么对象、动作或决定；整句能否原封不动移到另一篇科技稿；它是在呈现冲突还是自我宣布「这里有张力／意义／戏剧性」；删除后损失事实、判断、关系或后果，还是只损失文章腔；朗读时像在解释具体问题，还是像在完成写作任务。修复顺序为删除、改成具体冲突或决定、确有必要才保留。
- 通过：保留句有明确表达任务和具体指向，删除会损失真实内容；评审能用原句和上述测试解释判断。必要路标、准确术语、字面事实、来源引语和持续参与后文论证的修辞均可通过。
- 失败：句子只宣布张力、意义、差距或态度，却没有新增对象、动作、证据、关系或后果；可跨题移植且删除无内容损失；只用「更像人／不像 AI」判退；或所有候选都重复同一类重大文章表演句却仍被迫选出赢家。
- 反例：「为山九仞，功亏一篑」若用来建立「最后一步未完成就不算交付」的问题模型，下一句立即映射到周报、纪要、图表、发群或建待办等动作，且这个模型继续参与后文论证，可以保留。该反例不等于每篇都要引用古语、名言或热梗。
- 回归：使用 `.agents/skills/self-media-ops/references/wechat-pragmatic-regression.yml`，在 `review.md` 留下判断。累计 3 篇符合条件的公众号分析稿后，于 2026 年 8 月 25 日前复核误杀、漏判和返工成本；目前不宣称该机制已证明有效。

### PROJECT-WECHAT-RHYTHM-001｜句法节奏指纹（项目配置）

- 定位：AI 味的主要载体是句法节奏骨架，不是具体词汇。本规则是表达层主检查；词表 `PROJECT-WECHAT-AI-LEXICON-001` 降为终校附录。
- 触发：胜出稿进入 `editorial_review` 的一次完整诊断。
- 动作：逐类引用原句并做删除测试。只有删掉或改写后损失的只是文章腔，而不是事实、判断、关系或后果，才成立为缺陷。六类指纹是：① 三连排比／三项并列，单篇出现 3 处及以上时整体预警并逐处检查；② `A；B；C` 整齐三段式或 `A；B` 镜像对偶；③ 段末抽象升华，同一抽象归纳全文第二次出现即违规；④ 「不是 A 而是 B」「像 A，不太像 B」「正因为 A，反而 B」「A 来得及，B 来不及」「与其说 A，不如说 B」等对称翻转；⑤ 将「当然，这仍然是我的判断」「其他解释也成立」一类限定单独成段或固定放在小节倒数第二段，限定应压进陈述句本身；⑥ 「这直接关系到」「值得注意的是」「更实在／更关键」等只宣布重要性、不新增对象或证据的空转宣告。
- 修复：依次尝试删除、改成有具体对象的陈述、确有真实表达任务才保留并记录任务与指向。完整执行细则见 `.agents/skills/self-media-ops/references/wechat-ai-pattern-pass.md`。
- 通过：六类均已检查；所有判定都有原句与删除测试；开放的重复节奏、抽象升华、对称翻转、免责段或重要性空转均已关闭。
- 失败：把命中直接当缺陷而不做删除测试；只换禁词不改句法；用 AI 检测器分数、英文词表、句长／标点阈值、强加口语、错字或第一人称判断通过；借命中推断作者身份。
- 回归：使用 `.agents/skills/self-media-ops/references/wechat-rhythm-regression.yml` 做人工语义回归。

### PROJECT-WECHAT-CONCRETE-001｜具体性守恒（项目配置）

- 定位：真实对象、数字、场景、失败、玩笑和带体温的比喻是稿件人味的主要来源，是编辑阶段的保护对象，不是压缩对象。
- 触发：候选稿胜出后的任何压缩、去 AI 味、终校编辑，以及结构性重写。
- 动作：编辑压缩时优先删除抽象概括句、段末升华句和重复归纳。删除任何具体细节必须在 `review.md` 记录一行理由。同一抽象归纳全文最多出现一次。审核者 diff 候选稿与成稿，统计被删内容的具体／抽象比例；净效果为「删具体、留抽象」时判编辑方向缺陷，打回重编。
- 通过：保留或删除的具体细节均有可追溯理由；压缩净效果没有用抽象格言替代真实纹理；限定条件留在它约束的陈述句内。
- 失败：为控制篇幅删掉具体场景而保留概括它的格言句；把候选稿唯一的笑点或真实纹理换成干净的抽象句；把限定条件从陈述句里拆成独立免责段。
- 边界：事实错误、权利问题或跑题的具体细节可以删除，理由写「事实／权利／跑题」即可；本规则不要求堆砌细节，只禁止编辑方向反转。

### PROJECT-WECHAT-AI-LEXICON-001｜公众号表达禁用（用户反馈驱动的项目配置）

- 定位：既有事实 gate 负责真实性、证据与边界；本规则只处理传播成品的表达 loss。它是终校阶段的附录检查，不是候选与评审阶段的主检查；表达层主检查是 `PROJECT-WECHAT-RHYTHM-001` 与 `PROJECT-WECHAT-CONCRETE-001`。主理人对真实稿件明确说一次「不喜欢」即可形成或维持项目禁用，不要求先达到跨稿重复、完成机制解释或取得学术共识。
- 触发：公众号分析稿胜出并完成结构／表达修复后、逐句 copyedit 前运行一次；或用户／读者明确否定某个句式、词簇、语气框架和收尾方式。
- 动作：加载 `.agents/skills/self-media-ops/references/wechat-expression-library.yml` 的 `wechat_analytical` adapter。公众号当前 24 组全部进入 `ban_entry_ids`，`review_entry_ids` 为空；共享表达库里的 P0／P1 只保留来源与其他项目适配意义，不构成公众号放行层。命中不得静默留在未加引号的作者正文：删除、改成主体／动作／尺度／条件／结果明确的正面陈述，或记录窄豁免。`WX-EXPR-012`—`013`、`017`—`020` 原复核组同样执行；真实账单、考试交卷、来源原话、官方术语和精度关键用法只通过明确豁免保留。`WX-EXPR-015` 的「不是 A，而是 B」及其变体默认改写，不用对称否定制造观点。
- 通过：作者正文没有未处理的禁用表达；每个保留项都有 entry ID、完整句、上下文、豁免类型、不可替代的信息任务和批准人；语义复核项有具体修复或放行理由。用户再次明确不喜欢时，以新反馈为准继续修改，不用旧规则反驳验收意见。
- 失败：要求用户先证明「为什么不喜欢」才修改；拿社区共识或论文覆盖当前项目喜好；把禁词换成同义套话；用随机口语、碎句、错字或标点噪声伪装成人话；或把命中用作 AI 作者身份、代写与诚信判断。
- 窄豁免：来源原话；官方名称、界面文字、法律／标准／规范原文或必须逐字准确的术语；按本义使用且改写会损失准确性的字面事实或具体对象名称；改写会损失精度的事实排除、术语消歧和互斥分类；承担真实依赖关系的操作步骤、法规条件或同尺度分类。能准确改成正面陈述时不豁免。
- 证据顺序：用户修改与明确喜好是主损失；跨内容包反馈用于验证；中文社区、编辑经验和 GitHub 只扩充候选；学术研究只提供组合特征与误判边界。完整调研见 `共享/运营/复盘/2026-08-03-中文 AI 表达模式广搜与禁用边界.md`。
- 回归：规则变化时人工运行 `.agents/skills/self-media-ops/references/wechat-expression-ban-regression.yml`。累计 3 篇适用稿后复核再次删改、读者冷读、误伤与同义套话迁移；新的明确厌恶可以立即收紧，不必等待复核日期。

### PROJECT-WECHAT-RED-CORPUS-001｜公众号红库（用户反馈驱动的正向项目配置）

- 定位：红库是可选正向参考，鼓励由当前稿件真实动作、对象、数字、摩擦、边界和作者判断长出的表达；它不是候选、评审或硬门的必经材料。红项是表达动作，不是「更像人」的固定词句，也不自动抵消项目词表命中。
- 触发：胜出稿修复时，编辑认为现有事实支持更具体的表达动作；用户／读者明确喜欢某种有内容落点的写法时，也可收录为项目正向配置。
- 动作：可选加载 `.agents/skills/self-media-ops/references/wechat-red-black-corpus.yml`。先确认事实和说话任务，再从红项选择与当前材料匹配的动作，用本稿自己的主体、对象、时间、数字和结果表达；若未加载或没有适用机会，无须留痕。
- 通过：红项承担可复述的信息任务，删除会损失事实、判断、关系或读者后果；第一人称、现场、时间、数字、失败和情绪均可追溯；来源示例没有被照抄。整篇零命中红项也可以通过。
- 失败：规定每篇或每节最低红项数量；照抄库中例句或第三方原句；虚构第一人称、测试、失败、现场和数字；用年度热梗、碎句、错字或表情符号制造网感；把黑词机械替换成红库套话；按红项数量判断作者身份或稿件质量。
- 边界：红库不要求口语化，不保证传播效果，也不替代事实、权利、隐私、语法、语用必要性和用户验收。圈内活词每次按目标读者、平台和日期重审；没有真实机会时不加。
- 回归：规则变化时人工运行 `.agents/skills/self-media-ops/references/wechat-red-corpus-regression.yml`。机器可校验结构、来源索引和禁配额字段；语义放行仍需人工核对上下文。效果命题登记为 `INSIGHT-003`，在后续 3 篇适用稿上前瞻观察，目前只称项目配置，不称已验证方法。

### CORE-SELECTION-001｜并行多稿盲选（实验性）

- 触发：公众号新分析稿，或主判断、入口、章节关系需要重做的结构性重写；必须已经通过 `CORE-VALUE-001`，并通过 `PROJECT-WECHAT-JUDGMENT-001` 锁定用户确认的故事合同。普通改字、事实快讯、状态通知、资料索引和固定格式清单不触发。
- 动作：冻结同一份用户确认故事合同、`CORE-CHAIN-001` 四格叙事链、叙事发动机、来源材料、可用事实与禁写边界；优先同时启动 3 个隔离写作 Agent，确有更多互斥执行路线时扩到 4—5 个。每个 Agent 只交一篇完整正文与隐藏事实映射，不得读取其他候选、共享句子级计划或顺序续写；冻结前只自查事实是否越出边界、骨架是否复用了冻结输入之外的现成大纲。候选匿名后，由 2 个未参与生成的评审 Agent 分别判断三项：事实是否遵守冻结边界；论证与叙事是否成立，包括对叙事链的粗查；是否存在跨题可移植的表演句，须引用原句。评审并行选择 1 篇或「一篇都不要」；分歧时对入围稿做一次独立决选。
- 通过：至少 3 篇候选遵守同一故事合同，并在场景与人物选择、信息揭示、技术压缩或叙事执行上存在可说明的非词面差异；评选理由落在读者实际获得的新认识、段落必要顺序、可删除背景、事实／推断纪律和可引用的跨题表演句。笼统的「更顺」「更像人」「更像 AI」仍然无效。选择记录可追溯；胜出稿在评选冻结后未经拼接，原样进入 `draft.md`。
- 失败：故事合同未获用户确认就启动写作；多个 Agent 写出同一骨架的换词稿；候选越出事实边界或复用现成大纲；生成 Agent 参与评选；评审看到作者、提示词或其他评语；没有「一篇都不要」出口；拿笼统语气印象冒充具体句证；所有候选都有重复的重大文章表演句却仍硬选；或把多篇优点拼成一篇。任一出现都不算完成评选。
- 反例：标题备选、单段开头、纯翻译、固定数据表和一句话快讯可以在一个 Agent 内比较局部版本，不必生成 3 篇完整稿。
- 回归：每轮保留用户确认的故事合同及日期、匿名候选、分支隔离说明、两份原始评语、决选记录、胜出理由和「none」判定；后续若连续 2 个独立内容包仍需结构性重写，或评审只选出表面更顺但同样空洞的稿件，暂停该层并复核成本。

### CORE-TIME-001｜40 分钟文本出稿

- 触发：普通公众号新分析稿已完成必要广搜，且用户确认的故事合同与可检索材料均已冻结；目标是交付可冷读的文本初稿，不含讨论等待、生图、排版、上传和发布。
- 动作：广搜、价值初筛和用户共创发生在 Pre-T0；用户确认故事合同后启动 T0。第 8 分钟前完成补检并冻结候选输入；第 22 分钟前用默认 3 个写作 Agent 单波并行冻结候选；第 28 分钟前用 2 个新评审 Agent 单波完成选择或 none；第 38 分钟前只对胜出稿做必要事实复核；最迟第 40 分钟交付。5 个候选不得成为突破时限的理由。
- 通过：T1 − T0 不超过 40 分钟，并记录 T0、候选冻结、选稿冻结、T1 与实际并发波次；早于 30 分钟完成无需等待。
- 失败：未获得用户确认就启动 T0；第 8 分钟仍无法把确认后的故事合同映射到冻结材料；候选或评审被串行执行；为了赶时限跳过时效事实、数字、身份或引语核查；或第 40 分钟仍没有胜出稿／明确 none。价值门失败时应在 Pre-T0 降级或停写，不能用剩余时间补出一篇空稿。
- 例外：医疗、法律、金融建议、受限公司材料、密集数据核验或来源尚不可得的题目，不静默牺牲硬门追时限；应在 8 分钟内缩窄范围、降级稿型，或明确告知转入慢线。若任务同时要求图片，视觉检索与制作须从研究阶段并行，文本 SLA 不自动扩展为整包 SLA。

### CORE-FACTCARD-001｜最小事实底座

- 触发：判断依赖读者不熟悉的主体、事件或术语。
- 动作：分析前补足理解判断所需的最少事实。
- 通过：圈外读者能说清谁、发生了什么、为什么与后文有关。

### CORE-HUMAN-001｜材料关系优先

- 触发：已经通过 `CORE-VALUE-001` 的文章按来源分成几份小报告，或靠套话、短句和口语硬做节奏。
- 动作：先明确每段承担事实、机制、限制或后果中的哪项工作，再处理句子。
- 通过：隐藏小标题后仍能复述材料的推进关系或共同比较尺度。

### CORE-COPYEDIT-001｜最终正文终校

- 触发：结构和事实稳定，准备进入 `ready`。
- 动作：逐句检查语法、指代、比较、连接、标点和术语，并锁定正文哈希。
- 通过：无 open 缺陷，正文与终校哈希一致；正文再改就重新终校。

## `ready` 硬门

- 事实和来源可追溯，时效信息已重开核查。
- 发布图片在包内，来源、权利和允许平台明确。
- 公司、个人和不同平台的成稿没有混用受限表达或资产。
- 中文排版、临时路径、凭据和敏感信息检查通过。
- 独立冷读后的叙事链逐拍对照、候选稿到成稿的具体性 diff、一次完整节奏／语用诊断、一次终校词表扫描和逐句终校均无阻断项。
- 目标平台校验器通过；警告已处理或说明。

硬门负责暴露风险，不负责制造正文。某个事实边界若只用于防止误写，应压成最短限定、图注或审校记录；只有它本身改变主判断且读者确实承担后果时，才有资格成为章节。

## 反馈升级

```text
原始反馈
→ 单稿症状与修复
→ 第二个独立案例或严重安全事件
→ 明确触发、动作、通过条件和反例
→ 修改最窄的权威真源
```

普通措辞偏好默认留在案例；但公众号主理人对成品表达的明确否定属于项目目标 loss，一次即可更新 `PROJECT-WECHAT-AI-LEXICON-001` 的项目禁用 adapter，不必等待第二案例。主理人对真实稿件中某种具体表达动作的明确喜欢，也可更新 `PROJECT-WECHAT-RED-CORPUS-001`；必须同时记录适用语境、信息任务和反模板边界，不能只收一句表面话术。两类修改都要标为项目审美／传播配置，不能冒充跨平台语言规律或 AI 作者鉴定。事实、权利、隐私、凭据、发布等跨项目硬规则仍按原升级门处理。

`PROJECT-WECHAT-JUDGMENT-001`、`PROJECT-WECHAT-RHYTHM-001`、`PROJECT-WECHAT-CONCRETE-001`、`PROJECT-WECHAT-PRAGMATIC-001`、`PROJECT-WECHAT-AI-LEXICON-001`、`PROJECT-WECHAT-RED-CORPUS-001` 与 `CORE-SELECTION-001` 都来自用户明确的项目配置。round-01 证明自动评选可以选出相对赢家，却不能替代用户对文章问题、逻辑和表达的确认；round-02 在用户先锁定标题、核心判断与 4 个章节转折后获得一次正向冷读。后续反馈显示，并列式故事合同会把候选推成资料板块，重复检查也会在压缩阶段删具体、留抽象，因此当前流程把叙事链与具体性设为结构约束，把完整表达诊断收敛到胜出稿一次。上述配置不证明 Best-of-N、传播改善或某种通用检测机制有效；累计 3 篇符合条件的公众号分析稿后，再复核讨论成本、结构返工、再次删改、误伤漏判、红项模板化和适用反例。
