# 可迁移内容工作流

版本：6.4

更新日期：2026 年 8 月 22 日

## 目的

用与任务风险相称的最短流程完成值得写的内容。把「值不值得写」「应走哪一档」「哪些决定必须由人掌握」「怎样形成正文」和「能不能交付」拆开：研究与专项审稿可以并行，公开正文保持一条受人控制的生产线；先确定信息关系，再逐节成文，已确认内容不被后续模型静默重写。

### CORE-PORTABILITY-001｜clone 后可运行合同

- 触发：首次 clone；迁移机器；修改 SOP、Skill、依赖、工作流入口、发布适配器或版本化公司工具；以及准备把一组工具整理成可交接的 Git 工作单元。
- 动作：依赖、入口、配置模板、能力包和本机运行输入只登记到 `tools/workflow-toolchain.json`。Python 聚合安装清单只用根 `requirements-workflow.txt`；Node 分别用 `微信公众号/package-lock.json` 和 `tools/agent-runtime/package-lock.json`，统一执行 `npm ci`。全新环境先运行 `tools/bootstrap.ps1`，日常命令只通过 `tools/workflow.ps1` 调用 clone 内 `.venv`、Codex、Claude 和平台适配器；不得依赖已激活的全局 Python、全局 CLI、机器绝对路径或桌面散件。可分发代码与模板全部版本化；真实密钥、Cookie、登录态和按治理规则保持 `local-only` 的原件只通过登记入口注入。任何工具改动后先做 source-only 检查，再做本地 runtime doctor 和相关回归。
- 通过：受支持的 Git、PowerShell、Python 与 Node 已安装后，一份不借用原工作树文件的全新 clone 可以运行 `tools/bootstrap.ps1 -FullTest` 并以退出码 0 完成；`capabilities doctor --bundle-only` 显示 9 个能力包全部 `PACKED`。所有精确依赖、入口、配置模板和必要资产均已跟踪，Python 与 JavaScript 语法通过，Wenyan、Codex 与 Claude 锁版本一致，公司扩展 22 文件树与登记哈希一致，核心本地 capability／doctor 返回成功；SOP 操作路径均为仓库相对路径。本机账号或 host 条件另由普通 doctor 显示为 ready 或明确列出所需输入。
- 失败：只在维护者当前机器可用；说明要求无锁的 `npm install`，或调用未安装依赖的全局 `python`／`codex`／`claude`；出现盘符开头的 Windows 路径或个人 home 目录等机器绝对路径；依赖未精确锁定；入口、公司工具或配置样本只存在于忽略目录、桌面或未跟踪文件；受限 Prompt 没有版本／哈希约束的本地导入器；把「缺账号输入」误写成「适配器没有打包」，或反过来把模板存在误报为账号已可执行；以及没有真实冷 clone 回归却声称可交接。
- 范围：合同打包 Windows PowerShell 工作流中所有可合法再分发的适配器、精确依赖、clone 内 Codex／Claude CLI、配置模板、版本化公司扩展和受限资产导入器。它不替系统安装 Git、PowerShell、Python、Node、Chrome／Edge，不复制远端 `image_gen` 服务、真实凭据、Cookie、浏览器 Profile、登录态或受治理的原文，也不取得外部账号授权，不执行发布、飞书写入或浏览器覆盖。普通 doctor 必须把这些本机输入逐项 fail loud；授权与保密分级继续单独生效。
- 来源与回归：来自主理人 2026 年 8 月 22 日「SOP 与 workflow 所需依赖、工具必须 clone 后可用」及随后「把所有能力都打包」的明确要求。每次合同或工具链变化，都执行 source-only 检查、能力包 doctor、全量测试，并从当前提交建立一份不共享文件的冷 clone，实际运行 `tools/bootstrap.ps1 -FullTest` 与 `tools/workflow.ps1 verify`；生成的 `.venv`、`node_modules`、本地配置、缓存和临时 clone 不提交。本规则是主理人绑定的 E0 运维合同，不把本机账号就绪冒充为 Git 打包结果。

## 共用入口与四档生产路由

```text
任务分流与必要研究
→ 选择最低可安全完成的 L0／L1／L2／L3
→ 锁定本轮不可逆决定与故事关系
→ 按小节／段落契约单线成文并锁定确认单元
→ 问题优先审稿与局部差异修复
→ 共用事实、权利、终校和交付硬门
→ 授权交付与反馈复盘
```

| 档位 | 适用任务 | 最小生产路径 | 什么时候停止或升档 |
|---|---|---|
| L0 局部任务 | 想法、调研、错字、单句、补链接，以及不改变判断、事实、素材和状态的修改 | 只读目标文件与局部规则；完成对应局部检查 | 一旦改变核心判断、事实边界、结构或资产，重新分流 |
| L1 事实短稿 | 已核事实快讯、状态通知、固定格式简报、纯翻译或资料索引 | 事实包或最小来源底座 → 1 篇短稿 → 事实回映 | 出现来源之外的分析主张时升到 L2；事件本身未核时停在 `research` |
| L2 标准分析 | 价值门通过，研究后只有 1 条明显占优的核心判断和叙事路线；这是公众号分析稿默认档位 | 在 `brief.md` 锁定简版故事合同和不可逆决定 → 建立小节／段落契约 → 单线形成 canonical draft 并锁定确认单元 → 1 次独立冷读只报问题 → 局部差异修复 | 冷读推翻中心框架、仍有至少 2 条实质竞争路线，或需要重做主判断与章节依赖时，退回研究或升到 L3 |
| L3 多路线稿 | 至少 2 条实质竞争框架仍成立；主判断／入口／章节依赖的结构性重写；高编辑或声誉风险的旗舰稿；用户明确要求比较路线；或 L2 因中心框架失败而升档 | AI 提交最多 3 张成文前路线卡 → 用户选择并锁定完整故事合同 → 按 L2 相同方式单线逐节成文、锁定与审稿 | 路线卡没有真实决策差异时降到 L2；用户未选择路线时停在共创，不生成完整正文 |

档位是生产成本与判断不确定性的路由，不是文章长短、重要性或质量等级。始终选择最低可安全完成的档位；事实密集、图片权利复杂或公司材料敏感，可以增加对应专家检查，但不因检查多就自动升级到 L3。正文一旦暴露「不值得写」，可以从任何档位退回 `research`。

L2 在 `brief.md` 记录读者问题、唯一核心判断、一句话主线、证据关系、最强对手、叙事发动机、四格叙事链、不写方向和本轮不可逆决定。只有出现会改变中心判断或故事路线的真实选择，或用户明确要求共创时，才调用 `PROJECT-WECHAT-JUDGMENT-001` 等待确认；一条路线明显占优时不制造仪式性确认。

L2 与 L3 都使用 `research/co-writing-log.md` 记录小节／段落契约、声音锚点、确认状态、重开理由和局部补丁。L3 的差异只发生在成文前：`CORE-ROUTE-001` 先把真实路线选择交给用户，确认后与 L2 共用 `CORE-COAUTHOR-001`。默认不生成多篇完整候选，也不让 AI 盲选终稿。

用户明确要求多个完整版本时，可以把它们作为一次有边界的交付分别生成；共同事实与故事约束必须冻结，版本不可互相拼接，最终采用哪一版由用户决定。该例外不恢复 AI 投票，也不把多版本设为普通分析稿默认路径。

所有分析稿记录请求进入、证据可写、合同锁定、首个可冷读文本交付和用户复核时点，分别报告端到端等待、证据就绪后的文本时间与用户等待。`CORE-TIME-001` 在本轮 3 案例试跑中只记录实耗，不先承诺未经验证的 SLA。

图片线分成两段：研究阶段可以并行找来源、判断权利和规划信息任务；正式生成或深度编辑默认等 L2 简版合同稳定或 L3 路线锁定后再做，除非图片本身会改变选题判断。

排版交付和实质反馈复盘发生在正文生产之后。它们是生命周期动作，不是写作档位。

## 任务模式

| 模式 | 最小路径 |
|---|---|
| 想法 | 建立最小 `draft.md`，先做价值判断，不创建整套内容包 |
| 调研 | `draft.md` + `sources.md`；记录哪些证据会改变判断 |
| 普通改字 | 目标稿件 + 相关局部检查 |
| 公众号事实快讯 | 走 L1；按 `PROJECT-WECHAT-QUICKNEWS-001` 建立已核事实包，加载版本化提示词单路成稿并逐段回映来源 |
| 新分析稿 | 默认走 L2；简版故事合同、分阶段共写记录、1 条 canonical draft 生产线和 1 次问题优先独立冷读。命中 `CORE-LANE-001` 的升档条件才走 L3 |
| 分析长稿 | 长度不决定档位；单一明显占优路线走 L2，多条实质竞争路线或旗舰高风险稿走 L3 |
| 结构性重写 | 局部结构修复走 L2；主判断、入口或章节依赖重做时走 L3，先比较路线卡并重新锁定完整故事合同 |
| 其他稿型明确要求共创 | 调用 `PROJECT-WECHAT-JUDGMENT-001`；共创本身不自动触发多稿 |
| 明确要求多个完整版本 | 冻结同一事实与边界后分别交付；版本之间不拼接，用户选择，AI 不投票代选 |
| 明确要求文风实验 | canonical draft 已形成后，才可选用笨拙写作实验；L2／L3 canonical draft 都只做一次完整人话诊断 |
| 生图 | 视觉计划 + manifest + Image2 预检 |
| 进入 `ready` | 完整事实、权利、审校、终校和平台校验 |
| 交付或发布 | 发布配置、授权和真实记录 |
| 实质反馈 | 单稿 retrospective；达到晋升条件后才碰中央 SOP |

## 状态

`idea → research → draft → fact_checked → editorial_review → ready → published → archived`

| 状态 | 最低含义 |
|---|---|
| `idea` | 有题目或问题，尚未承诺交付 |
| `research` | 正在建立来源和事实底座 |
| `draft` | 正文已形成，仍允许结构调整 |
| `fact_checked` | 时效、数字、引语、身份和口径已复核 |
| `editorial_review` | 正在处理结构、人话、语法、视觉与平台适配 |
| `ready` | 所有发布门通过，等待用户决定是否发布 |
| `published` | 有真实链接或用户明确确认 |
| `archived` | 本轮结束，后续问题另开周期 |

状态写在 `draft.md` frontmatter。`publish-record.md` 只记录真实交付和发布事件。

## 核心规则

`CORE-VALUE-001` 决定分析题是否继续；`CORE-LANE-001` 选择 L0—L3；L1 事实快讯由 `PROJECT-WECHAT-QUICKNEWS-001` 管理，L2 标准分析由 `CORE-STANDARD-001` 管理，L3 的成文前路线选择由 `PROJECT-WECHAT-JUDGMENT-001`、`CORE-CHAIN-001` 和 `CORE-ROUTE-001` 管理；两档正文统一受 `CORE-COAUTHOR-001` 约束。所有面向读者的普通稿件受 `CORE-EVIDENCE-SEAM-001` 约束：证据核验在后台完成，不把核验过程写成正文。公众号 L2／L3 分析稿的首屏另受 `PROJECT-WECHAT-OPENING-001` 约束。两档 canonical draft 都在 `editorial_review` 运行一次 `PROJECT-WECHAT-RHYTHM-001`、`PROJECT-WECHAT-PRAGMATIC-001` 与 `PROJECT-WECHAT-CONCRETE-001`，再按 `PROJECT-WECHAT-EXPLANATION-001` 单独检查解释过量；`PROJECT-WECHAT-AI-LEXICON-001` 只在终校前扫描一次，`PROJECT-WECHAT-RED-CORPUS-001` 仅作可选正向参考。`CORE-TIME-001` 记录真实时间，不把试跑目标冒充 SLA。任何档位都不能把材料不足包装成文章。

### CORE-VALUE-001｜值得写门

- 触发：准备把热点、帖子、模型卡、论文、产品更新或一组来源写成分析稿。
- 动作：先用自己的话回答四件事：来源已经告诉了读者什么；本文新增的非显然判断是什么；哪组证据关系支持或限制它；这个判断会改变读者的理解、选择或下一步行动什么。再写出最强替代解释。
- 通过：新增判断不是来源改写或通用常识；至少一条证据会真实改变判断强度；读者后果具体；反证出现时知道怎样改口。事实、判断和推断彼此可辨。
- 失败：只能补背景、讲定义、扩大叙事、重复厂商口径，或靠钩子、网梗、第一人称和完整结构制造「像一篇文章」的感觉。此时停在 `research`，允许降级成事实简报或不写。
- 反例：纯事实快讯、状态通知和资料索引不要求非显然判断，但必须诚实标明稿型，不能伪装成分析长稿。

### CORE-LANE-001｜L0—L3 生产分流（试运行）

- 触发：任何内容任务完成初步稿型识别后；分析任务先通过 `CORE-VALUE-001`，再决定 L2 或 L3。
- 动作：选择最低可安全完成的档位并记录档位与理由。L0 只处理局部；L1 只报告已核事实；L2 用一条明显占优的简版故事合同进入分阶段单线共写并做 1 次独立冷读；L3 只在至少 2 条实质竞争路线、中心结构性重写、旗舰级编辑／声誉风险、用户明确要求比较路线，或 L2 中心框架失败时启动完整共创和成文前路线卡。事实密度、图片数量、权利复杂或公司保密本身只增加专项硬门，不自动升级 L3。
- 通过：档位理由可以用事实不确定性、框架竞争或变更范围解释；L2 与 L3 的差异不是篇幅和「重要程度」；只加载该档位需要的文件和角色。
- 失败：普通分析稿无条件进入 3 稿；让多个 Agent 写同一正文或用 AI 投票代替用户选择；为了使用多 Agent 强凑路线差异；把纯事实快讯包装成分析；或在中心框架已失败时继续局部润色而不退回研究／升档。
- 范围：本仓库跨平台生产路由；公众号 L1—L3 的具体写法由相应项目规则约束。医疗、法律、金融、受限公司材料等高风险任务仍可进入慢线和专项审核，档位不能降低事实、保密或授权门。
- 反例：一篇来源密集但只有 1 条清晰判断的稿件仍可走 L2，并增加 evidence review；一篇很短但存在 2 个互斥解释框架的评论稿可以走 L3；错字修改保持 L0。
- 回归：用 L0 局部改字、L1 官方快讯、L2 单一路线分析、L3 双框架路线卡、L2 冷读后升档、密集事实但单框架不升档、用户明确多个完整版本 7 个案例回放。累计 3 篇适用分析稿后，于 2026 年 9 月 11 日前复核误分流、中心重置、总耗时、Agent 调用、用户实质改写和事实返工。本规则是主理人绑定的 E0 项目配置，效果尚未验证。

### CORE-PROMISE-001｜一个承诺

- 触发：标题、开头、正文或结尾出现多个并列主旨。
- 动作：只留一个读者能复述的问题，其他内容降为证据或删除。
- 通过：标题、证据和末句回答同一个问题。

### CORE-HOOK-001｜首屏压力

- 触发：已经通过 `CORE-VALUE-001` 的分析稿先播日期、公司、融资、履历或背景，读者看完首屏仍不知道哪里反常、有什么代价或为什么要继续看。
- 动作：只选一个可见动作或事实，在首屏形成「发生了什么 → 哪里不对劲或尚未解决 → 后文要追什么」；履历、历史和定义延后到第一次真正需要它们的位置。
- 通过：冷读者看完前三段，能说清主体正在做什么、局面哪里反常，以及继续读会得到什么答案。去掉名气、金额和热点词的光环后，那个具体冲突仍然成立。纯事实快讯可以直接报事件。

### PROJECT-WECHAT-OPENING-001｜公众号分析稿首句去通稿化（主理人绑定项目配置）

- 触发：微信公众号 L2／L3 分析稿形成首个可冷读正文；首句、首段采用「日期／近日／当地时间 + 主体 + 发布、宣布、公告、表示或报道」；或核心问题在两段背景之后才出现。来源案例为 `astra-pause-trillion-param-myth / FB-005`。
- 动作：把已核日期保留为证据，但默认移到第一层冲突之后；首段先交代一个具体的矛盾、异常、代价、未决问题或会改变读者判断的结论，再补主体、日期和发布背景。不得仅把「8 月 7 日」换成「近日」，或把日期挪到主体后面继续写通稿导语。写前在 `brief.md` 与 `research/co-writing-log.md` 记录开场发动机、首屏压力和 `time_first_exception`；开场单元锁定或 canonical draft 冷读前，运行 `.agents/skills/self-media-ops/scripts/check_wechat_opening.py <file>`。
- 通过：第一段已经给出可复述的冲突或问题，日期删去仍不损失开场发动机；前三段不能直接压成「某日某公司宣布某事」的新闻摘要。检查脚本返回 `ok`，或时间前置有记录完整的窄豁免理由。
- 失败：首句按时间顺序播报事件，核心问题等到「所以／真正值得关注的是」才出现；用「刚刚／近日／同一天」替换具体日期；把「主体在某日公告」当成修复；或为了避开检查虚构场景、情绪和第一人称。
- 范围：仅适用于微信公众号 L2／L3 分析稿正文及用户明确要求的完整备选版本，不约束 L1 事实快讯、状态通知、问答原话开场。若日期、倒计时、时间差或先后顺序本身就是核心因果压力，可以时间前置，但必须在同一段显出压力，并在故事合同或共写记录填写 `time_first_exception`；「事情很新」不构成豁免。
- 回归：使用 `.agents/skills/self-media-ops/references/wechat-opening-regression.yml` 的正反例，并由 `.agents/skills/self-media-ops/tests/test_opening_rule.py` 验证规则入口、共写记录模板和启发式检查。该规则是主理人明确要求的 E0 项目配置，不宣称普遍提高传播效果；累计 3 篇适用分析稿后，于 2026 年 9 月 11 日复核误报、漏报和再次改写。

### PROJECT-WECHAT-QUICKNEWS-001｜公众号事实快讯提示词短路由（项目配置）

- 触发：微信公众号事实快讯、状态通知，或用户明确要求「按快讯处理」；稿件只需准确报告已发生的事件及必要解释，不承载来源之外的分析主张。数字、日期、价格、身份、产品名、引语和「最新」表述仍先核验。
- 动作：先把原始材料编译为已核事实包，至少记录核验时间与时区、事件句、来源、逐条 claim、证据类型、时效、限制、读者后果、未知项、禁写项和已登记图片；不得把一组未核链接直接交给文风指令。然后加载 `.agents/skills/self-media-ops/references/wechat-quicknews-prompt.yml`，按材料量设置篇幅和语气，单路生成标题、正文、内部事实回映与未决项。编辑逐段核对 claim ID 与 source ID，交付前重开时效来源，再做目标平台终校；内部回映不进入发布正文。
- 通过：正文每个可核事实均能回映来源；厂商自报、第三方结果、作者判断、推断和未知信息彼此可辨；第一段已交代主体、动作与关键变化；篇幅是「最短但完整」，没有为字数填充；没有媒体身份仿冒、固定署名、第三方独特表达、虚构第一人称、热词配额或无资产的图片占位。
- 失败：事件本身仍是传闻或匿名截图却开始写稿；原始材料和文风要求未经事实包隔离就同时进入模型；为固定篇幅补履历、行业史或通用常识；用情绪、类比或网梗覆盖限定；要求固定段落、热词、括号尾巴或「神级收尾」配额；图片未登记来源与权利却输出占位；没有内部事实回映。
- 反例：一句服务状态通知可以只写 1—3 句；无信息增量的短通知不扩成 2000 字文章。需要证明「为什么改变行业」的稿件属于分析稿，回到 `CORE-VALUE-001` 并按 `CORE-LANE-001` 选择 L2 或 L3；高风险主题与来源不可得的传闻不得借快讯名义降低事实门。
- 回归：用提示词合同内的正常快讯、极短通知、无图、未核传闻和分析稿转路由 5 个案例人工回放；累计 3 篇真实快讯后，于 2026 年 9 月 11 日前复核事实返工、篇幅填充、仿写残留和交付时间。本规则是主理人绑定的 E0 项目配置，尚不证明传播效果。

### CORE-STANDARD-001｜L2 标准分析单稿与独立冷读（试运行）

- 触发：分析任务通过 `CORE-VALUE-001`，研究后只有 1 条明显占优的核心判断与叙事路线，且未命中 `CORE-LANE-001` 的 L3 条件。
- 动作：在 `brief.md` 记录 L2 档位、请求进入／证据可写时点、不可逆决定，以及简版故事合同：读者问题、唯一核心判断、一句话主线、证据关系、最强对手、叙事发动机、四格叙事链和不写方向。按 `CORE-COAUTHOR-001` 建立 `research/co-writing-log.md`，以小节或高影响段落为单元形成契约并进入一条 canonical draft 生产线；不得创建伪候选。随后由未参与正文生成的冷读者先只读公开正文，只报告带位置、理由和通过条件的问题，再打开 `brief.md` 对照故事合同。修复必须以局部差异呈现，确认单元不静默重写；中心框架失败则退回研究或升到 L3。
- 通过：简版合同、共写记录和确认状态完整；正文没有越出事实边界；冷读者能复述同一问题、判断和必要顺序；锁定单元未被无理由覆盖；没有开放的中心框架缺陷；档位、时间、冷读结论与是否升档均可追溯。
- 失败：省略简版合同直接出长稿；一次性把全文生成后再统一「去 AI 味」；写作者用自评冒充独立冷读；冷读前先看 brief 导致确认偏差；审稿者直接改写整篇；发现两条实质路线仍留在 L2；或为了保留单稿路径只修句子、不处理中心框架失败。
- 范围：公众号普通分析稿、单一路线的热点／论文解释、产品分析、人物／职业与企业产品稿。事实快讯走 L1；结构性重写、多路线竞争与旗舰高编辑风险走 L3。
- 反例：用户明确要求共创时可以调用 `PROJECT-WECHAT-JUDGMENT-001`，但若最终仍只有 1 条明显占优路线，确认后继续 L2，不因讨论过就自动生成 3 稿。事实密集但框架单一的稿件增加 evidence review，仍不自动升档。
- 回归：连续记录 3 篇 L2 的端到端时间、证据就绪后文本时间、首次冷读后的中心改动、单元接受标签、锁定单元保留率、用户实质改写、事实修正与后续升档；若 2 篇需要重做中心框架，暂停 L2 默认并复核分流条件。

### CORE-ROUTE-001｜L3 成文前路线选择（试运行项目配置）

- 触发：任务按 `CORE-LANE-001` 进入 L3，至少 2 条会改变核心判断、开场发动机或章节依赖的实质路线仍成立；或用户明确要求先比较路线。
- 动作：完成必要研究后，AI 最多提交 3 张匿名路线卡，每张只写读者问题、核心判断、叙事发动机、四格叙事链、最强对手、关键事实取舍、开场压力、结尾落点，以及选择它会放弃什么。路线卡不写成完整正文，也不由 AI 评审投票。由用户选择、修改或全部退回；选定路线连同确认日期写入 `research/judgment-workshop.md`，再进入 `CORE-COAUTHOR-001` 的单线成文。
- 通过：路线之间存在可说明的决定差异；用户选择或修改记录可追溯；未选路线没有流入 canonical draft；最终正文只有一条作者线。
- 失败：用标题、语气或同义词变化伪造路线；在用户选择前生成完整正文；让生成者或评审 Agent 代替用户决定终稿；把多条路线拼成一篇；或用户全部退回后仍为了交稿硬选相对赢家。
- 例外：用户明确要求交付多个完整版本时，可以在同一冻结事实与边界下分别生成，但每版独立、不得互拼，采用决定仍由用户作出；这是一项明确交付，不是 L3 默认流程或效果证据。
- 回归：用双框架实质选择、同框架换标题、用户全部退回、用户明确多个完整版本 4 个案例回放。后续 3 个适用案例记录路线卡数量、用户修改、是否发生中心重置和实际讨论成本；2026 年 9 月 11 日复核。

### CORE-COAUTHOR-001｜分阶段人控共写与确认锁定（试运行项目配置）

- 触发：L2／L3 分析稿已经通过价值门并拥有可写故事合同，准备从研究进入公开正文；结构性重写重新触发。L0、固定格式 L1 和纯机械终校不强制建立完整共写记录。
- 人类决定权：用户或本轮明确指定的人类编辑拥有会改变文章身份的不可逆决定，包括读者问题、核心判断、哪些事实进入正文、开场发动机、声音锚点、关键段落取舍和结尾落点。AI 可以提出推荐、追问和反例，但不得在后续润色中静默改变这些决定。用户说「按这个方案直接写」视为锁定现有决定，不视为放弃最终验收。
- 段落契约：在 `research/co-writing-log.md` 按小节或高影响段落记录最小关系：读者进入时怎样理解；本单元新增、纠正或改变什么；使用哪项证据或实例；必须保留什么限制；读完后把读者送到哪里。相邻普通段落承担同一任务时可以共用一个小节契约，不为每段制造表格。
- 动态颗粒度：事实解释、机制梳理和同口径比较可以由 AI 提交一个段落或小节候选；开头、结尾、核心判断和已有鲜明声音的段落优先采用 `human_first` 或 `critique_only`。一个候选不够时，只有真实表达策略不同才追加第二个局部版本；默认不生成多个全文版本。
- 声音锚点：用户明确认可的段落记录原位置或稳定引用、它完成的信息关系和禁止照抄的表面词句。确认后的段落／小节标为 `locked`；除事实错误、链条断裂或用户明确要求外不得重写。需要重开时记录理由、旧文与局部 diff，不能用一次全稿润色覆盖。
- 审稿与并行：研究、事实核查、权利和互不依赖的定向审稿可以并行；公开正文只由一条 canonical writer 生产线修改。审稿者先提交问题位置、读者损失、理由和通过条件，不直接改写正文；需要改文时给局部 diff，由用户或正文负责人接受、修改或拒绝。多个审稿意见不能自动合并成新全文，也不能以 AI 多数票决定自然度。
- 通过：不可逆决定、单元契约、声音锚点、确认标签和重开理由可追溯；公开正文只有一个 canonical 版本；锁定单元保持原意与声音；所有修复均能指向具体问题和局部差异；事实审计仍留在后台。
- 失败：把完整研究包和文风要求一次性丢给模型生成全文；先让 AI 写完再全篇去 AI 味；后续模型重写已确认段落；用禁词或固定连接词模仿正向样本；并行写手同时改 `draft.md`；审稿者静默改文；或用户的核心决定被模型综合意见覆盖。
- 范围：本仓库 L2／L3 分析、解释、人物、产品与观点稿；快讯、翻译、表格和纯资料索引可以缩短记录。该规则是主理人明确采用的 E0 项目配置，研究只支持设计方向，不证明本仓库已经降低返工。
- 来源与回归：来源案例为 `astra-pause-trillion-param-myth / FB-009—010`，研究复核见 `共享/运营/复盘/2026-08-11-人机协同写作模式复核与试运行设计.md`。按 `INSIGHT-004` 在后续 3 个适用案例前瞻记录中心重置率、单元接受标签、语义返工、锁定保留率、事实护栏和实耗；2026 年 9 月 11 日决定保留、收窄或退役。

### CORE-CHAIN-001｜叙事链与写后对照

- 触发：L2 简版故事合同、L3 完整故事合同，以及两档 canonical draft 进入 `editorial_review` 后的写后对照。
- 数据结构：故事节拍必须以「叙事链表」记录，每一节四格全部必填：① 本节新增的事实或动作；② 它让局面发生了什么变化；③ 它留下了什么未解决的问题；④ 下一节为什么必须回答这个问题。第 ④ 格写不出来，说明两节是并列关系：合并、重排，或改用「平行比较」结构并声明共享尺度。
- 平行比较例外：明确承诺清单或对照的稿型可以使用并列章节，但必须在链表头部声明唯一共享尺度，即同一问题、同一量纲或同一决策用途；每节都在这把尺子上给出结论。
- 写后对照：L2／L3 canonical draft 进入 `editorial_review` 时，审核者先独立冷读，再把成稿逐节映射回对应故事合同的叙事链表，逐拍检查「上一节留下的问题，这一节是否真的在回答」。遮住小标题读，任何一节能前移或删除而文章不塌，判结构缺陷打回。成稿偏离链表本身不是缺陷，但偏离后链条断裂是缺陷，且偏离须在 `review.md` 记录；已锁定单元只有在确认该缺陷后才重开。
- 叙事发动机：从谜团揭示、人物追求、问题升级、实验验证、对照决策五种发动机中选一条为主，全文只允许一条。
- 通过：叙事链四格完整；线性稿逐节形成「回答上一问并逼出下一问」的依赖，平行稿逐节使用同一尺度；写后映射已记录且没有开放的链条断裂。
- 失败：节拍表退化为只有「写什么／不写什么」的内容清单；成稿与链表无人对照；用「文章大体顺」代替逐拍检查。

### PROJECT-WECHAT-JUDGMENT-001｜公众号写前共创门（试运行项目配置）

- 触发：L3 多路线稿在路线选择前强制触发；L2 只有在存在会改变中心判断或故事路线的真实选择，或用户明确要求共创时触发。L0、L1 和路线明显占优且未要求共创的 L2 不触发。
- 动作：完成必要广搜后，Codex 主动提交写前共创包，不把空白问题丢给用户。共创包至少包含一个推荐方案：读者真正要解决的问题、唯一核心判断、一句话故事主线、读者追问链、`CORE-CHAIN-001` 四格叙事链、叙事发动机、开场压力、结尾落点、必要事实锚点和明确不写的方向；另列本文最强的反例或对手（最强替代解释、最硬反方证据或最可能推翻主判断的案例），并指出在第几拍正面接它。故事节拍成立后再补 2—3 个标题和暂定小标题；重点修辞另写具体表达任务和指向。存在真实分歧时按 `CORE-ROUTE-001` 给最多 3 张成文前路线卡。根据用户反馈修改并记录到 `research/judgment-workshop.md`。
- 通过：用户明确确认或修改后的标题方向、核心判断、故事主线、追问链、叙事发动机、四格叙事链和暂定小标题均已记录；最强对手非空，或稿件已明确降级；重点修辞有具体任务或明确不预设；L3 另有选定路线卡；`user_confirmed: true`，并有确认日期。锁定记录随后由 `research/co-writing-log.md` 引用；触发共创但留在 L2 的单稿在 `brief.md` 记录确认引用。
- 失败：命中触发条件却未讨论就出现完整正文；只问「你想怎么写」而不提供推荐方案；只列漂亮小标题却说不清前后依赖；用户已经修改中心但共写记录仍保留旧框架；用禁写边界清单删光反方材料；让 AI 投票代替用户选路线；或给路线明显占优的 L2 强加仪式性确认。
- 反例：纯事实快讯可以在事实核验后直接成稿；路线明显占优的 L2 可在 `brief.md` 锁定简版合同后进入分阶段单线写作；讨论中用户明确说「按你的方案直接写」即视为当轮确认，不必为了形式继续追问，共创后也不自动升级 L3。
- 回归：触发本门的任务记录故事合同引用与确认日期；若连续 3 篇中讨论成本高于避免的结构返工，或用户确认后仍连续 2 篇要求更换中心，复核并收窄该门。

### PROJECT-WECHAT-PRAGMATIC-001｜语用必要性（试运行项目配置）

- 触发：L2／L3 canonical draft 完成分阶段成文并进入 `editorial_review` 的一次完整诊断；检查高显著性转折、抽象判断、总结、隐喻、指示词或疑似「金句」。本规则不依赖关键词命中或 AI 检测分数。
- 动作：引用具体句子，并依次回答：作者此刻必须传递的具体任务是什么；抽象词与「这里／背后／这一刻」指向什么对象、动作或决定；整句能否原封不动移到另一篇科技稿；它是在呈现冲突还是自我宣布「这里有张力／意义／戏剧性」；删除后损失事实、判断、关系或后果，还是只损失文章腔；朗读时像在解释具体问题，还是像在完成写作任务。修复顺序为删除、改成具体冲突或决定、确有必要才保留。
- 通过：保留句有明确表达任务和具体指向，删除会损失真实内容；评审能用原句和上述测试解释判断。必要路标、准确术语、字面事实、来源引语和持续参与后文论证的修辞均可通过。
- 失败：句子只宣布张力、意义、差距或态度，却没有新增对象、动作、证据、关系或后果；可跨题移植且删除无内容损失；只用「更像人／不像 AI」判退；L2 冷读已发现中心性表演句却仍局部放行；或 L3 路线之间没有实质差异却仍强行选路，canonical draft 的重大表演句又未处理。
