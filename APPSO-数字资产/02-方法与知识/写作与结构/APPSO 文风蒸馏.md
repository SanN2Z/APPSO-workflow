# APPSO 文风蒸馏：可复用版本

这不是仿写词库。它把近 25 篇样本中的稳定方法转成我们自己的写作约束。

## 一句话风格合同

把前沿科技写成普通人能立即感到的动作、麻烦或选择；用一个清楚的问题组织证据，最后给出比热点本身更耐用的判断。

## 写前先选稿型

| 稿型 | 核心任务 | 不该做的事 |
|---|---|---|
| 快讯 | 快速说清已确认事实和意义 | 用长背景掩盖信息不足 |
| 早报 / 周报 | 高密度提供多个独立事实 | 强行给每条新闻升华 |
| 热点 / 论文解释 | 把反常现象解释清楚 | 把截图或梗直接当结论 |
| 产品实测 | 用相同任务展示真实差异 | 只复述发布页和厂商跑分 |
| 方法指南 | 把案例背后的方法交给读者 | 堆提示词却不解释何时使用 |
| 人物 / 职业稿 | 用人物选择解释行业变化 | 只写履历或励志口号 |
| 企业产品稿 | 解释产品如何进入真实组织 | 把商业案例写成普遍事实 |

## 标题

1. 一个标题只承诺一个主要反差或问题。
2. 让技术名词和一个熟悉动作同框；读者不懂名词也能理解剧情。
3. 陌生人名必须附带动作或冲突，不能只卖身份。
4. 数字只在改变判断时使用；不要同时堆人名、引语、模型名、英文术语和第二结论。
5. 「刚刚、突发、终于」只用于真实时效稿，不能代替内容价值。
6. 早报可并列多条标题，单篇观点稿不套用早报规则。

## 开头三步

```text
看得见的场景 / 动作 / 引语
→ 普通人的摩擦、欲望或疑问
→ 本文只回答的一个问题
```

- 在前几段建立冲突，不先抄发布会背景。
- 专业读者熟悉、普通读者陌生的事实，随后用极简事实卡补齐。
- 作者可以在场，但判断必须有后续证据兑现。

## 正文推进

每一节至少完成四件事：

1. **判断**：这一节想改变读者什么看法。
2. **证据**：官方信息、实测、原帖、论文或独立结果中的哪一种支持它。
3. **限制**：哪些条件下不成立，或还有什么替代解释。
4. **读者后果**：它会改变成本、时间、连续性、选择或风险中的什么。

优先使用具体动作：谁查了什么、在哪一步卡住、花了多少、交付了什么。抽象概念只在后文会反复使用时命名。

## 证据编织

- 官方资料说明「厂商声称能做什么」。
- 相同任务实测说明「真实完成度如何」。
- 社交内容说明「大家在讨论或遇到什么」，不证明动机和普遍性。
- 论文、系统卡和访谈负责解释机制或长期趋势。
- 成本和步骤换算负责把技术差异变成用户体感。

商业合作稿至少补一个独立来源、一个真实限制和一个不适用场景。

## 人话与网感

- 底色是清楚解释，梗只放在开头、转折或评价处。
- 英文术语首次出现时立即翻译成一个动作或日常问题。
- 连续两个高密度段落后，回到场景、类比或作者判断。
- 笑点之后补事实边界；不要让模型或公司被过度人格化。
- 允许短句单独成段，但不要机械制造「金句墙」。
- 开头、中段、结尾应像同一个人在说话。

## 图片节奏

- 一张图只承担一个证据或解释任务。
- 重要截图保留来源和上下文。
- 产品实测优先使用同任务、同条件的前后对比。
- 图片可让读者喘气，但关键定义必须存在于正文。

## 结尾

```text
回到开头的人 / 动作 / 问题
→ 用正文证据重新解释它
→ 沿同一个标题承诺，增加一层由正文证据支持的后果
```

「增加一层」不是强制升华。证据只够回答当下问题时，就停在当下；不得为了显得深刻，临时改换分析单位、时间尺度或责任主体。最后一句留下判断，不留下泛化 CTA、空口号或只为好笑的尾巴。

## 我们比参考样本多做一步

- 明标事实、厂商自报、第三方结果、作者体验、推断和玩梗。
- 新概念必须有统一定义、多个证据和反例，不能只服务标题。
- 产品评测记录版本、设置、预算和失败案例。
- 商业稿不因合作关系降低证据门槛。
- 冷读者必须能说清：发生了什么、作者怎么看、凭什么、与我有什么关系。

## 禁止仿写

- 不收集或复用参考账号的固定口头禅、独特比喻和收束句。
- 不为了「像 APPSO」刻意加入某个名人、网络梗或强情绪。
- 不把文章改成「开头段子 + 中段说明书 + 结尾金句」的拼接体。

## 发布前快速评分

每项 `0 / 1 / 2` 分，任一项为 0 则退回修改：

1. 单一标题承诺
2. 普通人可进入的开头
3. 稿型与结构匹配
4. 一个清楚的统领问题
5. 证据和限制成对出现
6. 术语已翻译成人话
7. 全文声音一致
8. 图片承担明确任务
9. 结尾沿同一承诺增加有证据的后果，证据不足时及时停止
10. 事实与商业边界透明
