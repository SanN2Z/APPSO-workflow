# 公开科技媒体结构观察

更新日期：2026 年 7 月 25 日
状态：`pilot`

## 已有证据

APPSO／爱范儿公开样本已有 25 篇人工归纳。当前可以继续作为项目 adapter 候选的，不是某个词或标题模板，而是四类信息任务：

- 开头先建立可见事件、反常事实、直接判断或读者问题，背景随后补；
- 用一个问题组织不同来源，让每组材料承担事实、机制、限制或后果中的明确角色；
- 参数和技术说明之后，落回用户的成本、等待、追责、完成度或选择；
- 结尾沿标题承诺增加一层有证据的后果，不另开第二套方法论。

这些观察的证据与稿型边界见 [`APPSO 近 25 篇样本分析.md`](../APPSO%20近%2025%20篇样本分析.md)。它们是公开样本归纳，不是 APPSO 官方 SOP。

## 首批跨媒体管线

量子位的首批 3 个 URL 只用于验证以下能力。爱范儿、机器之心、少数派与 36Kr 的自动流程暂时只处理公开列表或官方 RSS 元数据，不读取正文；机器之心页面需要客户端加载，v1 不调用隐藏 API 或执行 JavaScript：

- 不同站点能否在遵守 robots 和限速的前提下输出同一结构 schema；
- 正文、HTML、摘要、引文与独特表达是否完全不落盘；
- 标题、作者、日期、栏目与结构统计是否足够支持后续人工分层；
- 商业稿、快讯、实测和深度分析能否在聚合前被分开。

在完成结构采集、人工稿型标注，并达到每媒体每稿型至少 10 篇之前，本轮不发布「机器之心风格」「量子位风格」或跨媒体平均值。

首轮 `plan` 已验证 3 个 URL 与策略配置；真实采集因运行环境 DNS 返回非公网保留地址而被 SSRF 门禁阻断，零文章请求、零结构记录。当前观察继续保持 `pilot`，不能把元数据目录误当成已经完成的正文结构样本。

## 后续要检验的问题

1. 问题式开头是否只在观点稿有效，快讯和教程是否更适合从事件或任务直接进入。
2. 高信息密度稿如何在证据段之间建立依赖，而不是靠「值得注意的是」等框架词转场。
3. 小标题的工作是导航、推进问题还是重新总结；不同稿型的比例是否不同。
4. 图像出现位置是否与证据任务相关，而不是固定每若干段插图。
5. 结尾增加的「一层后果」是否仍属于标题承诺，怎样识别临时升华和第二论题。

## 禁止形成的结论

- 「某媒体常用某词，所以我们也该用」；
- 「平均句长达到某个数字就更像真人」；
- 「抓取数量越多，文章质量越好」；
- 「公开文章可以直接用于模型训练」；
- 「公开样本归纳等于媒体官方写作规范」。
