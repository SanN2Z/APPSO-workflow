# APPSO 示意图设计速查

来源：[Markdown 示意图设计系统规范](../../01-栏目与品牌/品牌视觉/原始资料/Markdown%20示意图设计系统规范.md)

资料属性：internal

## 一句话原则

一张图只讲一个逻辑。先定结构和阅读路径，再调字号；内容放不下时拆图，不继续缩字。

## 画布

| 项目 | 参数 |
|---|---|
| 默认画布 | 1080 × 1440 px，竖版 |
| 上安全区 | 72 px |
| 左、右安全区 | 各 64 px |
| 下安全区 | 64 px |
| 有效内容区 | 952 × 1304 px |
| 网格 | 6 栏 |
| 栏距 | 24 px |
| 基础单位 | 8 px |

## 品牌元素

| 角色 | 参数 |
|---|---|
| 主品牌色 | `#ec1700` |
| 辅助品牌色 | `#fc7c0a` |
| 暖白背景 | `#F8F5EC` |
| 白色内容面 | `#FFFFFF` |
| 主文字 | `#121212` |
| 字体 | OPPO Sans |

颜色建议：70% 中性背景、20% 深色文字和结构线、10% 品牌强调色。小字号文字不要使用橙色。

## 页面四区

1. 标题区：140—220 px。
2. 核心示意图区：700—860 px。
3. 解释区：180—260 px，保持 3—5 条短句。
4. 页脚区：60—100 px，放 Logo、来源、时间与注释。

## 字号硬底线

以下原规范数值是画布坐标，不足以单独证明手机上可读。发布验收按图片实际显示宽度换算：`显示字号 = 画布字号 × 显示宽度 ÷ 画布宽度`。以 1080 px 图显示为 360 px 为例，画布 12 px 只剩 4 px。

新图在 360 px 宽度下，正文至少 12 px，关键说明优先 14 px，必要来源注释至少 10 px；对应 1080 px 画布至少为 36／42／30 px。更窄的正文容器按实际宽度重算。将此要求追加到任务的 Output constraints，不改写原始规范。放不下先删冗余或拆图，不继续缩字。

- H1 不低于 28 px。
- H2 不低于 20 px。
- 正文不低于 12 px。
- 标签与注释不低于 10 px。

内容增加时，依次缩小 Note、Small、Body、H3、H2；H1 尽量保持稳定。触到底线仍放不下，必须拆图。

## 组件

- 节点圆角：16—20 px。
- 节点内边距：20—24 px。
- 节点间距：24—32 px。
- 标准线宽：2 px；强调线宽：3 px。
- 一张图最多使用 2 种线型。
- 小标题圆点：品牌红，默认直径 8 px，与文字间距 10 px。
- 小标题圆点建议每图出现 3—6 次，不用于 H1、正文和页脚。

## 容量

- 流程图主要节点：5—7 个。
- 结构图一级模块：3—5 个。
- 关系图关联对象：3—6 个。
- 每个节点文案尽量不超过 18 个字或 2 行。
- 每个说明模块建议控制在 40—70 字。

## Logo

- 页脚优先使用 SVG，透明 PNG 只作备选。
- 推荐高度 28 px，可在 24—32 px 内调整。
- Logo 已带品牌字样时，不重复添加「爱范儿制图」。
- Hunt Good 与 APPSO 公司稿的自制信息图必须带 APPSO 标识。当前已确认可用的资产是 [APPSO Logo 红底白字.png](../../01-栏目与品牌/品牌视觉/原始资料/APPSO%20Logo%20红底白字.png)。
- 该 PNG 不是透明版本：按原比例缩放成克制的红色页脚锁定块，保留完整红底与白色字样；不要抠底、变色、拉伸或假造透明版本。
- 该用法只覆盖 APPSO 公司稿与 Hunt Good 信息图，不外推到个人稿、其他品牌或通用模板。拿到官方 SVG 后，再按同一位置替换。

## Image2 执行合同

- APPSO 信息图不是先读本速查再自行排版。最终 Image2 调用必须同时接收完整的[《Markdown 示意图设计系统规范》](../../01-栏目与品牌/品牌视觉/原始资料/Markdown%20示意图设计系统规范.md)和登记版 [APPSO Logo 红底白字 PNG](../../01-栏目与品牌/品牌视觉/原始资料/APPSO%20Logo%20红底白字.png)。
- 生图计划使用 `visual_route: infographic`、`prompt_ref: appsso-infographic-v1`、`reference_strategy: provided_local`；完整规范按 `prompt_format: full_file` 逐字进入 Prompt，Logo 作为 `referenced_image_paths` 输入。
- HTML／CSS 草图、速查摘要和确定性布局可以用于内部检查信息关系，不能替代上述 Image2 输入合同，也不能直接冒充 APPSO 发布信息图。

## 交付检查

- 测评比较图分清本次实测、作者偏好、厂商介绍、独立评测和产品公司的自有评测。机构结果注明日期、指标与运行环境；不同测试不拼成综合排名。
- 被测模型的网页、游戏、插画等产物使用真实素材。信息图可以整理评价与数据，不凭空画出作品充当测评证据；缺失项和疑似问题照实保留。
- 已制作的信息图须插入当前交付载体的对应位置；默认飞书稿写入后读回核对，公众号样式交接或明确要求本地预览时再生成 HTML。检查手机宽度下文字可读、来源与 AI 标记可见，不能只交付素材文件。

- [ ] 缩到手机宽度后，标题和主逻辑仍能一眼读懂。
- [ ] 一张图只有一个核心视觉逻辑。
- [ ] 正文与注释没有低于字号底线。
- [ ] 节点、图标、圆点、箭头与线型保持统一。
- [ ] 来源和 Logo 克制地放在页脚，不抢正文。
- [ ] Hunt Good／APPSO 自制信息图已使用登记版本的 APPSO 标识；没有重复「爱范儿制图」。
- [ ] 输出文件与来源已进入资产台账或内容包 manifest。
