# Markdown 示意图设计系统规范文档

## 1. 文档目标

本规范用于统一品牌在 `Markdown` 内容转译为示意图时的视觉表达方式。适用对象包括流程图、关系图、结构图、逻辑拆解图、方法说明图、信息型图文页等。

这套系统重点解决 4 件事：

1. 保证同一批内容在不同页面中拥有统一的视觉语言。
2. 保证在手机预览场景下的可读性。
3. 在固定画布里控制信息密度、层级节奏和视觉路径。
4. 让 `Markdown` 的内容结构能稳定映射到版式与组件。

## 3. 设计原则

### 3.1 单图单逻辑

每一张示意图只表达一个主逻辑。主逻辑可以是流程、结构、关系、方法、拆解、对比中的一种。

一张图里不同时承载多套平行叙事。内容一旦并行过多，焦点就会被打散。

### 3.2 先结构，后字号

先确定信息分区、模块关系、视觉路径和留白秩序，再根据内容多少调整字号。

字号是收口工具，不是解决拥挤问题的第一手段。

### 3.3 手机预览优先

本系统以手机预览为主要使用场景，排版判断优先级如下：

1. 标题能否一眼识别。
2. 主逻辑能否快速读懂。
3. 正文能否在不放大的情况下完成阅读。
4. 辅助信息是否清晰但不抢主信息。

### 3.4 缩字有底线

最小字号不得小于 `10 px`。

`10 px` 只用于注释、编号、短标签、图注等辅助信息。正文与节点说明尽量维持在 `12 - 14 px` 以上。

### 3.5 内容过多时优先拆页

当内容已经逼近最小字号限制，仍无法在当前画布中清晰容纳时，应拆分页面，而不是继续压缩文字。

## 4. 画布与安全区

### 4.1 固定画布

系统默认示意图画布为：

- 宽度：`1080 px`
- 高度：`1440 px`
- 方向：竖版

该比例适用于手机预览、社交媒体封面、信息长图首屏、演示内容截屏等场景。

### 4.2 安全区

为保证边缘呼吸感与手机端预览可读性，统一设定安全区：

- 上边距：`72 px`
- 下边距：`64 px`
- 左边距：`64 px`
- 右边距：`64 px`

### 4.3 有效内容区

扣除安全区后，推荐内容区域为：

- 内容宽度：`952 px`
- 内容高度：`1304 px`

主要标题、节点、图形、说明信息应尽量落在该区域内。

## 5. 网格系统

### 5.1 基础网格

统一采用 `6 栏网格`。

- 栏数：`6`
- 栏距：`24 px`
- 基础单位：`8 px`

### 5.2 采用 `6 栏` 的原因

`6 栏` 足以覆盖大多数示意图中的信息组织方式，同时避免分栏过细带来的碎裂感。

这套网格尤其适合：

- 流程结构
- 关系组织
- 节点卡片
- 左右分区
- 上下分层
- 单列信息流

### 5.3 常用占栏方式

- 整宽主图：`6 栏`
- 左右双区：`3 / 3`
- 主次结构：`4 / 2` 或 `2 / 4`
- 三模块并列：`2 / 2 / 2`
- 单列纵向堆叠：`6 栏`

### 5.4 间距体系

统一使用以下基础间距值：

- `8 px`
- `16 px`
- `24 px`
- `32 px`
- `48 px`
- `64 px`

建议用法：

- 小元素之间：`8 - 16 px`
- 模块内部：`16 - 24 px`
- 模块之间：`24 - 32 px`
- 大区块之间：`48 - 64 px`

## 6. 页面结构

一张 `1080 × 1440 px` 的示意图，建议拆成 4 个固定区域。

### 6.1 标题区

建议高度：`140 - 220 px`

包含内容：

- 分类标签
- 主标题
- 一句话摘要

规则：

- 标题区负责建立理解入口。
- 标题区不宜过高，避免挤压主示意图区。

### 6.2 核心示意图区

建议高度：`700 - 860 px`

包含内容：

- 流程图
- 关系图
- 结构图
- 逻辑图
- 对比示意

规则：

- 一张图只保留一个核心视觉逻辑。
- 所有线条、节点、箭头和层级关系都在此区完成。

### 6.3 解释区

建议高度：`180 - 260 px`

包含内容：

- 关键节点说明
- 补充解释
- 重点结论
- 注意事项

规则：

- 信息以 `3 - 5` 条为宜。
- 文字保持短句。
- 这一区帮助读者看懂主图，不取代主图。

### 6.4 页脚区

建议高度：`60 - 100 px`

包含内容：

- `Logo`
- 来源
- 时间
- 注释

规则：

- 页脚语气应轻。
- 不与主图区争夺注意力。
- 若使用制作方署名，应优先将品牌 logo 放在页脚左侧，来源信息放在页脚右侧。

#### 6.4.1 底部署名区 Logo 规则

适用于信息图、参数图、流程图、关系图等页面底部左侧署名区。

建议规则：

- 优先使用当前品牌提供的 **SVG logo**。
- 首选文件格式：`SVG`；备选格式：透明底 `PNG`。
- 适合浅色或暖白底背景中的小尺寸署名位。
- 默认位置：页脚左侧。
- 建议高度：`24 - 32 px`，推荐值：`28 px`。
- 若 logo 本身已包含品牌文字，则不再额外补充“爱范儿制图”或其他重复署名文案。
- 若页脚空间紧张，可仅保留 logo，不强制附加辅助文字。
- logo 周围应保留清晰留白，不与页脚分割线、来源文字或渐变条贴得过近。

## 7. 字体系统

### 7.1 字体

统一使用 `OPPO Sans`。

### 7.2 字号底线

- 最小字号：`10 px`
- 正文推荐下限：`12 px`
- 正文舒适值：`14 px`
- 强阅读型正文建议：`14 - 16 px`

### 7.3 字号角色

- `10 px`：脚注、图注、编号、极短标签
- `12 px`：辅助说明、图例说明、较短节点注释
- `14 px`：标准正文、常规节点说明
- `16 px`：阅读优先型正文、关键说明

### 7.4 自适应字号档位

#### 低密度版

适用于内容少、图形占比较大、强调视觉感的页面。

- `H1`：`40 / 48`
- `H2`：`28 / 36`
- `H3`：`22 / 30`
- `Body`：`16 / 24`
- `Small`：`13 / 18`
- `Note`：`12 / 16`
- `Label`：`12`

#### 标准版

适用于大多数常规示意图页面，为默认方案。

- `H1`：`34 / 42`
- `H2`：`24 / 32`
- `H3`：`18 / 26`
- `Body`：`14 / 22`
- `Small`：`12 / 18`
- `Note`：`10 / 14`
- `Label`：`11 - 12`

#### 高密度版

适用于节点偏多、说明偏多、信息量较大的页面。

- `H1`：`30 / 38`
- `H2`：`22 / 28`
- `H3`：`16 / 22`
- `Body`：`12 / 18`
- `Small`：`11 / 16`
- `Note`：`10 / 14`
- `Label`：`10 - 11`

### 7.5 字号自适应顺序

当内容增多时，缩放顺序统一如下：

1. 先缩 `Note`
2. 再缩 `Small`
3. 再缩 `Body`
4. 再缩 `H3`
5. 最后才缩 `H2`

`H1` 尽量保持稳定，不轻易下压。

### 7.6 不可突破的字号底线

- `H1` 不低于 `28 px`
- `H2` 不低于 `20 px`
- `Body` 不低于 `12 px`
- `Label / Note` 不低于 `10 px`

低于此范围，视为内容过载，应拆页处理。

## 8. 色彩系统

### 8.1 颜色角色


| 颜色        | 角色    | 用法                    |
| --------- | ----- | --------------------- |
| `#ec1700` | 主强调色  | 核心节点、重点箭头、关键结论、标题引导圆点 |
| `#fc7c0a` | 辅助强调色 | 次重点、高亮标签、辅助强调、渐变尾色    |
| `#F8F5EC` | 页面底色  | 整体背景                  |
| `#FFFFFF` | 内容承载面 | 节点、模块卡片、局部内容底         |
| `#121212` | 主文字色  | 标题、正文、说明、注释           |


### 8.2 色彩使用比例

建议比例：

- `70%` 中性背景：`#F8F5EC / #FFFFFF`
- `20%` 深色文字与结构线
- `10%` 品牌强调色

### 8.3 使用原则

- 品牌橙主要用于重点，不用于大面积铺满。
- 小字号文字尽量不用橙色，避免在手机预览中发虚。
- 文字密集区域优先放在白色承载面上，而不是直接落在暖白底上。

## 9. 组件规范

### 9.1 节点 / 信息块

适用于流程节点、关系节点、结构模块、结论块。

建议规范：

- 圆角：`16 - 20 px`
- 内边距：`20 - 24 px`
- 节点间距：`24 - 32 px`

块内结构建议：

1. 标题
2. 一行说明
3. 必要时补一个标签

文字规则：

- 节点标题：`16 - 18 px`
- 节点说明：`12 - 14 px`
- 节点内部文字尽量控制在 `2 - 4` 行内

### 9.2 箭头 / 连线

适用于流程、因果、关系、层级。

建议规范：

- 标准线宽：`2 px`
- 强调线宽：`3 px`
- 箭头样式保持统一
- 优先使用直线、直角折线或柔和折线

统一原则：

- 一张图中最多使用 `2` 种线型
- 推荐组合：实线 + 虚线
- 避免混用波浪线、双箭头、复杂曲线等杂乱样式

### 9.3 图标

适用于辅助识别，不承担主叙事。

建议尺寸：

- 小图标：`20 px`
- 标准图标：`24 px`
- 强调图标：`32 px`

规则：

- 一张图只用一套图标风格
- 线性图标与面性图标不混用
- 图标不应抢过标题与主图逻辑

### 9.4 标签 / 状态标识

适用于分类、优先级、状态、结论类型。

建议规范：

- 高度：`24 - 28 px`
- 左右内边距：`10 - 12 px`
- 字号：`11 - 12 px`
- 圆角：`999 px` 或 `12 px`

## 10. 小标题前置圆点规范

### 10.1 用途

在部分模块级小标题、分组标题、段落引导标题前，可加入一个品牌红色实心圆形符号作为节奏点缀与分组提示。

适用场景包括：

- 核心能力
- 主要流程
- 结构组成
- 关键结论
- 注意事项

### 10.2 视觉规范

- 颜色：`#ec1700`
- 形态：实心圆形
- 描边：无
- 渐变：无

### 10.3 尺寸建议


| 小标题字号        | 圆点直径        |
| ------------ | ----------- |
| `16 px`      | `6 px`      |
| `18 px`      | `7 px`      |
| `20 px`      | `8 px`      |
| `22 - 24 px` | `8 - 10 px` |


默认建议值：

- 圆点直径：`8 px`

### 10.4 间距与对齐

- 圆点与标题文字间距：`8 - 12 px`
- 默认间距：`10 px`
- 对齐方式：与标题文字垂直居中对齐

### 10.5 使用层级

适合使用：

- `H2`
- `H3`
- 模块引导标题
- 分组标题

不建议使用：

- `H1`
- 正文段首
- 注释
- 页脚
- 每一个小标题

### 10.6 使用频率控制

- 同一张图中建议出现 `3 - 6` 次
- 同层级标题应统一使用，避免忽有忽无
- 该元素承担分组和节奏作用，不作为纯装饰反复出现

## 11. 内容容量上限

### 11.1 流程图

- 主要节点：`5 - 7` 个
- 辅助节点：最多 `3` 个
- 每个节点文案：尽量不超过 `18` 个字或 `2` 行

### 11.2 结构图

- 一级模块：`3 - 5` 个
- 每个模块的二级信息：`2 - 4` 条

### 11.3 关系图

- 核心对象：`1` 个
- 关联对象：`3 - 6` 个
- 连线类型：最多 `2` 类

### 11.4 说明型信息图

- 主标题：`1` 个
- 副标题：`1` 段
- 主要模块：`3 - 4` 个
- 每模块说明：建议控制在 `40 - 70` 字以内

## 12. Markdown 结构映射建议

为保证内容在不同页面中能稳定转译，建议 `Markdown` 原始内容采用固定层级。

### 12.1 推荐结构

```md
# 主标题

一句话摘要

## 核心结构
- 模块 A
- 模块 B
- 模块 C

## 流程 / 关系
- A -> B
- B -> C
- C -> D

## 说明
- 解释 1
- 解释 2
- 解释 3

## 注释 / 来源
- 来源信息
```

### 12.2 视觉映射关系

- `# 主标题` → 标题区
- `一句话摘要` → 标题区补充说明
- `## 核心结构 / 流程 / 关系` → 核心示意图区
- `## 说明` → 解释区
- `## 注释 / 来源` → 页脚区

## 14. 验收清单

每张示意图完成后，至少检查以下项目：

1. 缩小到手机预览时，标题与主逻辑能否一眼看懂。
2. 正文是否大于等于 `12 px`，辅助信息是否大于等于 `10 px`。
3. 一张图中是否只有一个核心视觉逻辑。
4. 模块关系是否主要依靠网格、留白与层级建立，而不是依靠堆颜色。
5. 圆点、箭头、图标和节点风格是否统一。
6. 内容过多时是否已经考虑拆页，而不是继续压缩字号。
7. `Logo` 是否处于克制位置，没有干扰主内容。

## 16. 结语

这套系统的重点不在于装饰，而在于把内容组织得更稳。品牌感来自节奏、留白、层级和重复规则，不来自堆积元素。

真正有效的统一性，往往很安静。
