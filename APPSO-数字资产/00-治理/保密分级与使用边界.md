# 保密分级与使用边界

2026-09-07 本次工作流整理采用主理人的直接授权：`tools/workflow-source-assets.json` 登记的流程原件、Prompt 和 Logo 统一进入当前私有仓库，不另走分级确认。以下通用边界不阻止本批已授权输入随 clone 保存，也不改变密钥、登录态和缓存的本地保存方式。

## 分级

### public

已经公开的事实、链接，以及确认可以公开的方法总结。可以对外引用，但仍需保留来源与版权边界。

### public-derived

根据 APPSO 公开文章得出的结构、节奏或信息源分析。它不是 APPSO 官方 SOP，对外使用时必须写清「公开样本归纳」。

### internal

实习反馈、编辑判断、未发布选题、来源评级、SOP、测试记录和一般复盘。仅用于内部学习与工作，不原样公开。

### restricted

未公开采访、联系人、授权凭证、商务条款、完整后台数据、公司终稿版本链，以及用户明确指出的公司原始资产。不得进入公开 Git、公开网盘或个人稿件。

用户或权利人明确授权在当前私有仓库保存的公司内部工具，可以标记为 `private-repository-only`，按版本放入 `tools/company/`。入库前必须确认远端为 Private，并排除凭据、浏览器 Profile、Cookie、登录态、缓存与会话导出；这项例外不适用于公司终稿、后台数据或授权凭证。

## 永不入库

- 密码、验证码、Cookie 和登录态。
- API Key、Token、AppSecret 和私钥。
- 完整请求头、浏览器会话文件和未脱敏账号导出。
- 未经许可的完整第三方文章、付费内容或资料包。

模板中只允许记录变量名和占位符，例如 `WECHAT_APP_SECRET=<local-only>`。

## 对外使用前检查

- [ ] 资料是否已经公开。
- [ ] 是否拥有当前平台的使用权。
- [ ] 是否包含公司内部判断、联系人或后台数据。
- [ ] 是否把公开样本分析误写成 APPSO 官方规则。
- [ ] 是否把公司成稿机械改写成个人内容。
- [ ] 是否保留必要来源、图注和事实限定。
