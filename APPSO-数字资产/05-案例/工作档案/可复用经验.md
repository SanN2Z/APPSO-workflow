# 可复用经验

更新：2026-09-05。分级：internal。这里记录这轮工作留下的判断，执行仍以现有 SOP 为准。

| 经验 | 来自什么情况 | 下次怎么用 |
|---|---|---|
| 先确定读者要看到什么，再找图 | 初期图少、长文密集，补图与正文关系弱 | 每节先列一个画面需求：结果、人物、原话或对比，再搜对应素材 |
| 好的截图需要交代来源和场景 | 作者认可后期采访图、官网截图和完整 X 帖子 | 优先找原页面；保留身份、标题和主视觉，手机尺寸看一遍。不要只截零碎文字 |
| 画面漂亮与任务完成分开记录 | Fable 游戏更精美，但控制方向可能有问题 | 同时留效果片段与操作片段，失败现象也记下来 |
| 录屏先标归属，再加工 | 小妖视频曾被归错模型 | 在记录中绑定模型、提示词、原文件、版本；派生 GIF 指回原视频 |
| 信息图不需要正文再念一遍 | 跑分段和结尾重复介绍性能 | 图注交代来源、单位和条件；正文写作者真正想讨论的问题 |
| 删解释，不把解释挤进前一句 | 多次反馈「AI 味」与结尾重复总结 | 删除重复解释、读者能自行得出的结论和强行转折，保持原判断与推进顺序 |
| 演示能证明的范围要写清 | 游戏、科研工作台和科学推理被放在同一篇稿里 | 分开实际体验、演示数据、厂商介绍和作者推断 |
| 验收要在最终使用位置完成 | 预览滑动正常，公众号粘贴曾失效；GIF 托管仍有问题 | 依次看预览、复制粘贴、保存重开；每步记录结果 |
| 先留过程，数据有了再补 | 稿件、代码和视频已存在，但发布与效率数据不齐 | 先记录改了什么和为什么，不倒推虚构耗时、成绩或个人贡献 |
