# AIGC 视频产品体验制作 SOP

版本：1.0

更新日期：2026 年 10 月 27 日

资料属性：internal

适用于 APPSO 视频生成、短剧工作台、转绘与相关创作产品的体验长稿，包括商单。由[APPSO 内容生产 adapter](<APPSO 内容生产 SOP.md>)进入；事实、权利、授权、生命周期和发布操作继续使用[核心流程](<../../共享/运营/SOP/内容工作流.md>)。本文件只规定测试作品怎么设计、制作、取材和交接。

这是主理人根据本轮反馈采用的 `E0 / project_configuration`；下一篇同类稿复核实际效果。短讯、单功能答疑和已有作品的局部修改按任务范围执行。

## 1. 先把要求变成可拍的案例

先读完用户提供的 brief、导出 PDF／手册，以及指定参考文章的正文、图片和视频。访问不到在线材料时，优先使用用户已导出的原件。参考稿要看实际案例、镜头、时长和图文节奏，不能只读标题或摘录。

在内容包已有 `brief.md` 中补齐：核心体验、甲方必须展示的功能与表述、必须出现的入口或操作、交付规格、预算与本轮授权范围。把参考稿中的质量要求转成具体制作目标，不复制其文案。

用一张简短的功能—案例对应表确定拍什么：

| 要展示的能力／宣传要求 | 观众会看到的案例与结果 | 实测路径 | 过程图与正文位置 |
|---|---|---|---|
| 每行写一个有实际区别的能力 | 写清场景、动作或反转，以及它为什么能展示该能力 | 网页、CLI 或两者衔接 | 对应哪个真实操作阶段 |

一场戏可以承担几项能力；同一画风换几个角色不自动算多个有效案例。主线案例负责连续制作，补充案例负责不同的视觉、表演或控制能力。未实际操作的能力按官方介绍归属，不算已实测。已有完整覆盖表时直接更新，不另建一套台账。

### 热点与选题

围绕功能找创意：表演控制找有反应和停顿的情境，镜头控制找明确的站位与遮挡，转绘找前后变化清楚的同一段内容，再结合当时的国内热门 IP、电影、节日或事件。

- 热点及发布时间、角色身份先查一手来源；区分当时仍热、即将发生和历史回顾。
- 候选要能用一句话说明「这个梗为什么适合展示这个功能」。优先有动作、冲突或反差的短故事，避免只让角色报产品名。
- 角色二创、原创借鉴和官方合作各自写清归属。IP 不能成为未核实新闻或官方授权的暗示。
- 热点不贴合时使用原创故事；已有作品只做局部修改时不为凑热点重拍。

完整视频体验长稿先规划几个有区别的展示任务；主展示片段默认以 15–20 秒为目标，完整讲完一个动作或反转。案例数量和时长服从当次 brief 与题材，按功能需要决定，不能机械凑满。

方案确定后再批量生成。用户要求先讨论方案时先交方案；方案或制作已获授权后，持续完成必要制作，不逐镜再问一次。

## 2. 制作前确定 CLI 与网页怎么分工

先查目标产品是否提供官方 CLI、API 或官方支持的自动化入口，并确认当前可用版本、账号接入、模型、规格、任务查询与下载方式、计费及与 Web 项目的关系。把结论记在已有研究笔记中。优先复用仓库已登记的本地工具；只读工具的版本与帮助即可确认的，不反复安装。

| 任务 | 默认执行方式 | 交付时必须对得上 |
|---|---|---|
| 批量关键图、同规格视频、重复参数任务 | 官方 CLI／API 可覆盖时优先调用 | 实际模型、输入、规格、任务 ID、原始输出与费用 |
| 工作台入口、剧本协作、画布、资产引用、分镜、转绘流程、3D 操作 | 在目标产品 Web 中实际执行并留图 | 正文介绍的操作确实发生，截图显示对应项目与阶段 |
| Web 产生资产或动态参考，再由 CLI 生成成片 | 两条路径衔接 | 保存实际输入引用与对应结果，能说明哪一步在哪完成 |
| CLI 不覆盖目标功能，或产品没有可用的官方入口 | 使用已登录的 Chrome | 完成实际操作及取材；不把寻找 CLI 变成主任务 |

CLI 是否同步到资产库、能否进入同一个 Web 项目，需要实际确认；通用生成接口不能自动代表工作室专用流程。正文按实际路径说明即可，CLI 补充成片不能被写成某个尚未跑通的网页功能产物，也不能拿其他产品生成的结果替代被测产品的结果。

新增可复用的工具、依赖或账号输入接入时，沿用 `CORE-PORTABILITY-001` 与 `tools/workflow-toolchain.json` 的登记入口；本 SOP 不写个人盘符、全局安装命令和登录信息。单次产品实测无需把所有厂商封装成统一 CLI 框架。

## 3. 先做出一条达标样片，再展开

选择最能支撑开头、最有视觉吸引力的一条先拍。小样用于验证人物和场景、动作与镜头要求、生成规格和费用是否合适；方向明确后先完成一条可放进成稿的展示片，再扩展其他案例。

每个案例直接在已有制作记录中保留一张任务卡，使用同一个案例名称：

```text
案例／对应功能／梗与来源：
目标：时长、比例、分辨率；人物、场景；主要动作与结尾
镜头要求：站位、朝向、运镜、切镜；对白及反应时间
路径与输入：Web／CLI；实际图像、视频或资产引用；模型与参数
任务与消耗：任务 ID、状态、扣分与已确认退款；等待情况按需记录
结果：原始文件、发布导出、关键帧、过程截图；可支持的描述
```

### 成片质量

- 先确定关键图中的人物、服装、道具与光线，再安排动作；需要跨场景或跨镜头连续时保留同一组设定与引用。产品支持时优先准备高分辨率关键图，原图与排版导出分开保存。
- 提示词写具体事件和镜头关系：谁先做什么、看见什么才反应、摄影机怎样移动、动作如何结束。不要靠「电影级」「震撼」代替场面设计。
- 15–20 秒片段应有完整节奏。人物需要观察和反应的时间；动作片要有起势、过程和结果。短片也要看得清主体、运动方向和视觉重点。
- 全片检查人物与道具连续性、动作、构图、运动、台词节奏和实际画质。完整播放并听审对白、音效与口型；ASR 只能辅助核对内容，抽帧只能辅助检查画面，不能据此声称已确认声音自然。
- 未达到展示要求时，针对具体镜头或参数修正，再决定采用或换案例。白模、预演、短技术演示用于说明制作机制；主展示用可观看的成片。不得靠循环、慢放或拼接把短技术片伪装成同等时长的生成成片。

被测产品产生的图和视频保留原始结果及真实模型归属，按[内容包素材合同](<../../.agents/skills/self-media-ops/references/content-package.md>)中的实际产品输出登记任务记录及输入；另制的封面、解释图继续走相应编辑视觉规范。创作延伸图、视频实际输入、真实抽帧分别标清，不能用更漂亮的延伸图冒充视频画面。

## 4. 操作时同步保留完整工作台

每个承担核心卖点的 Web 流程，在实际操作到该阶段时取材：入口与设置、关键制作状态、结果预览。页面里有资产与分镜的关系时，把关系一起留下；不用事后补造界面。

**工作台功能先提供全局图。** 保留产品导航、当前项目、资产栏、编辑区、预览区，以及当前阶段需要的底部片段或时间轴。全局指完整的产品工作区，不要求把无关桌面或浏览器标签一起截入。局部图只用来补读小字或比较细节，不能替代全局图。

例如重制转绘应能连起来看见：原片从哪里导入、风格／地区／比例在哪里设置、资产如何进入项目、分镜如何引用、结果在哪里预览与切换对比。拍当前案例实际经过的节点，不机械截图所有菜单。

原始截图完整保留；进入正文前处理账号隐私，并确认选中的是正确页签、关键内容加载完成、预览对应当前案例、没有无关弹窗或其他文档遮挡。截图必须在正文相应段落真实出现，放在素材文件夹里不算已配图。画面细节不清时可补局部图或原尺寸查看入口。

CLI 路径保留调用参数、任务与结果，不能伪装成网页操作截图。展示 Web 能力时配真实工作台图，展示成片质量时配实际视频与关键帧；官方宣传图用于补充产品全貌和官方口径，三种材料各有作用。

### 长任务与资源

提交生成后先保存任务 ID；客户端等待或下载超时，先查询已有任务并回收结果，再决定是否重试，避免重复扣分。复用已成功的资产和成片，局部改稿或重新打包不重新生成视频。

等待期间可处理其他已授权且不依赖该结果的资料、配图或文案；保持简短进度更新，交代已拿到什么、下一步等什么。用完关闭助手打开的重复页面、预览窗口和无用工作台，保留用户正在使用的页面。

## 5. 用成片和具体操作写体验

先展示最有吸引力的成片或具体场景，再解释它怎么做成；之后围绕不同能力展开案例。每个重要功能在正文中都应有可观看的结果或对应操作图。成稿顺序按读者兴趣组织，制作记录留在内部。

商单用真实好看的结果、明确的使用场景和具体操作承接卖点。普通调参、放弃方案和失败日志放内部制作记录；影响核心判断的限制在正文中准确、简短交代。不能虚构成功、夸大可控性，也不把正文写成故障排查记录。

### 官方图与成本

官方图优先用来解释入口全貌、核心能力和套餐条件，并注明出处；实际效果由本次作品承担。精确成本图使用记录中的真实数据，附可复算的明细。

- 区分本次展示作品成本、完整制作过程总成本、账户余额和官方最低单价；有重试、退款或未结任务时写清统计范围。
- 保留模型、分辨率、时长、是否使用动态参考、积分与金额单位。活动价注明取材日期、期限、会员档位、赠送条件及适用规格。
- 没有对应付款或积分换算依据时，不用宣传最低秒价乘时长冒充本次实际花费；折扣精确算法不明时保留官方归属。
- 只有活动或定价变动、统计范围变化等会影响当前描述的情况才重新核价、重画，不为改一张截图重算已经确认的任务。

## 6. 一次交出能阅读的图文视频

按用户当前选定的载体交付。发主编的 HTML／ZIP 应包含清洁正文、已嵌入或正确引用的实际图片、可播放的视频；视频、关键图和官方图在相应段落出现。发布用原始素材、排版导出及成本明细按需另包，编辑备注与正文分开。

交付前完成一次有实际用途的检查：

- 回看功能—案例表，确认必展要求在正文、作品或操作图中有落点；同一结果不夸大成另一种能力。
- 选定视频完整播放、听审并确认时长、分辨率、画面和声音；检查文件完整可解码，保留原始输出，导出不无故降低分辨率、帧率或音质。未完成的听审等事项在内部交接中列明。
- 看正文中的工作台全局图、关键图与官方图，确认内容完整、归属准确；手机宽度下检查主要信息可辨，细节可查看原图。
- 按接收者实际打开方式检查 ZIP 目录与相对路径，视频能加载；核对清洁阅读版没有混入调试日志、凭据、内部评语或修订记录。

已经通过的媒体检查不因重新排版重复跑一遍；只重查新替换的素材、受影响段落与打包路径。事实、版权、终校、状态与外部写入门继续按核心流程执行。

## 配置依据与复核

规则 ID：`APPSO-AIGC-VIDEO-EXPERIENCE-001`。

- 触发：APPSO 需要实际制作视频的产品体验长稿，或用户要求按该类稿制作和交接。
- 动作：按本文件把宣传要求、案例、执行路径、成片、过程图和正文位置连起来；先完成达标样片，再展开制作。
- 通过：重要功能有真实落点；主展示具备可观看的质量与完整节奏；CLI／Web 归属准确；过程图含完整工作台；读者能在交付载体中看图并播放视频。
- 失败信号：只有一条勉强跑通的样片便称完整交付；用短预演充当主片；CLI 作品冒称网页专用流程产物；只截局部面板；最后才补图；成本口径混算。
- 范围与反例：单功能短讯不要求多案例；5 秒技术参考可按其用途展示；产品无 CLI 就用网页；原创案例无需强挂热点；局部修改只处理指定范围。短片、热点和工具数量均不设通用配额。
