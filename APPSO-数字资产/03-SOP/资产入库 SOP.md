# 资产入库 SOP

版本：1.1

更新日期：2026 年 7 月 23 日

## 1. 先分类

判断资产属于：

- 原始公司资料。
- 公开样本研究。
- 内部方法或 SOP。
- 模板。
- 单稿案例。
- 受限材料。

## 2. 检查敏感信息

入库前搜索：密码、Cookie、Token、API Key、AppSecret、验证码、邮箱登录信息、完整请求头和私人联系人。

发现凭据时停止复制，只记录「通过公司凭据管理方式访问」，不保留值。

## 3. 决定保存方式

- public / public-derived：可保存链接和方法总结。
- internal：可保存脱敏后的规则、SOP 和模板。
- restricted：优先只建索引；确需本地保存时放入 `90-受限资料/`，并确保 Git 忽略。
- restricted 公司工具窄例外：用户或权利人明确授权、远端已确认是 Private、且凭据与运行态审计通过时，按版本保存到 `tools/company/`，并标记 `private-repository-only`。
- 公司终稿与完整参考文章：只建索引，不复制到模板或个人知识库。

公司工具窄例外不适用于公司终稿、后台数据、授权凭证、联系人、浏览器 Profile、Cookie、登录态、扩展存储导出、缓存或日志。

## 4. 原件与派生件分开

- 原件保留原文件名、来源日期和 SHA-256，不直接改写。
- 派生件使用可读标题，并写清来自哪个原件。
- 原件更新时，不覆盖旧版本；新增版本并写入变更记录。

## 5. 登记资产台账

最少字段：

- `id`
- `title`
- `path`
- `source`
- `obtained_on`
- `classification`
- `rights_status`
- `allowed_use`
- `contains_credentials`
- `notes`

二进制原件再记录 SHA-256、尺寸和格式。

## 6. 验证

- [ ] 文件真实存在并能打开。
- [ ] 相对链接有效。
- [ ] 原始公司资料已被 Git 忽略或只建立索引；如为公司工具窄例外，授权、Private 远端、审计、版本目录和文件树哈希均已登记。
- [ ] 没有凭据和私人登录信息。
- [ ] 权利状态没有被误写成已授权。
- [ ] 中文引号和中英文数字空格符合项目硬规则。
- [ ] 变更记录已更新。
