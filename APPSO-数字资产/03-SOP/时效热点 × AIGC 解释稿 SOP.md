# 时效热点 × AIGC 解释稿 SOP

更新时间：2026-07-22

## 适用范围

适用于“今天发生的公共事件，让某个 AI 产品、模型输出、创作流程或数据系统重新获得解释价值”的公众号稿。

它不适用于两类选题：

- 事件本身与 AI 无关，只是事后随手问了聊天模型；
- 说不清 AI 在其中完成了什么任务，也找不到可核的输入、版本、输出或实际后果。

核心不是给热点贴上 AI 标签，而是用热点提出一个能核查的问题：AI 在这件事里到底完成了什么任务，凭什么有效，又在哪些地方会失效？若文章讨论预测，再额外要求赛前留档、信息截止点、结果空间和评分规则；没有赛前记录，就不能把赛后回答包装成预测命中。

## 一、八阶段工作流

| 阶段 | 必须输入 | 必须产出 | 硬门 | 常见失败 |
|---|---|---|---|---|
| 0. 热点准入 | 热榜、官方结果、原帖、首次出现时间 | `hotspot card`：事件时间、发酵时间、今日新增、AI 连接、时效期限 | 删除 AI 后，文章的核心问题应随之改变；能指出 AI 的具体任务与实际后果；旧闻不得写成“刚刚” | 只因热点有流量便硬接 ChatGPT；赛后问答冒充赛前预测 |
| 1. 临时 brief | 热点卡、目标读者、交付时间 | 稿型、唯一问题、主钩子、暂定判断、边界、明确不写什么 | 圈外读者约 5 秒能复述问题；标题、开头、结尾服务同一承诺 | 同时卖赛果、公司史、博彩、国内外模型等多个钩子 |
| 2. 证据账本 | 一手来源、历史留档、协议页、实际结果 | `fact-sheet` 与通用任务卡；预测类另建轨迹表和方法比较表 | 写清任务、输入、系统版本、输出、实际后果、基线与限制；预测数字再补信息截止点、结果空间、样本与评分口径 | 把产品宣传当实测；把夺冠、90 分钟胜平负和晋级混算；把模拟次数当新信息数量 |
| 3. 锁定论证 | 已核事实、证据缺口、替代解释 | 一句可证伪判断、分节任务、最强反例、结尾新增信息 | 一次命中不得证明长期准确；不可比项目不得排榜 | 来源列表直接变成文章目录；先下“AI 靠谱”结论再找材料 |
| 4. 写正文 | 锁定 brief 与事实表 | `draft.md`、标题候选、近邻图注 | 首屏交代今天发生了什么；前 25% 出现真正问题；陌生主体背景通常 1—2 句 | 先写三段公司史；每节末尾都总结；个人案例抢走主线 |
| 5. 视觉编排 | 论证任务、原图、数据表、权利信息 | 实际素材、相对路径、`asset-manifest.yml`、手机预览 | 图片必须真实落盘；一张图只回答一个问题；数据、来源、口径和权利齐全 | 只有图片计划却称“完成”；AI 生成图伪装成新闻图；JPG poster 当视频 |
| 6. 发布门禁 | 精确正文、素材、来源 | `review.md`、`copyedit.md`、正文哈希、预览 | 时效事实重开；冷读、AI-pattern、逐句终校、版权、手机宽度和 validator 全通过 | 终校后又改正文；飞书临时链接是唯一素材存档；权利未清却标 `ready` |
| 7. 发布后复盘 | 初稿、交付稿、发表稿、全部反馈 | 语义 diff、改动原因、规则候选、回归案例 | 每项回答“改了什么、解决什么读者问题、能否推广” | 只统计字数；只写“更自然”；一篇个案直接污染全局规则 |

## 二、通用任务卡与预测类分支

所有 AIGC 热点先做一张通用任务卡：

```text
task | input | information_cutoff | system/version | output
actual_consequence | baseline | evidence | limitations
```

它用于回答：系统拿到了什么，做了什么，产出了什么，最后改变了什么。产品发布、AI 创作、工作流和预测稿都适用。若只有厂商演示，没有外部结果，就把“实际后果”明确标为待验证，不替厂商补结论。

预测类热点在此基础上必须多做下面两张表。

### 预测轨迹表

```text
forecast_at | information_cutoff | system/version | task
outcome_space | horizon | output/probability | actual_result
scoring_rule | source
```

同一张曲线只能连接同一口径的数据。若每一轮结束后模型获得了新赛果、新对手或新伤停，正文必须说明概率变化来自信息集变化，不能写成模型对同一道题反复“改口”。

### 方法比较表

```text
system | data/input | cutoff | output type | protocol
sample | baseline | audit trail | reproducibility | comparable_with
```

比较前依次对齐：

1. 预测的题目；
2. 信息截止时间；
3. 结果空间；
4. 模型与版本；
5. 输入资料和提示方式；
6. 样本量；
7. 评分规则与简单基线。

有一项关键口径不同，就只能并列介绍，不能用准确率排高低。

## 三、“靠谱吗”不能靠一场命中回答

最低证据组合是：

```text
赛前留档
+ 同一道题
+ 明确概率或置信度
+ 连续样本
+ 统一评分
+ 简单基线
+ 错误记录仍然保留
```

写判断时分开四件事：

- **能不能用**：是否比随机、简单排名或普通用户多提供信息；
- **概率准不准**：长期频率是否与给出的信心匹配；
- **能不能复现**：输入、代码、权重、版本和留档是否足够；
- **能不能赚钱或改变决策**：成本、赔率、平台利润和使用边界是否被计入。

重复模拟可以减少抽样波动，不能自动纠正底层概率。单场结果也不能验证一个 60% 是否校准。

## 四、推荐叙事路径

以下是检查顺序，不是强制文章模板：

```text
今天发生的结果或动作
→ 为什么一份旧预测重新被翻出
→ 比“猜中”更有信息量的证据
→ 它究竟预测了哪一道题
→ 数据与方法为什么可能有用
→ 连续记录暴露了什么失败模式
→ 普通读者该如何使用这个结论
```

优先找更早、信息量更大的留档。决赛前两队二选一通常不如开赛前完整排序有解释力；一张爆款截图也不如完整时间轨迹可靠。

陌生机构背景只补足读者判断可信度所需的信息：它是谁、做什么、数据从哪里来。通常 1—2 句够用。

个人经历最多承担一个论证任务，建议只写一段，并同时交代：做法、样本、结果、限制。不得把小样本盈利写成方法有效的主证据。

## 五、视觉与动态素材门

1. 新闻现场、官方界面和社交原帖优先使用有来源的原图；不用 AI 生成图伪装现场或官方截图。
2. 多阶段数字优先做项目原创图表，图表注明数据来源、日期和比较口径。
3. “视觉方案”不等于“配图完成”。宣布成稿前，正文要求的文件必须位于 `assets/` 并实际插入 Markdown。
4. 手机端检查标题、轴标签、数字和图注；缩小后读不清的图不算完成。
5. 视频本体、poster 和动图是三种资产：
   - MP4 才是完整视频；
   - JPG/PNG 只是封面；
   - GIF 只适合短、无声循环，不能代替长视频。
6. 下载、裁切、转码或转 GIF 不会自动产生转载权。来源不明或未获许可时，只保留原帖链接或等待授权。
7. 临时飞书 URL 不能成为唯一存档；发布后要保留本地文件、来源链接和图注对应关系。

## 六、人话与协作门

- 先说明“到底预测了什么”，再讨论“准不准”。
- 把数字翻译成读者后果，但俏皮话同样要过事实核查。
- 删除只负责引路的模板句；同一结论最多在开头设问、正文证明、结尾回收各出现一次。
- 结尾必须增加一层信息或判断。若只是换词重复开头，直接删除。
- 套式口语与非字面隐喻统一按[公众号 AI 痕迹诊断](<../../.agents/skills/self-media-ops/references/wechat-ai-pattern-pass.md#5-manufactured-personality>)的迁移与删除测试处理；本专项遇到非字面的「怎么结账」时，直接写清谁承担成本、谁获利或如何评分。
- 用户明确说“开头已改好”“不要大动”后，把该段标成受保护区。后续只做事实修正、局部桥接和必要语病处理，并单独展示 diff。

## 七、公司稿与个人账号隔离

已有公司成稿时，个人账号版本只共享公开事实与来源，不共享成稿表达。

个人稿必须重新确定：

- 读者问题；
- 中心判断；
- 证据主线；
- 段落顺序；
- 例子与结尾；
- 视觉资产。

不得复用公司稿的标题句、独特比喻、图注、图片和结尾口号。字符串重合检查只能辅助，不能代替结构与观点独立性判断。两个版本使用独立内容包和状态记录。

## 八、发布前专项清单

- [ ] 今天新增的事实已经明确，不把旧闻包装成突发。
- [ ] AI 是必要解释变量，不是硬贴标签。
- [ ] 已写清 AI 的任务、输入、系统版本、输出、实际后果、基线和限制。
- [ ] 【预测类】预测题目、时间窗口、结果空间和评分规则没有混用。
- [ ] 【预测类】没有用一次命中证明长期可靠。
- [ ] 【预测类】不可比准确率没有被直接排名。
- [ ] 【预测类】模拟稳定性没有被写成模型准确性。
- [ ] 类比、梗和金句没有改变事实。
- [ ] 个人案例有样本与限制，且不是主证据。
- [ ] 结尾比开头多提供了一层信息。
- [ ] 正文所需图片已落盘、插入、标注来源并通过手机检查。
- [ ] 视频本体与 poster 已区分，转载与改编权已记录。
- [ ] 用户确认过的段落没有被擅自全面重写。
- [ ] 公司稿与个人稿没有共用成稿表达或视觉资产。

## 九、可直接复用的 Prompt

### 热点准入

```text
你是公众号时效选题编辑。只筛选，不写稿。

输入：候选事件、链接、出现时间和当前讨论。
输出：
1. 事件发生时间、官方宣布时间、重新发酵时间；
2. 今天新增了什么；
3. AI 在事件中是方法、产品、创作工具、传播噱头，还是事后强行关联；
4. 普通读者真正会问的一个问题；
5. 可验证的反差；
6. 所需一手证据与历史留档；
7. go / hold / reject。

直接拒绝：删掉 AI 后问题完全不变；说不清 AI 的具体任务与后果；旧材料被包装成“刚刚”。若声称预测命中，必须另查赛前留档。
```

### 通用证据编辑

```text
不要写正文。先把材料拆成原子事实，再建立任务卡：
任务、输入、信息截止点、系统与版本、输出、实际后果、
简单基线、来源和限制。

分开已核事实、厂商自报、第三方测试、作者体验和推断。
没有外部结果时，不把演示效果写成真实效果；不同任务、
版本或输入条件下的结果不得直接排名。若属于预测，再进入
预测证据账本，补结果空间、样本与评分规则。
```

### 预测证据编辑

```text
不要写正文。把材料拆成原子事实，并为每条预测建立账本。

必须写清：谁在何时、基于截至何时的信息、预测哪一道题、
结果空间、时间范围、输出标签还是概率、样本量、评分方式、
实际结果、来源和限制。

分开已核事实、机构自报、第三方结果、作者体验和推断。
不同任务或评分口径不得直接排名。特别检查：重复模拟次数
提高的是抽样稳定性，不能自动证明底层概率准确。
```

### 主编锁定结构

```text
基于事实表，为“时效热点 × AIGC 解释稿”只锁定一个问题。

输出目标读者及盲区、唯一标题承诺、一句可证伪判断、
最小事实卡、论证路径、最强替代解释、结尾必须新增的信息，
以及明确删除的次要钩子。

不要把来源列表直接变成目录，不要预设每篇都用相同小标题。
```

### 主笔写作

```text
按已锁定 brief 写公众号稿。

首屏交代今天发生的事，并尽快抛出唯一问题。
陌生机构背景最多保留改变信任判断的 1—2 句。
先说明预测任务，再谈准确率；连续数据要说明信息集如何变化；
不可比数字只说明差异，不排榜。个人经历只解释一个边界。
结尾提供读者以后判断同类新闻的方法，不重复开头。
所有类比、梗和金句也要接受事实核查。
```

### 独立审校

```text
先只读公开正文，不看提纲。回答：发生了什么？作者判断是什么？
凭什么？最强限制是什么？为什么与普通读者有关？结尾新增了什么？

再检查热点时间、AI 的必要性、预测口径、连续留档、一次命中、
不可比准确率、模拟稳定性、类比准确性、图片视频任务与版权、
手机可读性和结尾信息增量。只报告具体缺陷、读者伤害和通过条件。
```

### 初稿—终稿复盘

```text
对比初稿、交付稿、最终发表稿与全部编辑反馈。
按标题/开头、统领问题、结构、事实、口径、方法、例证、
个人经历、结尾、图片视频、版权和自然中文分类。

每项输出：原来怎样 → 最终怎样 → 为什么改 → 解决了什么读者问题
→ 本稿特例还是跨稿规则 → 是否进入 SOP。

不能只写“更顺、更自然、更像人”，必须指出具体的信息或阅读损失。
```
