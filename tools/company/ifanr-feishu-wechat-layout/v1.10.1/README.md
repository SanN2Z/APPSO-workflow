# 1.10.1｜头图与正文独立编辑修复候选

基于公司原版 1.10.0 的本地派生版本；restricted / private-repository-only。尚未完成真实公众号保存重开验收，未替换工具链默认版本。

## 修复内容

- 原版正文的 16 px 边距挂在外层 section，里面还有块级 span。改为独立 p 段落，边距随段落编辑。
- 头图独立为零缩进 p 段落，与正文平级。
- 头图 GIF 超限或托管失败时，补图提示使用没有边距的行内标记，避免补图落进带 16 px padding 的容器。
- 引用、列表、正文图片与横滑图库保持原有格式。权限、网络、账号、保存和回滚逻辑保持原版。

## 试用

1. 打开 Chrome 的 chrome://extensions，暂时停用旧版排版插件。
2. 开启开发者模式，选择「加载已解压的扩展程序」，加载本目录的 extension/。
3. 刷新飞书和公众号编辑页，避免继续运行旧版页面脚本。
4. 用测试草稿重新收录并排版。已有稿件不会自动变更；不要为套用修复直接覆盖已手工改好的正文。
5. 头图提示补图时，选中该段提示文字并粘贴头图，不要将图片粘到第一段正文里。
6. 保存后重开并做手机预览，核对头图全宽、正文左右 16 px，以及可单独调整的段落边距。

## 本地验证

仓库根目录运行 `node tools/company/ifanr-feishu-wechat-layout/tests/paragraph-editability.cjs`。只使用 Node 内置模块和本机 Chrome；没有访问真实账户。Chrome 不在默认安装路径时可设置 CHROME_PATH。

20 项检查覆盖：初始 0 / 16 缩进、段落调整独立性、头图不进入正文图库、GIF 超限与托管失败后的手动补图、原生 insertHTML 粘贴、清理及重新解析。local-validation.json 登记精确文件与哈希。完整的飞书采集、微信转换、保存重开与冷克隆均未在本轮声称通过。

浏览器本地预览和测试输出位于 ../tests/artifacts/，不入 Git。上游原版说明和既有已知问题见 ../v1.10.0/README.md 与规范入口。
