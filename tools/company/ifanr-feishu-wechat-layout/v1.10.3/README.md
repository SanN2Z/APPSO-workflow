## 本轮明确的版式

正文文字、标题、引用、列表、普通图片、图库视窗左右各 16 px；头图与尾图左右 0。根容器不加 padding。普通文字与单图的边距设在可单独编辑的 p 段落上。补图提示只用行内文字，不附加有边距的提示框。

默认在文章末尾保留空白通栏段落，供手动添加尾图。飞书最后一张图确实是尾图时，可在收录前选择「原稿末图作为尾图」，插件会使其独立通栏，不混入图库。没有该选择时，最后一张正文图仍缩进。

作者日志显示：23 张源图中 22 张正文静态图可见且已托管，第 1 张 GIF 头图在 HTML 插入后未被确认托管；最终又被替换为补图提示。44 个 img 节点包含 22 个隐藏节点。日志未保留头图替换前的状态，不能据此断言是微信拒绝上传还是旧版检测误判。

- GIF 先发送原始 File 粘贴事件，只有事件未被编辑器接受才回退原来的 HTML 插入。接受事件不等于上传成功，仍检查可见、加载完成的微信图片。
- 失败前记录文件事件是否被接受，以及图片的来源类别、可见性、加载状态和序号；不记录完整地址、正文或请求头。
- 原图的隐藏辅助节点不重复计为托管完成；第三方 URL、空地址或未加载图片不作完成证据。
- 「下载原始 GIF 头图」保留原始动画。若微信不接受自动流程，选中头图段的提示文字，通过公众号「图片 → 本地上传」补入；不要复制橙色提示文字或提示框。

## 使用新版

1. 停用旧扩展，加载本目录的 extension 文件夹，确认 1.10.3。
2. 收录前确认题图品牌；作者本次日志使用的是爱范儿头图，APPSO 稿可明确选择 AppSo。
3. 选择尾图方式，重新收录。旧版 v6 排版包不自动复用，以免仍带旧的图片边距。
4. 进入唯一的公众号编辑页执行排版。先保存重开，核对正文文字与图片边距、头尾通栏以及 GIF 动画。
